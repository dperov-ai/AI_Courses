# Практичні завдання до Уроку 198: Використання v0 та інших інструментів створення інтерфейсів за текстовим описом

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

## Завдання 1: Генерація інтерактивної форми чекауту за допомогою v0.dev

**Мета:** Опанувати складання промпту для платформи v0 та отримати робочий компонент оформлення замовлення.

**Вхідний контекст та бізнес-сценарій:**
Створіть сучасну, адаптивну форму чекауту з вибором способу оплати (Card / Apple Pay / PayPal), полем промокоду та блоком підсумкової суми.

**Покроковий алгоритм виконання:**
1. Складіть розгорнутий промпт за моделлю PACT із зазначенням компонентів shadcn/ui.
2. Згенеруйте інтерфейс у v0.dev та перевірте адаптивність перемиканням розміру екрана.
3. Зробіть точкову ітерацію (Selection Edit): змініть вигляд кнопки оплати та додайте іконку замка безпеки.

**Рекомендований системний AI-промпт:**
```text
Створи високоякісний промпт для v0.dev для створення компонента CheckoutForm на базі Next.js, Tailwind CSS та shadcn/ui. Опиши секції: контактні дані, спосіб доставки, платіжні опції (Tabs), підсумок замовлення з розрахунком знижки. Вкажи підтримку темної теми та адаптивність.
```

**Очікуваний результат:**
Повний системний промпт для генерації у v0 та опис проведеної ітерації доопрацювання.

**Критерії самоперевірки та оцінювання:**
- [ ] Використання семантичних компонентів shadcn/ui
- [ ] Підтримка темної теми через Tailwind dark:
- [ ] Описано точкове редагування окремого елемента

## Завдання 2: Інтеграція та аудит доступності згенерованого v0 коду

**Мета:** Провести аналіз згенерованого React-коду на предмет доступності (a11y) та адаптивності.

**Вхідний контекст та бізнес-сценарій:**
Вам надано згенерований v0 компонент модального діалогу підтвердження видалення проекту. Перевірте його на відповідність нормам доступності.

**Покроковий алгоритм виконання:**
1. Проаналізуйте код на наявність правильних ARIA-міток (aria-labelledby, aria-describedby).
2. Перевірте фокус-менеджмент: чи блокується фокус всередині модального вікна (Focus Trap).
3. Внесіть правки в Tailwind-класи для покращення видимості фокусу клавіатури (:focus-visible).

**Рекомендований системний AI-промпт:**
```text
Проведи інженерний аудит доступності (Accessibility Review) для коду модального вікна shadcn AlertDialog. Перевір наявність правильних семантичних тегів, контрастність кнопок відміни та підтвердження і наявність видимого outline при навігації клавіатурою.
```

**Очікуваний результат:**
Звіт аудиту доступності з фрагментами оптимізованого коду компонента.

**Критерії самоперевірки та оцінювання:**
- [ ] Відповідність критеріям WCAG 2.2 AA
- [ ] Наявність видимих станів :focus-visible
- [ ] Семантично правильні кнопки та заголовки

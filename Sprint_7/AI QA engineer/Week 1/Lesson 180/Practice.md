# Практичні завдання до Уроку 180: Основи HTTP, REST та API для AI QA Operator

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Складання матриці тестування статус-кодів для REST ендпоінта

**Мета:** Спроектувати повне тестове покриття для одного критичного REST API ендпоінта з точки зору QA Operator.

**Вхідний контекст та бізнес-сценарій:**
Вам надано ендпоінт створення нового користувача: POST /api/v1/users. Необхідно скласти матрицю з 8 тест-кейсів, що охоплюють валідні та невалідні сценарії.

**Покроковий алгоритм виконання:**
1. Визначте 1 позитивний сценарій (Happy Path) із очікуваним кодом 201.
2. Складіть 5 негативних сценаріїв валідації (порожні поля, невалідний email, дублікат, відсутність авторизації, переповнення довжини рядка).
3. Для кожного кейсу зафіксуйте вхідний payload, очікуваний HTTP-статус та очікуване тіло помилки.

**Рекомендований системний AI-промпт:**
```text
Дій як Lead QA Engineer. Склади тестову таблицю перевірок для ендпоінта реєстрації POST /api/v1/users. Включи перевірки кодів 201, 400, 401, 409, 422. Опиши точний JSON запиту та очікуваної відповіді для кожного випадку.
```

**Очікуваний результат:**
Тестова матриця у форматі Markdown із детальним описом вхідних даних та очікуваних результатів.

**Критерії самоперевірки та оцінювання:**
- [ ] Покриття статусів 201, 400, 401, 409, 422
- [ ] Коректні зразки JSON для кожного кейсу
- [ ] Чітко сформульовані очікувані результати

## Завдання 2: Ручне тестування API та фіксація невідповідностей через cURL

**Мета:** Виявити дефекти реалізації API за допомогою cURL та зафіксувати баг-репорти.

**Вхідний контекст та бізнес-сценарій:**
Протестуйте публічний або мок-ендпоінт. Перевірте його стійкість до відсутності заголовка Authorization та передачі некоректних типів даних.

**Покроковий алгоритм виконання:**
1. Виконайте cURL запит із валідними даними та збережіть заголовки відповіді.
2. Виконайте запит без токена та зафіксуйте код відповіді (очікується 401).
3. Оформіть знайдений дефект (якщо сервер повернув 200 або 500) у вигляді професійного баг-репорту.

**Рекомендований системний AI-промпт:**
```text
Склади професійний баг-репорт на дефект: Ендпоінт POST /api/v1/cards повертає 500 Internal Server Error замість 422 при передачі від'ємного значення балансу. Додай повну cURL команду для відтворення та стек логів.
```

**Очікуваний результат:**
Зразок оформленого Bug Report за стандартом enterprise-команд.

**Критерії самоперевірки та оцінювання:**
- [ ] Чіткі Steps to Reproduce з cURL командою
- [ ] Точний опис Expected vs Actual Result
- [ ] Правильно виставлені Severity та Priority

# Контрольні запитання до Уроку 182: Побудова API test scenarios

Даний блок містить перелік запитань для самоконтролю, перевірки глибини засвоєння матеріалу та самостійної підготовки.

---

1. Що таке наскрізний тестовий сценарій (API Test Scenario) і чим він відрізняється від одиночного перевірочного запиту?

2. Що таке перехресне забруднення тестових даних (Test Data Pollution) і як йому запобігти?

3. Що таке тестування скінченних автоматів станів (State Machine Testing) в API?

4. Який HTTP статус-код сервер повинен повертати при спробі виконати неможливий перехід стану (наприклад, оплатити вже скасоване замовлення)?

5. З яких обов'язкових трьох фаз складається надійний API сценарій?

6. Як у середовищі Postman організувати передачу ID новоствореного об'єкта в наступний запит?

7. Що таке негативний комбінаторний сценарій?

8. Як штучний інтелект допомагає проектувати графи переходів станів?

9. Чому важливо перевіряти стан пов'язаних сутностей після виконання операції?

10. Що таке конкурентні тестові сценарії (Race Condition API Testing)?

11. Як перевірити поведінку системи при аварійному обриві мережі посеред довгого сценарію?

12. Чому сценарії з використанням жорстко захардкоджених ID (наприклад, /users/1) вважаються антипатерном?

13. Що таке ідемпотентний сценарій повторної спроби (Retry Scenario)?

14. Як перевіряється розмежування прав доступу в багатокористувацьких сценаріях (Multi-tenant)?

15. Яку роль відіграє затримка (Delay) або Polling у сценаріях з асинхронною обробкою?

16. Як AI генерує синтетичні тестові профілі користувачів для складних сценаріїв?

17. Що таке Boundary Scenario (Сценарій граничних умов)?

18. Як перевіряти сценарії інтеграції зі сторонніми сервісами (Third-Party APIs)?

19. Що таке Smoke API Scenario?

20. Як оцінювати успішність виконання комплексного API сценарію?

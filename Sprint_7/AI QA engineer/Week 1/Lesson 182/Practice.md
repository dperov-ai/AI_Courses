# Практичні завдання до Уроку 182: Побудова API test scenarios

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Побудова матриці станів та переходів для замовлення (State Transition Matrix)

**Мета:** Спроектувати набір тест-кейсів для валідації всіх дозволених та заборонених переходів стану.

**Вхідний контекст та бізнес-сценарій:**
Сутність 'Замовлення' має 4 стани: PENDING, PAID, CANCELLED, COMPLETED. Необхідно побудувати матрицю переходів.

**Покроковий алгоритм виконання:**
1. Складіть таблицю перехресних переходів (4x4) між усіма станами.
2. Позначте валідні переходи зеленим (дозволені) та заборонені червоним (мають повертати 409/422).
3. Опишіть тестовий сценарій для перевірки спроби скасування вже виконаного замовлення (COMPLETED -> CANCELLED).

**Рекомендований системний AI-промпт:**
```text
Створи детальну матрицю переходів станів (State Transition Table) для замовлення з 4 статусами. Опиши 3 негативні сценарії спроби заборонених переходів із точними HTTP-запитами та очікуваними відповідями бекенду.
```

**Очікуваний результат:**
Документ із таблицею станів та детальним описом негативних перевірок.

**Критерії самоперевірки та оцінювання:**
- [ ] Повна матриця 4x4 станів
- [ ] Чітко виділені заборонені бізнес-переходи
- [ ] Описано точні HTTP-статуси помилок

## Завдання 2: Створення ланцюгового API сценарію в середовищі Postman

**Мета:** Налаштувати автоматичну передачу змінних між запитами у тестовій колекції.

**Вхідний контекст та бізнес-сценарій:**
Створіть колекцію з 3 послідовних запитів: Реєстрація -> Логін (отримання токена) -> Створення задачі з використанням токена.

**Покроковий алгоритм виконання:**
1. У першому запиті згенеруйте унікальний email через `Date.now()` і збережіть у змінну.
2. У другому запиті витягніть `token` із відповіді та збережіть у `pm.environment`.
3. У третьому запиті використайте збережений токен у заголовку Authorization для створення сутності.

**Рекомендований системний AI-промпт:**
```text
Напиши JavaScript-код для вкладок 'Pre-request Script' та 'Tests' у Postman для ланцюжка з 3 кроків: створення користувача, вхід та збереження Bearer токена, та виклик захищеного ендпоінта з отриманим токеном.
```

**Очікуваний результат:**
Повний набір перевірочних скриптів Postman для ланцюгової передачі контексту.

**Критерії самоперевірки та оцінювання:**
- [ ] Використання pm.environment.set() та pm.environment.get()
- [ ] Наявність перевірки pm.response.to.have.status(200/201)
- [ ] Коректне очищення змінних після тесту

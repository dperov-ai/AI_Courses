# Контрольні запитання до Уроку 183: JSON та структуровані дані

Даний блок містить перелік аналітичних та практичних запитань для самоконтролю, перевірки глибини засвоєння матеріалу та підготовки до технічних інтерв’ю.

---

### 1. Чому невідповідність типу даних у JSON (Type Mismatch) є критичною для мобільних додатків?

**Відповідь:** Мобільні додатки на Swift (iOS) та Kotlin (Android) використовують сувору статичну типізацію при десеріалізації JSON (Codable / kotlinx.serialization). Якщо поле очікується як Int, а приходить String, весь процес парсингу падає з фатальною помилкою (Crash) застосунку.

---

### 2. У чому полягає різниця між відсутнім полем (undefined), полем зі значенням null та порожнім масивом []?

**Відповідь:** Відсутнє поле означає, що властивість не передана взагалі. null означає, що поле явно існує, але не має значення. Порожній масив [] означає, що колекція існує і готова до ітерації, але наразі не містить елементів.

---

### 3. Чому повернення null замість порожнього масиву [] вважається поганою практикою бекенду?

**Відповідь:** Тому що клієнтський код на фронтенді часто викликає методи масивів (.length, .map, .filter). Якщо значення дорівнює null, виконання операції призведе до помилки 'Cannot read properties of null'.

---

### 4. Що таке JSONPath і де він використовується тестувальниками?

**Відповідь:** Це мова запитів для навігації та фільтрації елементів усередині складних JSON структур. Вона використовується в інструментах тестування (Postman, RestAssured, JMeter) для швидкого доступу до вкладених даних.

---

### 5. Як у синтаксисі JSONPath вибрати всі елементи масиву, ціна яких перевищує 100?

**Відповідь:** Використовуючи вираз фільтрації: $[?(@.price > 100)].

---

### 6. Які вимоги висуваються до передачі дат та часу в JSON за стандартом ISO 8601?

**Відповідь:** Дата і час повинні передаватися у вигляді рядка з часовим поясом: 'YYYY-MM-DDTHH:mm:ss.sssZ' (наприклад, '2026-10-26T10:15:30.000Z'), де 'Z' означає UTC (нульовий меридіан).

---

### 7. Чому суми грошей у фінансових системах не можна передавати у форматі звичайного дробового числа (float/double)?

**Відповідь:** Через обмеження точності двійкової арифметики з рухомою комою (0.1 + 0.2 !== 0.3). Гроші передають або як ціле число в мінімальних одиницях (копійки, центи: 15000 замість 150.00), або як рядок '150.00'.

---

### 8. Що перевіряє автоматизована валідація JSON Schema у тестах API?

**Відповідь:** Вона перевіряє всю структуру відповіді за один крок: типи кожного поля, наявність обов'язкових полів, діапазони чисел, відповідність регулярним виразам та відсутність заборонених додаткових полів.

---

### 9. Що таке Deep Object Comparison (Глибоке порівняння об'єктів)?

**Відповідь:** Це рекурсивне порівняння двох об'єктів JSON на рівність усіх значень та вкладених структур незалежно від порядку розташування ключів.

---

### 10. Як перевірити структуру масиву об'єктів, якщо кількість елементів невідома заздалегідь?

**Відповідь:** Використовуючи конструкцію JSON Schema: 'type: array, items: { $ref: "#/$defs/ItemSchema" }', яка перевіряє кожен елемент масиву незалежно від його довжини.

---

### 11. Що таке Masked Sensitive Data у JSON-відповідях?

**Відповідь:** Це приховування персональних даних користувачів (наприклад, 'cardNumber': '•••• •••• •••• 4242', 'phone': '+380••••••89') для захисту приватності згідно з GDPR.

---

### 12. Яка різниця між boolean значенням true та рядковим значенням 'true'?

**Відповідь:** Булевий тип true — це логічний примітив. Рядок 'true' — це текст довжиною 4 символи. У багатьох умовах мов програмування рядок 'false' також вважається truthy, що створює важковловимі баги.

---

### 13. Як перевірити унікальність елементів у масиві за допомогою JSON Schema?

**Відповідь:** За допомогою ключового слова 'uniqueItems: true'.

---

### 14. Що означає помилка 'Unexpected token in JSON at position X'?

**Відповідь:** Це синтаксична помилка парсингу: відсутня лапка, зайва кома, наявність коментаря або спецсимволу в некоректному місці.

---

### 15. Як за допомогою AI згенерувати JSON Schema з реальної відповіді сервера?

**Відповідь:** Надати AI приклад JSON відповіді та промпт: 'Створи строгу валідаційну схему JSON Schema Draft 2020-12, визнач обов'язкові поля та заборони additionalProperties'.

---

### 16. Що таке Payload Bloat (роздуття розміру) і як його виявляє QA?

**Відповідь:** Це надмірний обсяг переданих даних, коли сервер повертає 50 непотрібних полів замість 5 потрібних для екрана. QA аналізує заголовок Content-Length та рекомендує оптимізацію.

---

### 17. Як правильно перевіряти вкладені структури з динамічними ключами (Dictionary/Map)?

**Відповідь:** Використовуючи директиву JSON Schema 'patternProperties' або 'additionalProperties: { type: "string" }'.

---

### 18. Чому порядок ключів в об'єкті JSON не повинен мати значення для тестів?

**Відповідь:** Специфікація JSON визначає об'єкт як НЕвпорядковану колекцію пар ключ-значення. Сервер має право повертати ключі в довільному порядку, і тест не повинен падати через зміну послідовності полів.

---

### 19. Що таке Circular Reference у структурах даних і чи можливе воно в чистому JSON?

**Відповідь:** Це циклічне посилання об'єкта на самого себе. У стандартному JSON воно неможливе — спроба серіалізації такого об'єкта призведе до винятку парсера.

---

### 20. Як автоматизувати перевірку великих масивів даних через бібліотеку Ajv?

**Відповідь:** Скомпілювати схему один раз через ajv.compile(schema) та викликати validate(responseBody) для кожного елемента, отримуючи детальний звіт помилок validate.errors.

---

# Практичні завдання до Уроку 185: Аналіз API errors та response payloads

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

## Завдання 1: Локалізація кореневої причини збою (Root Cause Analysis) за допомогою логів та AI

**Мета:** Опанувати дешифровку серверних логів та формування висновків для інженерної команди.

**Вхідний контекст та бізнес-сценарій:**
Під час тестування переказу коштів ендпоінт POST /api/v1/transfers повернув статус 500 Internal Server Error. У системному лозі зафіксовано стек-трейс бази даних.

**Покроковий алгоритм виконання:**
1. Проаналізуйте наданий стек-трейс (Deadlock detected on table 'accounts').
2. Використовуючи AI, визначте точну причину блокування транзакцій.
3. Складіть рекомендації для бекенд-розробника щодо усунення взаємного блокування (Deadlock Prevention).

**Рекомендований системний AI-промпт:**
```text
Дій як Staff QA / SRE. Проаналізуй наступний стек-трейс: 'ERROR: deadlock detected on transaction update accounts SET balance = balance - 100 WHERE id = 1'. Поясни, чому виник Deadlock при паралельних переказах між двома користувачами, та опиши архітектурне рішення для виправлення дефекту.
```

**Очікуваний результат:**
Технічний висновок із детальним поясненням виникнення стану гонки та рекомендаціями щодо сортування ресурсів при блокуванні.

**Критерії самоперевірки та оцінювання:**
- [ ] Правильно визначено причину взаємного блокування
- [ ] Запропоновано сортування ID акаунтів перед транзакцією
- [ ] Складено професійний баг-репорт для розробників

## Завдання 2: Оформлення вичерпного баг-репорту з cURL та RFC 7807 аналізом

**Мета:** Створити зразковий дефект-репорт для критичного збою API за стандартами міжнародних команд.

**Вхідний контекст та бізнес-сценарій:**
Ендпоінт повернення коштів POST /api/v1/refunds повертає некоректний формат помилки без зазначення причин збою.

**Покроковий алгоритм виконання:**
1. Сформуйте точну команду cURL для гарантованого відтворення проблеми.
2. Зафіксуйте розбіжність між очікуваним RFC 7807 форматом та фактичним збоєм.
3. Опишіть рівень критичності (Severity/Priority) та вплив на бізнес.

**Рекомендований системний AI-промпт:**
```text
Склади бездоганний Bug Report на дефект: Ендпоінт POST /api/v1/refunds повертає сирий рядок 'Error 500' замість JSON стандарту RFC 7807 при передачі вже відшкодованого charge_id. Включи передумови, cURL, Expected vs Actual Result та бізнес-вплив.
```

**Очікуваний результат:**
Оформлений баг-репорт у форматі Markdown за структурою enterprise-рівня.

**Критерії самоперевірки та оцінювання:**
- [ ] Повна відтворюваність через готову cURL команду
- [ ] Чітко виділена розбіжність зі стандартом RFC 7807
- [ ] Коректне обґрунтування пріоритету виправлення

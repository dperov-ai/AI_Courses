# Практичні завдання до Уроку 210: Відокремлення відомої проблеми від нового дефекту

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Тріаж вхідних тікетів та зіставлення з базою відомих помилок KEDB

**Мета:** Опанувати швидку ідентифікацію відомих проблем та фільтрацію справжніх нових дефектів.

**Вхідний контекст та бізнес-сценарій:**
У службі підтримки є реєстр із 4 активних відомих проблем (KEDB). Надійшло 5 нових звернень від різних користувачів.

**Покроковий алгоритм виконання:**
1. Проаналізувати 5 вхідних звернень (симптоми, логи, платформи).
2. Зіставити кожне звернення з реєстром KEDB.
3. Для звернень, що є відомими проблемами — надати клієнту відповідний Workaround та прив'язати до батьківського тікета.
4. Для звернення, що є новим дефектом — скласти повноцінний баг-репорт у Jira.

**Рекомендований системний AI-промпт:**
```text
У тебе є база з 3 відомих помилок KEDB [вставити KEDB] та 4 нових звернення клієнтів [вставити звернення]. Для кожного звернення: 1) Визнач, чи це відома помилка (вказавши її ID) чи новий баг, 2) Напиши відповідь клієнту з обхідним шляхом (якщо це KEDB), 3) Якщо це новий баг — оформи детальний тікет для розробників з кроками відтворення.
```

**Очікуваний результат:**
Повний звіт тріажу звернень: точна класифікація, клієнтські відповіді з workaround та один професійний інженерний баг-репорт.

**Критерії самоперевірки та оцінювання:**
- [ ] Точно розмежовано відомі проблеми від нових багів.
- [ ] Обхідні шляхи сформульовані зрозуміло для кінцевого користувача.
- [ ] Новий баг-репорт містить очікуваний та фактичний результат, оточення та стектрейс.

## Завдання 2: Побудова процесу дедуплікації тікетів за допомогою AI-агента

**Мета:** Розробити автоматизований промпт для AI-тріажера, що аналізує вхідні звернення та KEDB.

**Вхідний контекст та бізнес-сценарій:**
Контакт-центр хоче впровадити AI, який в автоматичному режимі перевірятиме кожен новий тікет і маркуватиме його тегом дубліката.

**Покроковий алгоритм виконання:**
1. Сформулювати критерії порівняння для AI (збіг сутностей, HTTP-кодів та дій користувача).
2. Написати системний промпт для AI-класифікатора з поверненням структурованого JSON.
3. Протестувати роботу промпту на суперечливих кейсах (схожі симптоми, але різні платформи).
4. Зафіксувати метрики надійності класифікації.

**Рекомендований системний AI-промпт:**
```text
Створи інженерний системний промпт для AI-агента автоматичного тріажу тікетів підтримки. Промпт повинен приймати текст тікета та JSON-базу відомих проблем, проводити глибокий семантичний аналіз і повертати JSON: { is_known_issue: bool, matched_issue_id: string|null, confidence_score: float, suggested_workaround: string, requires_new_bug_ticket: bool }.
```

**Очікуваний результат:**
Готовий до впровадження системний промпт для автоматизації тріажу у CRM-системі.

**Критерії самоперевірки та оцінювання:**
- [ ] Строгий формат виводу у валідному JSON.
- [ ] Враховано оцінку впевненості (confidence score).
- [ ] Захист від помилкового об'єднання через різні платформи чи коди помилок.

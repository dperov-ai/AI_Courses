# Практичні завдання до Уроку 202: Outline та логічна структура

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Складання та аудит інженерного Outline для керівництва розгортання

**Мета:** Розробити вичерпний покроковий план технічного посібника з розгортання системи моніторингу Prometheus та Grafana у Kubernetes.

**Вхідний контекст та бізнес-сценарій:**
DevOps-команда впроваджує новий стандарт моніторингу. Необхідно створити еталонний план інженерного гайду для внутрішнього порталу розробників.

**Покроковий алгоритм виконання:**
1. Визначити цільову аудиторію та попередні вимоги (доступ до кластера k8s, helm, kubectl).
2. Розробити покрокову структуру від підготовки Helm values до налаштування алертів.
3. Для кожного пункту визначити необхідний артефакт (YAML конфігурація, bash команда, скріншот дашборду).
4. Використати AI для перевірки плану на сліпі зони (безпека RBAC, ліміти ресурсів Pods).

**Рекомендований системний AI-промпт:**
```text
Склади деталізований інженерний Outline для посібника 'Розгортання виробничого моніторингу Prometheus + Grafana в Kubernetes'. Структура повинна включати: Передумови, 5 послідовних кроків реалізації, обов'язкові кроки валідації після кожного кроку, зразки конфігураційних YAML файлів, блок перевірки типових збоїв (CrashLoopBackOff) та матрицю ролей RBAC.
```

**Очікуваний результат:**
Глибоко деталізований Markdown-план статті з анотаціями тез, команд та очікуваних артефактів для кожного розділу.

**Критерії самоперевірки та оцінювання:**
- [ ] Присутні всі обов'язкові етапи життєвого циклу розгортання.
- [ ] Кожен крок супроводжується критерієм валідації.
- [ ] Враховані вимоги безпеки та управління ресурсами.

## Завдання 2: Усунення логічних розривів у сирому плані за допомогою AI

**Мета:** Навчитися знаходити порушення причинно-наслідкових зв'язків у технічних текстах.

**Вхідний контекст та бізнес-сценарій:**
Молодший технічний автор склав хаотичний план статті про налаштування CI/CD пайплайну, де кроки розгортання на Production стоять раніше запуску автоматизованих тестів.

**Покроковий алгоритм виконання:**
1. Проаналізувати наданий дефектний план.
2. Виявити всі логічні інверсії та пропущені фази пайплайну.
3. Перебудувати структуру відповідно до кращих практик DevOps (Lint -> Test -> Build -> Staging -> Prod).
4. Сформулювати перехідні речення між розділами.

**Рекомендований системний AI-промпт:**
```text
Проаналізуй наступний дефектний план статті про CI/CD [вставити план]. Знайди всі порушення логіки, пропущені кроки перевірки якості та безпеки, і запропонуй виправлену хронологічну послідовність з обґрунтуванням кожної зміни.
```

**Очікуваний результат:**
Аналітична таблиця з переліком виявлених дефектів плану та повністю перероблений, логічно бездоганний Outline.

**Критерії самоперевірки та оцінювання:**
- [ ] Усунуто небезпечні перестановки кроків розгортання.
- [ ] Додано етапи безпеки (SAST/DAST) та валідації.
- [ ] Сформульовано перехідні логічні містки між етапами.

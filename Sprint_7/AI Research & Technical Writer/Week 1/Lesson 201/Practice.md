# Практичні завдання до Уроку 201: Information Architecture документа

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Проектування інформаційної архітектури та дерева документації

**Мета:** Розробити збалансовану ієрархічну структуру порталу документації для складного B2B-продукту.

**Вхідний контекст та бізнес-сценарій:**
FinTech-стартап запустив платіжний шлюз для інтернет-магазинів. Документація наразі складається з одного гігантського файлу README на 40 сторінок, у якому неможливо нічого знайти.

**Покроковий алгоритм виконання:**
1. Проаналізувати перелік тем у README (реєстрація, отримання ключів, REST API, Webhooks, тестування, вирішення спорів, безпека PCI DSS).
2. Спроектувати трьохрівневе дерево навігації сайдбару згідно з Diátaxis.
3. Скласти карту взаємних посилань (Cross-linking Matrix) між статтями.
4. Написати промпт для AI, який автоматично розіб'є суцільний текст на окремі Markdown-файли відповідно до спроектованого дерева.

**Рекомендований системний AI-промпт:**
```text
Ти — експерт з Information Architecture технічної документації. Перетвори хаотичний список із 30 тем платіжного шлюзу [вставити перелік тем] на професійну трьохрівневу структуру бокового меню (Sidebar). Використовуй стандарти Diátaxis, дотримуйся Закону Міллера (не більше 7 кореневих категорій) та дай дієслівні семантичні назви кожному розділу.
```

**Очікуваний результат:**
Деталізоване навігаційне дерево порталу документації у форматі списку/Mermaid-діаграми з описом призначення кожного вузла.

**Критерії самоперевірки та оцінювання:**
- [ ] Не більше 6-7 розділів першого рівня.
- [ ] Кожен розділ містить чіткі семантичні підрозділи без змішування концепцій.
- [ ] Заголовки інструкцій сформульовані у дієслівному наказовому способі.

## Завдання 2: Рефакторинг заплутаної статті за принципом «Перевернутої піраміди»

**Мета:** Опанувати реструктуризацію складної інженерної статті для прискорення знаходження рішення.

**Вхідний контекст та бізнес-сценарій:**
Інженер написав статтю про усунення помилки підключення до бази даних, але помістив команду виправлення в кінець 10-го абзацу після розлогих міркувань про історію створення протоколу TCP/IP.

**Покроковий алгоритм виконання:**
1. Виділити з тексту 핵심: симптом, причину та команду негайного виправлення.
2. Переписати початок статті за принципом Inverted Pyramid (TL;DR, Quick Fix).
3. Оформити покрокову діагностику у вигляді нумерованого списку з блоками коду.
4. Перенести історичні та теоретичні деталі в окремий підрозділ «Архітектурні передумови».

**Рекомендований системний AI-промпт:**
```text
Проведи глибокий рефакторинг наданої статті з траблшутингу [вставити текст]. Застосуй принцип перевернутої піраміди: на самий початок винеси блок TL;DR та швидку команду вирішення, далі подай чекліст передумов та нумеровані кроки діагностики, а глибоку теорію залиш у завершальному розділі. Оформи у GitHub Flavored Markdown.
```

**Очікуваний результат:**
Оптимізована стаття, що дозволяє інженеру вирішити інцидент за 30 секунд без вичитування зайвої теорії.

**Критерії самоперевірки та оцінювання:**
- [ ] Присутній чіткий блок швидкого вирішення на початку.
- [ ] Використано коректні семантичні виділення (Callouts, Code blocks).
- [ ] Глибина заголовків не перевищує рівень H3.

# Практичні завдання до Уроку 205: Стандартизація термінології

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Створення корпоративного глосарію та правил лінтера Vale

**Мета:** Розробити нормативний словник термінів компанії та налаштувати автоматизований контроль через конфігурацію Vale.

**Вхідний контекст та бізнес-сценарій:**
У компанії відбувся злиття двох фінансових платформ. Одна називала рахунки «Wallets», інша «Accounts», а третя «Balances». Необхідно навести повний лад.

**Покроковий алгоритм виконання:**
1. Визначити конфліктні терміни та провести їхній аналіз.
2. Сформувати таблицю глосарію з канонічними термінами, забороненими синонімами та визначеннями.
3. Створити конфігураційний файл правила Vale у форматі YAML для автоматичної заміни застарілих слів.
4. Створити тестовий файл Markdown із порушеннями та перевірити роботу правила.

**Рекомендований системний AI-промпт:**
```text
Склади офіційний корпоративний глосарій термінів платіжної платформи для 5 ключових сутностей (Account, Transaction, Settlement, Merchant, Dispute). Для кожної сутності вкажи: 1) Канонічний термін, 2) Заборонені синоніми, 3) Контекстне визначення, 4) YAML-правило для лінтера Vale (тип substitution), що автоматично підсвічує застарілі слова як error.
```

**Очікуваний результат:**
Повний комбінований артефакт: таблиця глосарію в Markdown та готовий робочий конфігураційний блок для Vale.

**Критерії самоперевірки та оцінювання:**
- [ ] Глосарій містить чіткі межі понять без тавтологій.
- [ ] YAML-код для Vale є синтаксично валідним.
- [ ] Покриті всі критичні застарілі синоніми.

## Завдання 2: Автоматизований термінологічний аудит технічної статті за допомогою AI

**Мета:** Опанувати виявлення прихованих термінологічних конфліктів у технічній документації.

**Вхідний контекст та бізнес-сценарій:**
Сторонній підрядник написав документацію інтеграції API, використовуючи кальку з російської мови та застарілі терміни ('белий список', 'авторизація' замість 'автентифікація', 'клієнт' замість 'мерчант').

**Покроковий алгоритм виконання:**
1. Проаналізувати наданий фрагмент статті з дефектами термінології.
2. Створити промпт для AI-аудитора з еталонним корпоративним глосарієм.
3. Провести заміну термінів зі збереженням граматичних зв'язків речень.
4. Скласти звіт про виправлені термінологічні помилки.

**Рекомендований системний AI-промпт:**
```text
Ти — провідний редактор технічної документації. Проскануй наданий фрагмент статті [вставити текст] на предмет відповідності наступному глосарію: [Вживати Merchant замість Client/Partner, Allowlist замість Whitelist, Authentication замість Verification/Auth]. Знайди всі невідповідності, виправ текст зі збереженням природної української мови та надай підсумкову таблицю внесених виправлень.
```

**Очікуваний результат:**
Очищений та стандартизований текст статті, а також детальний звіт лінтингу термінології.

**Критерії самоперевірки та оцінювання:**
- [ ] Усунуто всі невідповідні терміни та русизми.
- [ ] Збережено ідеальну граматичну узгодженість речень після замін.
- [ ] Звіт містить посилання на кожне виправлене слово.

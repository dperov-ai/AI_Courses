# Практичні завдання до Уроку 203: Рівні деталізації

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Створення 3-рівневої архітектурної документації за моделлю C4

**Мета:** Опанувати проектування документації на рівнях Context, Container та Component за допомогою Markdown та Mermaid.

**Вхідний контекст та бізнес-сценарій:**
Компанія створює сервіс онлайн-банкінгу. Необхідно задокументувати систему для різних стейкхолдерів: від інвесторів до розробників модулів безпеки.

**Покроковий алгоритм виконання:**
1. Розробити діаграму System Context (Банкінг, Клієнт, Core Banking System, SMS шлюз).
2. Розробити діаграму Container (Web App, Mobile App, API Gateway, Auth Service, Database).
3. Розробити опис Component для мікросервісу Auth Service (TokenIssuer, PasswordHasher, RateLimiter).
4. Скласти текстовий супровід для кожного рівня відповідно до його аудиторії.

**Рекомендований системний AI-промпт:**
```text
Створи комплексну трирівневу архітектурну документацію за моделлю C4 для онлайн-банкінгу. Для кожного з трьох рівнів (1. System Context, 2. Containers, 3. Auth Service Components) надай: діаграму Mermaid, опис ролей/компонентів, протоколи передачі даних та адаптуй мову викладу під відповідного читача (C-Level -> Tech Lead -> Backend Developer).
```

**Очікуваний результат:**
Повний інженерний документ у форматі Markdown із трьома послідовними рівнями занурення та діаграмами Mermaid.

**Критерії самоперевірки та оцінювання:**
- [ ] Чітке розмежування деталей на кожному рівні C4.
- [ ] Наявність коректних синтаксичних Mermaid-діаграм.
- [ ] Адаптація стилістики під цільову аудиторію кожного рівня.

## Завдання 2: Адаптація технічної статті під Executive та Developer аудиторії через AI

**Мета:** Навчитися трансформувати низькорівневий інженерний звіт у стратегічний бізнес-документ.

**Вхідний контекст та бізнес-сценарій:**
Інженери виявили вразливість нульового дня (Zero-day) у системі автентифікації та випустили патч. Необхідно підготувати два документи: Executive Summary для правління компанії та Detailed Security Advisory для технічної команди клієнта.

**Покроковий алгоритм виконання:**
1. Проаналізувати технічний опис експлойту та патчу.
2. Створити промпт для трансформації тексту в Executive Summary (акцент на ризиках, втратах та захисті клієнтів).
3. Створити промпт для розробників (акцент на CVE, векторі атаки, версіях бібліотек та кроках оновлення).
4. Перевірити обидва документи на відсутність витоку конфіденційної інформації.

**Рекомендований системний AI-промпт:**
```text
На основі наданого інженерного опису інциденту безпеки [вставити текст] згенеруй два окремі документи: 1) Executive Briefing для ради директорів (1 сторінка, без термінів коду, з оцінкою ризиків та статусу захисту), 2) Security Bulletin для сторонніх DevOps/Security інженерів (із зазначенням CVE, CVSS скору, версій пакетів та команд bash для негайного оновлення).
```

**Очікуваний результат:**
Два документи з діаметрально протилежним, але ідеально вивіреним рівнем деталізації під свої цільові групи.

**Критерії самоперевірки та оцінювання:**
- [ ] Executive версія не містить коду і фокусується на бізнес-наслідках.
- [ ] Security Bulletin містить точні інженерні специфікації та кроки захисту.
- [ ] Збережено 100% фактичну точність інформації.

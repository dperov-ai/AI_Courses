# Практичні завдання до Уроку 216: Використання AI для аналізу та моделювання процесів

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Побудова наскрізного AI-пайплайну: Від інтерв'ю до діаграми Mermaid та User Stories

**Мета:** Опанувати повний цикл роботи сучасного аналітика: екстракція, моделювання, декомпозиція за допомогою промптингу.

**Вхідний контекст та бізнес-сценарій:**
Проведено інтерв'ю з керівником відділу закупівель щодо погодження рахунків постачальників. Необхідно створити повний пакет проектних артефактів.

**Покроковий алгоритм виконання:**
1. Використати фреймворк CREATE для екстракції ролей та кроків із тексту розмови.
2. Згенерувати крос-функціональну схему процесу в Mermaid flowchart TD.
3. Застосувати патерн Devil's Advocate для пошуку дірок у безпеці погодження.
4. Сформувати 3 готові User Stories у форматі Gherkin (Given-When-Then) за стандартом INVEST.

**Рекомендований системний AI-промпт:**
```text
Ти — Lead Business Analyst. Використовуючи наданий сирий текст інтерв'ю про закупівлі [вставити текст], виконай 4 послідовні задачі: 1) Виділи таблицю сутностей (ролі, системи, тригери, результати), 2) Згенеруй крос-функціональну схему процесу Mermaid flowchart TD, 3) Проведи аудит вразливостей (Devil's Advocate) та запропонуй 2 додаткові контрольні точки, 4) Створи 3 детальні User Stories за стандартом INVEST із критеріями прийнятності Given-When-Then.
```

**Очікуваний результат:**
Комплексний аналітичний пакет артефактів: таблиця сутностей, схема Mermaid, звіт безпеки та 3 Agile User Stories.

**Критерії самоперевірки та оцінювання:**
- [ ] Повне дотримання всіх 4 етапів інженерного аналізу.
- [ ] Схема Mermaid валідна та містить правильні розгалуження.
- [ ] Сценарії Gherkin описують як позитивні, так і негативні випадки.

## Завдання 2: Стрес-тестування та моделювання виняткових ситуацій за допомогою AI

**Мета:** Навчитися за допомогою штучного інтелекту проектувати компенсаційні підпроцеси для збійних ситуацій.

**Вхідний контекст та бізнес-сценарій:**
У процесі онлайн-бронювання квитків часто виникають збої: зависання платіжного шлюзу, вичерпання місць у момент оплати, обрив з'єднання.

**Покроковий алгоритм виконання:**
1. Описати базовий сценарій бронювання ('Happy Path').
2. Запустити AI-симуляцію 4 критичних виняткових ситуацій (Timeout банку, подвійне списання, збій друку квитка).
3. Для кожного випадку спроектувати компенсаційний підпроцес (Refund, автоскасування резерву, сповіщення підтримки).
4. Оновити загальну процесну схему.

**Рекомендований системний AI-промпт:**
```text
Візьми за основу базовий процес бронювання квитків [вставити кроки]. Проведи симуляцію відмов: змоделюй 3 сценарії технічних збоїв (таймаут шлюзу оплати, відсутність відповіді сервера авіаліній, збій запису в базу). Для кожного збою розроби вичерпний компенсаційний підпроцес (відкат транзакцій, випуск ваучера, сповіщення чергового оператора). Оформи фінальну схему стійкого до відмов процесу.
```

**Очікуваний результат:**
Інженерна модель відмовостійкого процесу з повним описом компенсаційних транзакцій та відновлення консистентності даних.

**Критерії самоперевірки та оцінювання:**
- [ ] Опрацьовані всі сценарії втрати консистентності даних.
- [ ] Запропоновано конкретні автоматичні компенсаційні дії (Saga Pattern / Rollback).
- [ ] Гарантовано захист коштів клієнта та репутації компанії.

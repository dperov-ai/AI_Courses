# Практичні завдання до Уроку 214: BPMN — базові елементи та правила

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Моделювання процесу затвердження кредиту за стандартом BPMN 2.0

**Мета:** Опанувати побудову валідної схеми BPMN з різними типами шлюзів (XOR, AND) та типами завдань.

**Вхідний контекст та бізнес-сценарій:**
Банк модернізує видачу експрес-кредитів. Необхідно створити строгу BPMN-схему взаємодії клієнта, AI скорингу, кредитного аналітика та АБС банку.

**Покроковий алгоритм виконання:**
1. Визначити пул процесу та доріжки: Клієнт, Автоматична система (Service Tasks), Співробітник (User Tasks).
2. Застосувати Service Task для перевірки бюро кредитних історій.
3. Застосувати шлюз Exclusive (XOR) для автоматичної відмови при скорингу < 500.
4. Застосувати шлюз Parallel (AND) для паралельного запиту документів та надсилання SMS.
5. Оформити схему у Mermaid або описі XML.

**Рекомендований системний AI-промпт:**
```text
Створи синтаксично та семантично бездоганну схему BPMN 2.0 для процесу 'Оформлення експрес-кредиту онлайн'. Використай: 1) Стартову подію отримання заявки, 2) Service Task перевірки кредитної історії через API, 3) XOR Gateway для відсікання неплатоспроможних, 4) AND Gateway для одночасного списання комісії та надсилання договору на пошту, 5) User Task для ручного затвердження сум понад 100 000 грн, 6) Відповідні End Events. Оформи у вигляді Mermaid або структурованої специфікації.
```

**Очікуваний результат:**
Повна схема BPMN із точним дотриманням правил взаємодії завдань, шлюзів та коректним завершенням усіх гілок.

**Критерії самоперевірки та оцінювання:**
- [ ] Шлюзи використані за призначенням без ризику дедлоків.
- [ ] Чітко розмежовані Service Tasks та User Tasks.
- [ ] Всі потоки завершуються валідними End Events.

## Завдання 2: Виявлення та виправлення синтаксичних помилок BPMN за допомогою AI

**Мета:** Навчитися знаходити інженерні та логічні помилки у наданих діаграмах BPMN 2.0.

**Вхідний контекст та бізнес-сценарій:**
Молодший аналітик створив схему погодження договору, де перетнув межу пулів суцільною лінією та замкнув гілки XOR-розгалуження в шлюз AND.

**Покроковий алгоритм виконання:**
1. Проаналізувати надану дефектну специфікацію схеми.
2. Знайти всі грубі порушення стандарту BPMN (Deadlock на шлюзі AND, порушення Sequence Flow між пулами, відсутність імен дій).
3. Сформулювати пояснення, чому движок Camunda не зможе виконати цей процес.
4. Скласти виправлену версію схеми.

**Рекомендований системний AI-промпт:**
```text
Проведи аудит наступного опису схеми BPMN [вставити опис]. Знайди всі порушення стандарту BPMN 2.0: 1) Дедлоки на шлюзах, 2) Некоректне використання Sequence Flow між пулами, 3) Непідписані розгалуження, 4) Відсутність обов'язкових подій. Надай детальний аналітичний висновок та виправлену коректну схему.
```

**Очікуваний результат:**
Експертна інженерна рецензія схеми з переліком критичних дефектів та повністю виправленою моделлю процесу.

**Критерії самоперевірки та оцінювання:**
- [ ] Виявлено всі порушення правил нотації OMG BPMN 2.0.
- [ ] Усунуто архітектурний дедлок на злитті шлюзів.
- [ ] Відновлено коректне використання Message Flow.

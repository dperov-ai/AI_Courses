## Завдання 1: Створення централізованого модуля валідації схем для Playwright на базі Ajv

**Мета:** Розробити універсальний хелпер для швидкої валідації JSON Schema в автотестах.

**Вхідний контекст та бізнес-сценарій:**
Створіть модуль schemaValidator.ts, який компілює схеми за допомогою Ajv з підтримкою форматів та надає зручний метод validateSchema(data, schema).

**Покроковий алгоритм виконання:**
1. Ініціалізуйте Ajv з прапорцями allErrors: true та підключіть ajv-formats.
2. Напишіть функцію assertSchema(data, schema), яка викидає зрозумілу помилку з переліком невалідних полів.
3. Застосуйте створений хелпер у тесті отримання списку продуктів.

**Рекомендований системний AI-промпт:**
```text
Напиши утилітарний модуль на TypeScript для Playwright з використанням бібліотеки Ajv та ajv-formats. Реалізуй функцію assertSchema(data, schema), яка виводить детальні помилки валідації у разі збою. Напиши зразок тесту з перевіркою схеми замовлення.
```

**Очікуваний результат:**
Файл schemaValidator.ts та тестовий файл orders-schema.spec.ts.

**Критерії самоперевірки та оцінювання:**
- [ ] Коректне підключення ajv-formats
- [ ] Деталізований вивід шляху до помилкового поля
- [ ] Покриття негативного сценарію невідповідності схеми

## Завдання 2: Розробка валідаційної схеми для складного вкладеного DTO

**Мета:** Спроектувати строгу JSON Schema для відповіді фінансової транзакції з вкладеними об'єктами та масивами.

**Вхідний контекст та бізнес-сценарій:**
Створіть схему для транзакції, що містить ідентифікатор (UUID), суму (number >= 0.01), статус (enum), об'єкт платника та масив коментарів.

**Покроковий алгоритм виконання:**
1. Опишіть схему з strict додатковими властивостями (additionalProperties: false).
2. Додайте регулярний вираз для валідації банківського IBAN номера.
3. Перевірте працездатність схеми на двох тестових JSON об'єктах (валідний та з 3 помилками).

**Рекомендований системний AI-промпт:**
```text
Створи детальну JSON Schema для об'єкта банківської транзакції: id (uuid), amount (число >= 0.01), currency (UAH, USD, EUR), sender (об'єкт з полями name та iban), tags (масив унікальних рядків). Заборони additionalProperties.
```

**Очікуваний результат:**
Схема у форматі TypeScript об'єкта та два зразки тестових даних.

**Критерії самоперевірки та оцінювання:**
- [ ] Використання format: uuid та регулярного виразу для IBAN
- [ ] Наявність uniqueItems: true для тегів
- [ ] Заборона зайвих властивостей на всіх рівнях вкладеності

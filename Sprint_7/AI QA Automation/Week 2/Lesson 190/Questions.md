# Контрольні запитання до Уроку 190: Створення API-запитів

Даний блок містить перелік аналітичних та практичних запитань для самоконтролю, перевірки глибини засвоєння матеріалу та підготовки до технічних інтерв’ю.

---

### 1. У чому полягає суть патерну Service Object в автоматизації тестування API?

**Відповідь:** Service Object інкапсулює роботу з конкретним ресурсом API (маршрути, заголовки, параметри запитів) у методи окремого класу, відокремлюючи мережеві деталі від бізнес-перевірок у тестах і усуваючи дублювання коду.

---

### 2. Як у Playwright надіслати запит із передачею multipart/form-data для завантаження файлу?

**Відповідь:** Використати параметр multipart у методі запиту: await request.post('/upload', { multipart: { file: { name: 'report.pdf', mimeType: 'application/pdf', buffer: fileBuffer } } }).

---

### 3. Чим відрізняється передача параметрів через data та через form у методах Playwright?

**Відповідь:** Параметр data серіалізує об'єкт у формат JSON і встановлює Content-Type: application/json. Параметр form кодує дані у формат ключ-значення (x-www-form-urlencoded).

---

### 4. Як правильно передавати параметри запиту (Query Parameters) у Playwright?

**Відповідь:** Через параметр params: await request.get('/orders', { params: { status: 'PENDING', limit: 10 } }), що автоматично формує валідний URL із кодуванням спецсимволів.

---

### 5. Як налаштувати автоматичні повторні спроби (Retries) при нестабільності мережевого виклику?

**Відповідь:** Налаштувати параметр retries у playwright.config.ts або створити кастомну функцію-обгортку з циклом спроб та експоненційною затримкою (Exponential Backoff).

---

### 6. Що повертає виклик методу request.post() у Playwright?

**Відповідь:** Об'єкт типу APIResponse, який надає асинхронні методи для отримання статусу status(), заголовків headers(), тіла у форматі JSON json() або сирих байтів body().

---

### 7. Чому метод response.json() є асинхронним (потребує await)?

**Відповідь:** Тому що тіло відповіді зчитується з мережевого потоку вхідних байтів асинхронно у міру їх надходження по сокету TCP.

---

### 8. Як зафіксувати точний час виконання запиту для перевірки відповідності SLA?

**Відповідь:** const start = performance.now(); const response = await request.get('/api'); const duration = performance.now() - start; expect(duration).toBeLessThan(300);

---

### 9. Як у Playwright передати кастомні HTTP-заголовки для одного конкретного виклику?

**Відповідь:** Передати об'єкт заголовків через параметр headers у виклику методу: await request.get('/data', { headers: { 'X-Custom-Trace': '12345' } }).

---

### 10. Що відбувається, якщо сервер повертає статус помилки (наприклад, 500) — чи падає Playwright автоматично?

**Відповідь:** Ні! Playwright не викидає виняток при отриманні кодів 4xx або 5xx, дозволяючи тестувальнику самостійно перевірити код статусу та проаналізувати тіло помилки.

---

### 11. Як у Playwright перевірити, чи був запит успішним за допомогою вбудованого методу?

**Відповідь:** Метод response.ok() повертає true, якщо статус-код відповіді знаходиться в діапазоні від 200 до 299.

---

### 12. Як обробляти запити, що повертають потік подій у реальному часі (Server-Sent Events / SSE)?

**Відповідь:** Використовувати потокові читачі (Stream Readers) через бібліотеки Node.js або відкривати постійне з'єднання через WebSocket клієнт.

---

### 13. Як налаштувати глобальний тайм-аут для одного конкретного запиту, якщо він виконує важкі обчислення?

**Відповідь:** Передати параметр timeout у мілісекундах: await request.post('/heavy-task', { timeout: 30000 }).

---

### 14. Що таке трасування мережевих запитів (API Tracing) у Playwright?

**Відповідь:** Збереження детальної хронології всіх надісланих запитів, відповідей, заголовків та таймінгів у trace.zip архів, який можна відкрити у Playwright Trace Viewer для візуального аудиту.

---

### 15. Як запобігти витоку конфіденційних токенів у консольних звітах тест-раннера?

**Відповідь:** Створити власний форматтер логів, який маскує вміст заголовка Authorization перед виведенням у stdout чи файл звітів.

---

### 16. Як передати масив значень у Query параметрах (наприклад, ?status=A&status=B)?

**Відповідь:** Передати масив у params: { status: ['A', 'B'] }, що Playwright скомпілює у правильний формат рядка запиту.

---

### 17. Як протестувати поведінку сервера при передачі невалідно закодованих символів в URL (Invalid URL Encoding)?

**Відповідь:** Сформувати прямий сирий рядок шляху з некоректними відсотковими послідовностями (наприклад, '/api/search?q=%E0%A4') і переконатися в отриманні 400 Bad Request.

---

### 18. Які переваги надає типізація DTO у TypeScript при створенні запитів?

**Відповідь:** Автодоповнення полів в IDE, запобігання помилкам у назвах властивостей та помилкам типів даних ще на етапі написання тестового коду до запуску тесту.

---

### 19. Як за допомогою AI автоматично згенерувати Service Object класи з OpenAPI специфікації?

**Відповідь:** Надати AI файл OpenAPI зі схемою шляхів та промптом: 'Згенеруй клас Service Object на TypeScript для Playwright з методами для кожного ендпоінта та суворою типізацією DTO'.

---

### 20. Як організувати видалення тестових сутностей, якщо в тесті виникла помилка?

**Відповідь:** Зберегти створений ID у змінну перед виконанням дій та викликати delete-метод у блоці try...finally або всередині фікстури після await use().

---

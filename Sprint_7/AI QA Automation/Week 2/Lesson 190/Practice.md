# Практичні завдання до Уроку 190: Створення API-запитів

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Створення модульного Service Object для роботи з каталогом товарів

**Мета:** Побудувати типізований клієнтський клас для роботи з товарами на базі Playwright APIRequestContext.

**Вхідний контекст та бізнес-сценарій:**
Розробіть клас ProductsService, який підтримує створення продукту, отримання списку з параметрами пагінації та фільтрації, оновлення ціни та видалення.

**Покроковий алгоритм виконання:**
1. Визначте TypeScript інтерфейси ProductDTO, CreateProductRequest та FilterParams.
2. Реалізуйте клас ProductsService з методами create, getList, updatePrice, delete.
3. Напишіть тест, який створює 2 товари, фільтрує їх за категорією та перевіряє успішний статус.

**Рекомендований системний AI-промпт:**
```text
Напиши виробничий клас ProductsService на TypeScript для Playwright. Реалізуй методи роботи з /api/v1/products з повною типізацією вхідних DTO та Query-параметрів. Додай зразок E2E тесту з використанням сервісу.
```

**Очікуваний результат:**
Файли ProductsService.ts та products-flow.spec.ts.

**Критерії самоперевірки та оцінювання:**
- [ ] Повна типізація без використання 'any'
- [ ] Коректне формування Query-параметрів
- [ ] Чітке розділення відповідальності між сервісом і тестом

## Завдання 2: Автоматизація завантаження файлу через multipart/form-data

**Мета:** Написати автотест для перевірки ендпоінта завантаження користувацького аватара.

**Вхідний контекст та бізнес-сценарій:**
Ендпоінт POST /api/v1/users/avatar приймає файл зображення (PNG/JPEG) до 2 Мб та повертає публічний URL завантаженого файлу.

**Покроковий алгоритм виконання:**
1. Створіть у пам'яті Buffer тестового зображення або використайте фікстуру файлу.
2. Надішліть multipart запит через Playwright request.post().
3. Перевірте отримання статусу 201 Created та валідацію URL у тілі відповіді.

**Рекомендований системний AI-промпт:**
```text
Створи автотест на Playwright TypeScript для завантаження файлу аватара через multipart/form-data. Перевір статус 201, перевір, що повернутий URL починається з 'https://cdn.', та додай негативний тест на спробу завантаження файлу забороненого формату (.exe).
```

**Очікуваний результат:**
Файл тесту upload-avatar.spec.ts із позитивним та негативним сценаріями.

**Критерії самоперевірки та оцінювання:**
- [ ] Використання параметра multipart у запиті
- [ ] Асерт наявності поля avatarUrl у відповіді
- [ ] Перевірка відхилення невалідного формату файлу

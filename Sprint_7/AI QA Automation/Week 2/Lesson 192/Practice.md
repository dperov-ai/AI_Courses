# Практичні завдання до Уроку 192: Positive та negative API scenarios

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Створення вичерпного параметризованого негативного сьюту для ендпоінта оплати

**Мета:** Побудувати автоматизований набір перевірок на базі Playwright, що охоплює 6 різних негативних векторів.

**Вхідний контекст та бізнес-сценарій:**
Ендпоінт POST /api/v1/payments приймає amount (number > 0), currency (UAH, USD, EUR) та cardToken. Реалізуйте параметризований сьют перевірок.

**Покроковий алгоритм виконання:**
1. Визначте 6 негативних випадків: сума 0, від'ємна сума, непідтримувана валюта, порожній токен, невалідний JSON, відсутність авторизації.
2. Створіть масив тестових кейсів із зазначенням вхідних даних та очікуваних статус-кодів (400, 401, 422).
3. Реалізуйте тест у Playwright з перевіркою коректності повернення помилок.

**Рекомендований системний AI-промпт:**
```text
Напиши параметризований E2E автотест на Playwright TypeScript для ендпоінта POST /api/v1/payments. Покрий 6 негативних сценаріїв валідації та безпеки, перевіряючи статус-коди 400, 401, 422 та наявність опису помилки в JSON.
```

**Очікуваний результат:**
Файл payments-negative.spec.ts із повною параметризацією та типізацією.

**Критерії самоперевірки та оцінювання:**
- [ ] Покриття щонайменше 6 різних негативних умов
- [ ] Коректне використання параметризованого циклу
- [ ] Асерти на статус-код та структуру повідомлення про помилку

## Завдання 2: Побудова позитивного E2E флоу з перевіркою зміни бізнес-стану

**Мета:** Написати повний позитивний сценарій життєвого циклу замовлення з верифікацією бази даних через API.

**Вхідний контекст та бізнес-сценарій:**
Реалізуйте сценарій: Створення клієнта -> Створення замовлення -> Оплата -> Перевірка фінального статусу замовлення 'PAID'.

**Покроковий алгоритм виконання:**
1. Створіть унікального клієнта через API та збережіть токен.
2. Створіть замовлення на 2 товари та перевірте початковий статус 'PENDING'.
3. Здійсніть успішну оплату через виклик ендпоінта платежів.
4. Виконайте фінальний GET-запит та підтвердіть статус 'PAID' і наявність номера транзакції.

**Рекомендований системний AI-промпт:**
```text
Створи повний позитивний E2E автотест на Playwright TypeScript для життєвого циклу покупки: реєстрація користувача, створення замовлення, оплата та перевірка фінального статусу 'PAID'.
```

**Очікуваний результат:**
Файл тесту order-lifecycle-positive.spec.ts.

**Критерії самоперевірки та оцінювання:**
- [ ] Ланцюгове прокидання ідентифікаторів між запитами
- [ ] Перевірка зміни статусу сутності
- [ ] Повна автономність та детермінованість тесту

## Завдання 1: Створення комплексного сьюту асертів з використанням Soft Assertions

**Мета:** Розробити надійний автотест для валідації складної фінансової відповіді за допомогою expect.soft.

**Вхідний контекст та бізнес-сценарій:**
Перевірте ендпоінт отримання виписки за рахунком GET /api/v1/accounts/:id/statement. Відповідь містить номер рахунку, баланс, ліміти, статус та масив останніх 5 транзакцій.

**Покроковий алгоритм виконання:**
1. Виконайте запит та перевірте успішний статус через жорсткий асерт expect(response.ok()).toBeTruthy().
2. Реалізуйте серію з 6 soft-перевірок на поля облікового запису (статус ACTIVE, баланс >= 0, валюта UAH).
3. Для кожної транзакції у масиві перевірте валідність дати ISO 8601 та наявність ненульової суми.

**Рекомендований системний AI-промпт:**
```text
Напиши автотест на Playwright TypeScript з використанням expect.soft для валідації виписки рахунку. Забезпеч жорстку перевірку статусу та м'які перевірки для всіх вкладених полів і масиву транзакцій.
```

**Очікуваний результат:**
Файл тесту account-statement.spec.ts із повною типізацією та soft асертами.

**Критерії самоперевірки та оцінювання:**
- [ ] Коректне використання expect.soft
- [ ] Повне покриття полів верхнього рівня та вкладеного масиву
- [ ] Інформативні описи для кожного асерта

## Завдання 2: Розробка кастомного матчера toBeValidISO8601Date

**Мета:** Розширити функціонал бібліотеки expect кастомним доменним матчером дати.

**Вхідний контекст та бізнес-сценарій:**
Створіть повторно використовуваний матчер, що перевіряє валідність формату ISO дати та її відповідність поточному часовому інтервалу.

**Покроковий алгоритм виконання:**
1. Створіть файл customMatchers.ts та розширте інтерфейс Matchers у просторі імен PlaywrightTest.
2. Реалізуйте логіку перевірки через регулярний вираз та перевірку new Date(val).getTime().
3. Напишіть тест, що демонструє використання expect(res.createdAt).toBeValidISO8601Date().

**Рекомендований системний AI-промпт:**
```text
Створи кастомний матчер toBeValidISO8601Date для Playwright на TypeScript. Додай типізацію глобального інтерфейсу та напиши тест для перевірки його роботи на валідній та невалідній датах.
```

**Очікуваний результат:**
Файл customMatchers.ts з розширенням типів та тестовий файл test-custom-matcher.spec.ts.

**Критерії самоперевірки та оцінювання:**
- [ ] Сувора типізація TypeScript
- [ ] Коректний синтаксис expect.extend()
- [ ] Зрозуміле повідомлення про помилку у разі збою

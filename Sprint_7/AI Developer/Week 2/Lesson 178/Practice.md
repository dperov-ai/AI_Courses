## Завдання 1: Реалізація Auth Middleware для перевірки JWT та RBAC захисту

**Мета:** Написати безпечне серверне middleware для перевірки валідності токенів та контролю доступу за ролями.

**Вхідний контекст та бізнес-сценарій:**
Створіть модуль захисту API маршрутів для платформи, що розмежовує доступ між звичайними користувачами (USER) та адміністраторами (ADMIN).

**Покроковий алгоритм виконання:**
1. Реалізуйте middleware `authenticateToken`, що витягує Bearer токен із заголовка Authorization.
2. Верифікуйте токен за допомогою секретного ключа та впровадьте розшифровані дані користувача у `req.user`.
3. Реалізуйте middleware вищого порядку `requireRole(['ADMIN'])`, що повертає 403 Forbidden, якщо роль недостатня.

**Рекомендований системний AI-промпт:**
```text
Напиши код двох Express middleware на TypeScript: authenticateJWT (перевірка токена через jsonwebtoken) та authorizeRoles(...roles) для контролю доступу. Оброби сценарії відсутності токена (401), простроченого токена (401) та недостатніх прав (403).
```

**Очікуваний результат:**
TypeScript файл authMiddleware.ts із працездатними функціями перевірки автентифікації та ролей.

**Критерії самоперевірки та оцінювання:**
- [ ] Коректний парсинг префікса 'Bearer '
- [ ] Повернення 401 при недійсному токені
- [ ] Повернення 403 при невідповідності ролі

## Завдання 2: Проектування архітектури безпечної автентифікації з Access та Refresh токенами

**Мета:** Спроектувати повну схему входу, ротації токенів та виходу з системи.

**Вхідний контекст та бізнес-сценарій:**
Розробіть контракт безпеки для сервісу інтернет-банкінгу. Опишіть життєвий цикл токенів, зберігання в базі даних та реакцію на витік токена.

**Покроковий алгоритм виконання:**
1. Складіть таблицю структури бази даних для збереження активних Refresh-сесій (userId, tokenHash, expiresAt, deviceFingerprint).
2. Опишіть алгоритм роботи ендпоінта POST /api/v1/auth/refresh з обов'язковою ротацією токенів.
3. Опишіть процедуру примусового завершення сесій на всіх пристроях (Global Logout).

**Рекомендований системний AI-промпт:**
```text
Спроектуй технічну архітектуру механізму Access/Refresh токенів для високобезпечного фінансового сервісу. Опиши схему бази даних, час життя токенів, налаштування cookie та алгоритм дій у разі виявлення повторного використання Refresh токена.
```

**Очікуваний результат:**
Детальний технічний документ архітектури автентифікації у форматі Markdown.

**Критерії самоперевірки та оцінювання:**
- [ ] Використання HttpOnly Secure Cookie для Refresh токена
- [ ] Описано захист від повторного використання (Token Reuse Detection)
- [ ] Схема таблиці сесій із хешуванням токенів

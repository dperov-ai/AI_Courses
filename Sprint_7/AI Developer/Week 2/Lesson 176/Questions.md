# Контрольні запитання до Уроку 176: Створення та використання API

Даний блок містить перелік аналітичних та практичних запитань для самоконтролю, перевірки глибини засвоєння матеріалу та підготовки до технічних інтерв’ю.

---

### 1. У чому полягає філософія підходу API-First (Design-First) у порівнянні з Code-First?

**Відповідь:** API-First передбачає проектування та узгодження контракту API (OpenAPI/Swagger) до написання коду. Це дозволяє фронтенду, бекенду та QA працювати паралельно, використовуючи мок-сервери, і усуває проблеми несумісності на пізніх етапах.

---

### 2. Що таке CORS (Cross-Origin Resource Sharing) і від якої загрози він захищає?

**Відповідь:** CORS — це механізм безпеки веб-браузерів, що контролює доступ скриптів з одного джерела (Origin) до ресурсів іншого джерела за допомогою HTTP-заголовків. Він захищає конфіденційні дані користувача від викрадення шкідливими сайтами.

---

### 3. Що таке Preflight-запит у CORS і в яких випадках браузер його відправляє?

**Відповідь:** Це запит методом OPTIONS, який браузер автоматично надсилає перед основним запитом, якщо той містить нетипові заголовки (Authorization), методи, відмінні від GET/POST, або Content-Type, відмінний від application/x-www-form-urlencoded, multipart/form-data чи text/plain.

---

### 4. Чому налаштування 'Access-Control-Allow-Origin: *' є небезпечним для захищених ендпоінтів?

**Відповідь:** Значення '*' дозволяє будь-якому сторонньому веб-сайту надсилати запити до вашого API. Якщо застосунок використовує автентифікацію на рівні сесійних кук чи IP, зловмисник може отримати несанкціонований доступ до даних жертви.

---

### 5. Яку роль виконує бібліотека Mock Service Worker (MSW) або Prism у розробці API?

**Відповідь:** Вона створює повноцінний віртуальний сервер на основі OpenAPI схеми, який перехоплює мережеві запити фронтенду та повертає детерміновані тестові дані без потреби розгортання реального бекенду.

---

### 6. Як правильно передавати та обробляти параметри шляху (Path Parameters) у серверних маршрутах?

**Відповідь:** Шляхові параметри вбудовуються у шаблон URL (наприклад, /api/v1/users/:id) і використовуються для однозначної ідентифікації конкретного екземпляра ресурсу.

---

### 7. У чому різниця між Query Parameters та Path Parameters з точки зору архітектури?

**Відповідь:** Path Parameters ідентифікують конкретний ресурс (/users/12). Query Parameters використовуються для модифікації отримання ресурсу чи колекції (фільтрація, сортування, пагінація: /users?role=admin).

---

### 8. Що таке Webhook і чим він відрізняється від класичного API?

**Відповідь:** Класичний API працює за моделлю Pull (клієнт запитує дані у сервера). Webhook працює за моделлю Push (сервер сам надсилає HTTP POST-запит на вказаний клієнтом URL при виникненні певної події, наприклад, успішної оплати).

---

### 9. Як забезпечити безпеку вхідних Webhook-повідомлень (наприклад, від Stripe чи GitHub)?

**Відповідь:** Через перевірку криптографічного цифрового підпису (HMAC SHA-256) у заголовку запиту за допомогою спільного секретного ключа (Webhook Secret).

---

### 10. Що таке API Gateway та навіщо його ставлять перед пулом бекенд-сервісів?

**Відповідь:** Це єдина точка входу, яка централізує автентифікацію, лімітування запитів (Rate Limiting), маршрутизацію, CORS, моніторинг та SSL-термінацію, захищаючи внутрішні мікросервіси.

---

### 11. Яку інформацію повинен містити заголовок Location у відповіді на POST-запит?

**Відповідь:** Він повинен містити прямий URL новоствореного ресурсу (наприклад, 'Location: /api/v1/orders/ord_991').

---

### 12. Яким чином реалізується версіонування у виробничих API?

**Відповідь:** Через включення версії в базовий шлях URL (/api/v1/...), через заголовок запиту (X-API-Version: 1) або через Accept заголовок.

---

### 13. Що таке бібліотека Axios і які її ключові переваги над стандартним fetch() у браузері?

**Відповідь:** Axios підтримує автоматичну серіалізацію/десеріалізацію JSON, перехоплювачі запитів та відповідей (Interceptors), вбудований захист від XSRF та зручне налаштування тайм-аутів.

---

### 14. Для чого використовуються Axios Interceptors (Перехоплювачі)?

**Відповідь:** Для глобального додавання токена авторизації до кожного вихідного запиту та централізованої обробки помилок 401 (автоматичне оновлення токена через Refresh Token).

---

### 15. Що таке Rate Limiting і який алгоритм найчастіше використовується для його реалізації?

**Відповідь:** Це обмеження кількості запитів від одного користувача чи IP за проміжок часу. Найпопулярніший алгоритм — Token Bucket (або Leaky Bucket) з використанням Redis.

---

### 16. Який статус-код повинен повертати сервер, якщо клієнт перевищив допустиму частоту запитів?

**Відповідь:** 429 Too Many Requests з обов'язковим заголовком 'Retry-After: <секунди>'.

---

### 17. Як організувати кешування відповідей GET-запитів на рівні клієнта за допомогою HTTP-заголовків?

**Відповідь:** Сервер надсилає заголовок 'Cache-Control: public, max-age=3600, stale-while-revalidate=60', що дозволяє клієнту використовувати кеш протягом години.

---

### 18. Що таке контракти даних DTO (Data Transfer Object)?

**Відповідь:** Це структуровані об'єкти, що визначають точний формат даних, якими обмінюються клієнт і сервер, відокремлюючи мережевий контракт від внутрішніх моделей бази даних.

---

### 19. Чому не можна віддавати клієнту об'єкти ORM безпосередньо з бази даних?

**Відповідь:** Це загрожує витоком чутливих полів (паролі, внутрішні статуси) та створює жорстку залежність клієнта від структури таблиць СУБД.

---

### 20. Як штучний інтелект спрощує інтеграцію сторонніх API?

**Відповідь:** AI здатен миттєво генерувати код клієнтських функцій, типізовані інтерфейси TypeScript та автоматичні моки на основі відкритої документації або OpenAPI схеми.

---

# Практичні завдання до Уроку 177: Обробка запитів та відповідей

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Реалізація централізованого обробника помилок та Correlation ID Middleware

**Мета:** Побудувати надійний production-ready конвеєр обробки запитів із наскрізним логуванням.

**Вхідний контекст та бізнес-сценарій:**
Розробіть серверну інфраструктуру логування та обробки винятків для фінансового сервісу, що забезпечує генерацію Correlation ID та маскування деталей помилки 500.

**Покроковий алгоритм виконання:**
1. Створіть middleware для перевірки або генерації заголовка X-Correlation-ID за допомогою uuidv4.
2. Створіть кастомний клас помилки AppError з полями statusCode, errorCode та isOperational.
3. Реалізуйте фінальний Error Middleware, що логує повний стек у термінал і повертає стандартизований RFC 7807 JSON клієнту.

**Рекомендований системний AI-промпт:**
```text
Напиши код централізованої системи обробки помилок для Express на TypeScript. Створи клас AppError, middleware додавання X-Correlation-ID та кінцевий errorHandler middleware. Забезпеч маскування стек-трейсу для 500 помилок.
```

**Очікуваний результат:**
Повний набір TypeScript файлів: AppError.ts, correlationMiddleware.ts та errorHandler.ts.

**Критерії самоперевірки та оцінювання:**
- [ ] Генерація UUID для кожного запиту
- [ ] Коректне розрізнення оперативних та системних помилок
- [ ] Стандартизований JSON вихід для клієнта

---

## Завдання 2: Створення валідаційного Middleware на базі Zod

**Мета:** Написати універсальне middleware, що автоматично перевіряє вхідні DTO до виклику контролера.

**Вхідний контекст та бізнес-сценарій:**
Захистіть бекенд від невалідних запитів шляхом створення універсального валідатора схем.

**Покроковий алгоритм виконання:**
1. Напишіть функцію validateRequest(schema), яка приймає схему Zod.
2. Перевірте req.body, req.query та req.params залежно від налаштувань.
3. При невідповідності поверніть клієнту статус 422 з детальним списком некоректних полів.

**Рекомендований системний AI-промпт:**
```text
Створи універсальне Express middleware для валідації запитів через бібліотеку Zod на TypeScript. Middleware повинно приймати схему для body/query і повертати детальний 422 JSON у разі помилок.
```

**Очікуваний результат:**
Працездатне middleware validateRequest з прикладом його застосування на маршруті створення замовлення.

**Критерії самоперевірки та оцінювання:**
- [ ] Універсальність для будь-якої схеми Zod
- [ ] Повернення зрозумілих повідомлень про помилки полів
- [ ] Виклик next() тільки при 100% валідності

# Контрольні запитання до Уроку 175: JSON

Даний блок містить перелік аналітичних та практичних запитань для самоконтролю, перевірки глибини засвоєння матеріалу та підготовки до технічних інтерв’ю.

---

### 1. Які 6 базових типів даних підтримуються специфікацією JSON (RFC 8259)?

**Відповідь:** Рядок (String), Число (Number), Логічний тип (Boolean: true/false), Null, Об'єкт (Object), Масив (Array).

---

### 2. Чому в стандартному JSON категорично заборонено використовувати одинарні лапки?

**Відповідь:** Специфікація JSON строго вимагає використання лише подвійних лапок для позначення рядків та імен ключів. Використання одинарних лапок призводить до синтаксичної помилки парсера.

---

### 3. Що відбувається зі значенням undefined у JavaScript-об'єкті під час його серіалізації через JSON.stringify()?

**Відповідь:** Якщо undefined є значенням властивості об'єкта, ця властивість повністю опускається (видаляється). Якщо undefined знаходиться у масиві, воно замінюється на null.

---

### 4. У чому полягає проблема переповнення чисел (Number Overflow) у JSON при передачі великих 64-бітних цілих чисел?

**Відповідь:** Багато мов програмування (зокрема JavaScript) використовують числа подвійної точності IEEE 754, де максимальне безпечне ціле число становить 2^53 - 1. Будь-які 64-бітні ID (наприклад, Twitter Snowflake) спотворюються при парсингу, тому їх необхідно передавати у вигляді рядків.

---

### 5. Що таке Trailing Comma (завершальна кома) і чому вона є помилкою в JSON?

**Відповідь:** Це кома після останнього елемента списку або властивості об'єкта (наприклад, [1, 2, 3,]). За стандартом JSON вона заборонена, і строгі парсери викинуть помилку SyntaxError.

---

### 6. Яка різниця між серіалізацією та десеріалізацією?

**Відповідь:** Серіалізація — це перетворення програмного об'єкта з пам'яті в текстовий або бінарний рядок JSON для передачі чи збереження. Десеріалізація — зворотне перетворення текстового рядка JSON у структурований програмний об'єкт.

---

### 7. Що таке JSON Schema і яке її головне практичне призначення в API?

**Відповідь:** Це формальна декларативна специфікація для опису структури, типів даних, обов'язкових полів та обмежень JSON-документа. Вона використовується для автоматичної валідації контрактів API та генерації документації.

---

### 8. Чому коментарі офіційно відсутні у специфікації JSON?

**Відповідь:** Автор JSON Дуглас Крокфорд навмисно видалив коментарі зі специфікації, щоб запобігти їх використанню для передачі директив парсерам, зберігаючи формат максимально простим та кросплатформним.

---

### 9. Як правильно передавати дати та час у форматі JSON?

**Відповідь:** Стандарт JSON не має окремого типу для дати, тому дати передаються у вигляді рядків згідно зі стандартом ISO 8601 (наприклад, '2026-10-26T10:45:00.000Z').

---

### 10. Що таке тип даних JSONB у реляційних базах даних (наприклад, у PostgreSQL)?

**Відповідь:** JSONB — це збереження JSON у розібраному двійковому форматі, що забезпечує значно швидший пошук, підтримку індексів GIN/BTREE та можливість фільтрації за окремими ключами без повного парсингу тексту.

---

### 11. Як оптимізувати розмір великого JSON-документа для передачі по мережі?

**Відповідь:** Використовувати стиснення Gzip або Brotli на рівні HTTP, скорочувати довжину імен ключів, видаляти null/undefined поля та відключати форматування відступами (Pretty-print).

---

### 12. Що таке MIME-тип для формату JSON і як він зазначається в заголовках HTTP?

**Відповідь:** Офіційний стандартизований MIME-тип — 'application/json'.

---

### 13. Яким чином обробляти помилки синтаксису при парсингу JSON на стороні сервера?

**Відповідь:** Операцію JSON.parse() обов'язково огортають у блок try/catch, а у разі винятку повертають клієнту коректну відповідь 400 Bad Request із зазначенням помилки парсингу.

---

### 14. Що таке цикли посилань (Circular References) в об'єктах і чому вони ламають JSON.stringify()?

**Відповідь:** Це ситуація, коли об'єкт 'A' посилається на об'єкт 'B', а 'B' посилається назад на 'A'. Стандартний JSON.stringify() зациклюється і викидає виняток 'TypeError: Converting circular structure to JSON'.

---

### 15. Які інструменти командного рядка використовуються для швидкої фільтрації та форматування JSON?

**Відповідь:** Утиліта `jq`, яка дозволяє витягувати окремі поля, фільтрувати масиви та трансформувати структури безпосередньо в терміналі.

---

### 16. Що таке JSONP (JSON with Padding) і чи використовується воно сьогодні?

**Відповідь:** Це застарілий хак для обходу політики Same-Origin Policy в епоху до винайдення CORS, коли дані загорталися у виклик JavaScript-функції. Сьогодні вважається небезпечним антипатерном і не використовується.

---

### 17. Що визначає директива 'additionalProperties: false' у JSON Schema?

**Відповідь:** Вона суворо забороняє наявність будь-яких додаткових полів у перевіреному об'єкті, окрім тих, що явно описані в секції 'properties', захищаючи від атак типу Mass Assignment.

---

### 18. Як у JSON передати спеціальні символи (лапки, перенесення рядків, слеші)?

**Відповідь:** За допомогою символу зворотного слешу (Escape-послідовності): \", \\, \/, \n, \r, \t, \uXXXX для довільних символів Юнікоду.

---

### 19. У чому перевага JSON над бінарними форматами (Protobuf, MessagePack) при розробці веб-додатків?

**Відповідь:** JSON є людиночитабельним (Human-Readable), його легко інспектувати у вкладці Network DevTools без спеціальних компіляторів чи схем декодування.

---

### 20. Як генеративний AI використовує structured outputs (JSON Mode)?

**Відповідь:** Сучасні моделі підтримують режим генерації валідного JSON за наданою JSON-схемою, що гарантує 100% відповідність відповіді моделі програмним контрактам застосунку.

---

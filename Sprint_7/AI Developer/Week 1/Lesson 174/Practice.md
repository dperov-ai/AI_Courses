# Практичні завдання до Уроку 174: REST API

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

## Завдання 1: Проектування повного REST API контракту для сервісу електронної комерції

**Мета:** Розробити RESTful структуру ендпоінтів з дотриманням іменування, статус-кодів та семантики методів.

**Вхідний контекст та бізнес-сценарій:**
Спроектуйте API бекенду інтернет-магазину для сутностей Продукти (Products), Категорії (Categories) та Замовлення (Orders).

**Покроковий алгоритм виконання:**
1. Складіть таблицю з 10 ендпоінтів для операцій читання, створення, фільтрації, оновлення та видалення.
2. Для кожного маршруту вкажіть HTTP-метод, URI, очікувані параметри запиту та HTTP статус-коди успіху і помилок.
3. Розробіть приклад відповіді у форматі JSON для списку замовлень із підтримкою курсорної пагінації.

**Рекомендований системний AI-промпт:**
```text
Дій як Lead API Architect. Спроектуй RESTful специфікацію контракту для інтернет-магазину на основі наданих вимог. Склади таблицю маршрутів, опиши структуру DTO та правила пагінації. Забезпеч відповідність Рівню 2 моделі Річардсона.
```

**Очікуваний результат:**
Документ специфікації REST API з таблицею маршрутів, правилами статусів та прикладами JSON.

**Критерії самоперевірки та оцінювання:**
- [ ] Всі маршрути використовують іменники у множині
- [ ] Коректно підібрані HTTP-методи та коди відповідей
- [ ] Реалізовано параметри для сортування та пагінації

## Завдання 2: Рефакторинг застарілого RPC API в істинний RESTful стиль

**Мета:** Виявити антипатерни в існуючому API та трансформувати його у чисту REST-архітектуру.

**Вхідний контекст та бізнес-сценарій:**
Вам передано спадковий бекенд, де всі маршрути побудовані хаотично: POST /createUser, POST /deleteUserById, GET /updateUserEmail. Необхідно провести рефакторинг контрактів.

**Покроковий алгоритм виконання:**
1. Випишіть 5 антипатернів зі спадкового API та поясніть, чому вони шкодять підтримуваності.
2. Перепишіть маршрути відповідно до стандартів REST (використання ресурсів, HTTP-дієслів та статусів).
3. Складіть таблицю зіставлення старого API та нового REST контракту.

**Рекомендований системний AI-промпт:**
```text
Проведи аудит спадкового API: POST /addNewProduct, POST /removeProduct?id=5, GET /editProductPrice. Перетвори його на чистий RESTful дизайн. Опиши переваги нової архітектури.
```

**Очікуваний результат:**
Звіт аудиту з таблицею міграції старих RPC-ендпоінтів на чисті RESTful маршрути.

**Критерії самоперевірки та оцінювання:**
- [ ] Повне усунення дієслів з URI
- [ ] Застосування коректних методів POST, GET, PATCH, DELETE
- [ ] Чіткий опис відповідності статус-кодів

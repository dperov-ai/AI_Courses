# Практичні завдання до Уроку 173: HTTP та принципи обміну даними

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Аналіз та конструювання HTTP-запитів через cURL та DevTools

**Мета:** Опанувати роботу з сирими HTTP-запитами, передачею заголовків та аналізом кодів відповідей.

**Вхідний контекст та бізнес-сценарій:**
Вам необхідно протестувати взаємодію з публічним REST API сервісом (наприклад, JSONPlaceholder або ReqRes). Використовуючи cURL, виконайте серію запитів для перевірки створення та отримання даних.

**Покроковий алгоритм виконання:**
1. Складіть cURL команду для відправки POST-запиту з JSON payload, заголовками Content-Type та Authorization.
2. Виконайте запит з прапорцем -i / -v для виведення всіх вхідних та вихідних заголовків.
3. Проаналізуйте отримані HTTP-статуси та заголовки Date, Server, Content-Type, Content-Length.

**Рекомендований системний AI-промпт:**
```text
Створи набір із 4 production-ready cURL команд для перевірки CRUD операцій на REST API: створення ресурсу (POST), отримання (GET), часткове оновлення (PATCH) та видалення (DELETE). Додай пояснення до кожного заголовка та очікуваного коду статусу.
```

**Очікуваний результат:**
Вичерпний перелік команд cURL із поясненням семантики використаних заголовків та кодів відповідей.

**Критерії самоперевірки та оцінювання:**
- [ ] Використано коректні методи HTTP та заголовки Content-Type/Accept
- [ ] Правильно описано різницю між кодами 200, 201 та 204
- [ ] Наведено пояснення семантики ідемпотентності для кожного виклику

## Завдання 2: Проектування матриці статус-кодів та обробки помилок для API

**Мета:** Спроектувати стандарт обробки помилок у команді відповідно до RFC 7807 (Problem Details for HTTP APIs).

**Вхідний контекст та бізнес-сценарій:**
Розробіть уніфікований формат повернення помилок бекендом, щоб клієнтські застосунки могли однозначно розпізнавати причину збою та коректно інформувати користувача.

**Покроковий алгоритм виконання:**
1. Визначте структуру JSON-відповіді для помилок: type, title, status, detail, instance, invalidParams.
2. Складіть таблицю з 8 типових збоїв системи та призначте кожному точний HTTP статус-код (400, 401, 403, 404, 409, 422, 429, 500).
3. Опишіть, як захистити продакшн-відповіді від випадкового витоку внутрішніх деталей стек-трейсу.

**Рекомендований системний AI-промпт:**
```text
Розроби технічний стандарт формату помилок REST API за стандартом RFC 7807 для enterprise-застосунку. Наведи приклади JSON-відповідей для помилок валідації (422), відсутності авторизації (401) та перевищення ліміту запитів (429).
```

**Очікуваний результат:**
Специфікація формату помилок у форматі Markdown із валідними JSON-прикладами та матрицею статусів.

**Критерії самоперевірки та оцінювання:**
- [ ] Відповідність стандарту RFC 7807
- [ ] Наявність деталізованих повідомлень для полів валідації
- [ ] Відсутність конфіденційних деталей сервера в тілі 500 помилки

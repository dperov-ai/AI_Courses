# Практичні завдання до Уроку 127: Уточнення та пріоритизація вимог

## Мета заняття
Опанувати застосування фреймворків пріоритизації WSJF, MoSCoW та слісинг великих історій за критеріями INVEST з використанням штучного інтелекту.

---

### Завдання 1. Розрахунок пріоритетів за методологією WSJF (Базовий рівень)

#### Вхідні дані беклогу корпоративного порталу:
1. **Фіча А (Експорт звітів у PDF)**: User Value = 5, Time Criticality = 3, Risk Reduction = 2, Duration = 2.
2. **Фіча Б (Інтеграція з BankID для входу)**: User Value = 8, Time Criticality = 8, Risk Reduction = 5, Duration = 3.
3. **Фіча В (Темна тема оформлення)**: User Value = 3, Time Criticality = 1, Risk Reduction = 1, Duration = 1.
4. **Фіча Г (Автоматичний розрахунок податків)**: User Value = 10, Time Criticality = 9, Risk Reduction = 8, Duration = 5.

#### Завдання:
За допомогою AI:
1. Розрахуйте `Cost of Delay = User Value + Time Criticality + Risk Reduction` для кожної фічі.
2. Розрахуйте підсумковий показник `WSJF = Cost of Delay / Duration`.
3. Сформуйте відсортований список черговості взяття фіч у розробку.

### Завдання 2. Story Slicing монолітного Епіка за критеріями INVEST (Прикладний рівень)

#### Монолітний епік:
«Як менеджер з продажу, я хочу мати повноцінний модуль аналітики угод з фільтрами за 20 параметрами, прогнозуванням продажів на базі ML, експортом у 5 форматів та правами доступу для 10 ролей».

#### Завдання:
За допомогою AI розріжте цей моноліт на 3 незалежні, цінні та компактні User Stories, які задовольняють критеріям INVEST та формують поступовий інкремент функціоналу.

---

### Завдання 3. Побудова матриці розподілу скоупу релізу за MoSCoW (Робота з AI)

#### Завдання:
Складіть за допомогою AI структуровану таблицю скоупу першого релізу (MVP) мобільного банкінгу, чітко розподіливши 12 типових функцій за категоріями: Must Have (не більше 60% зусиль), Should Have, Could Have та Won't Have.

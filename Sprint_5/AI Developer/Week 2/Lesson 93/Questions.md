# Контрольні запитання до Уроку 93: Перевірка коректності коду від AI

1. **Який головний ризик несе сліпе копіювання згенерованого AI коду в продакшен без аудиту?**
   - A) Комп'ютер почне споживати більше електроенергії.
   - B) Ризик впровадження критичних вразливостей безпеки (SQLi, XSS, Path Traversal), галюцинацій та витоку даних. [Правильна]
   - C) Зміна мови операційної системи.
   - D) Немає жодного ризику, AI завжди пише безпечний код.
   *Пояснення: Моделі можуть генерувати вразливі патерни з історичних навчальних даних.*

2. **Який з наведених фрагментів коду містить критичну вразливість SQL Injection?**
   - A) `cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))`
   - B) `cursor.execute(f"SELECT * FROM users WHERE id = {user_input}")` [Правильна]
   - C) `db.query(User).filter(User.id == user_id).first()`
   - D) `SELECT * FROM users`
   *Пояснення: f-рядки та пряма конкатенація в SQL — класична вразливість SQL Injection.*

3. **Який інструмент статичного аналізу безпеки (SAST) спеціалізується на пошуку вразливостей у Python коді?**
   - A) Bandit. [Правильна]
   - B) Adobe Photoshop.
   - C) VLC Media Player.
   - D) Paint.
   *Пояснення: Bandit — провідний інструмент SAST для Python.*

4. **Чому використання алгоритму MD5 для збереження паролів користувачів є небезпечним?**
   - A) MD5 занадто повільний.
   - B) MD5 є криптографічно зламаним, нестійким до колізій та миттєво розшифровується через райдужні таблиці (Rainbow Tables). [Правильна]
   - C) MD5 працює лише на смартфонах.
   - D) MD5 заборонений в інтернет-магазинах.
   *Пояснення: Для паролів обов'язкові повільні стійкі алгоритми Argon2, Bcrypt або Scrypt.*

5. **Що перевіряє лінтер типізації Mypy в режимі `--strict`?**
   - A) Швидкість обертання жорсткого диска.
   - B) Суворе дотримання всіх типів аргументів, значень повернення та відсутність неявних типів `Any`. [Правильна]
   - C) Наявність орфографічних помилок в англійських словах.
   - D) Розмір шрифту.
   *Пояснення: Mypy гарантує строгу типізацію кодової бази.*

6. **Що таке вразливість Path Traversal (Directory Traversal)?**
   - A) Помилка в назві каталогу.
   - B) Можливість зловмисника отримати несанкціонований доступ до файлів операційної системи (наприклад, `../../etc/passwd`) через неперевірений шлях у запиті. [Правильна]
   - C) Швидка ходьба по вулиці.
   - D) Пошкодження кабелю живлення.
   *Пояснення: Небезпечна конкатенація шляхів дозволяє читати системні файли.*

7. **Як захиститися від Path Traversal при збереженні файлів від користувача?**
   - A) Довіряти імені файлу від клієнта.
   - B) Генерувати власний безпечний UUID для назви файлу та валідувати розширення через білий список (Whitelist). [Правильна]
   - C) Зберігати файли на робочому столі.
   - D) Заборонити зберігати файли.
   *Пояснення: Генерація UUID повністю нейтралізує ін'єкції у файлові шляхи.*

8. **Чому модуль `pickle` у Python заборонено використовувати для десеріалізації даних від неперевірених користувачів?**
   - A) `pickle` працює повільно.
   - B) `pickle` дозволяє виконати довільний шкідливий код на сервері (Remote Code Execution / RCE) під час розпакування об'єкта. [Правильна]
   - C) `pickle` змінює колір консолі.
   - D) Це застарілий формат 1980 року.
   *Пояснення: Небезпечна десеріалізація pickle призводить до повного захоплення сервера.*

9. **Який інструмент перевіряє зовнішні сторонні бібліотеки (залежності) на наявність відомих вразливостей (CVE)?**
   - A) `pip-audit` / `npm audit` / `Snyk`. [Правильна]
   - B) Microsoft Excel.
   - C) Google Chrome.
   - D) Блокнот.
   *Пояснення: Сканери залежностей перевіряють версії бібліотек за базами CVE.*

10. **Що таке Mutation Testing (Мутаційне тестування)?**
    - A) Створення комп'ютерних вірусів.
    - B) Метод оцінки якості тестів, коли в код навмисно вносяться дрібні помилки (мутації), щоб перевірити, чи здатні тести їх зловити. [Правильна]
    - C) Зміна розкладки клавіатури.
    - D) Біологічний експеримент.
    *Пояснення: Мутаційне тестування оцінює реальну силу ваших тестів.*

11. **Чому небезпечно вимикати перевірку SSL сертифікатів (`verify=False`) у запитах `requests / httpx`?**
    - A) Запити йтимуть занадто повільно.
    - B) Це відкриває систему до атак Man-in-the-Middle (MitM), дозволяючи перехоплювати та підміняти трафік. [Правильна]
    - C) Сервер вимкнеться.
    - D) Це безпечно.
    *Пояснення: Відключення валідації SSL руйнує шифрування каналу зв'язку.*

12. **Як AI може допомогти у проведенні Security Code Review?**
    - A) AI автоматично підписує сертифікати безпеки.
    - B) Може діяти як рев'юер за чеклістом OWASP Top 10, виявляючи потенційні місця ін'єкцій, витоків пам'яті та незахищених ендпоінтів. [Правильна]

13. **Що означає принцип 'Least Privilege' (Найменших привілеїв) у коді?**
    - A) Надавати кожному модулю чи користувачу лише мінімально необхідні права доступу для виконання його задачі. [Правильна]

14. **Як перевірити згенерований код на наявність витоку чутливих даних у логи?**
    - A) Перевірити, що паролі, токени та номери карток маскуються або виключаються з логування перед викликом `logger.info()`. [Правильна]

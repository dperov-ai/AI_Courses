# Контрольні запитання до Уроку 97: Decision Tables та State Transition

1. **Для яких систем техніка Decision Tables (Таблиці рішень) є найбільш ефективною?**
   - A) Для простих статичних сайтів з одним текстом.
   - B) Для складних бізнес-процесів із багатьма комбінаціями взаємопов'язаних умов (наприклад, правила знижок, скоринг кредиту, тарифікація). [Правильна]
   - C) Тільки для перевірки шрифтів.
   - D) Для вимірювання температури процесора.
   *Пояснення: Таблиці рішень систематизують складну комбінаторну логіку.*

2. **Скільки теоретично можливих комбінацій (правил) має таблиця рішень з 3 незалежними булевими умовами (True/False)?**
   - A) 3
   - B) $2^3 = 8$ правил. [Правильна]
   - C) 100
   - D) 0
   *Пояснення: Кількість комбінацій $N$ булевих умов розраховується як $2^N$.*

3. **Що означає символ '-' (Don't Care) у спрощеній таблиці прийняття рішень?**
   - A) Помилку в таблиці.
   - B) Значення цієї умови (True або False) не впливає на кінцевий результат дії (Action), що дозволяє об'єднати два правила в одне. [Правильна]
   - C) Заборону запуску тесту.
   - D) Видалення рядка.
   *Пояснення: Don't Care скорочує надлишкові правила без втрати логіки.*

4. **Що тестує техніка State Transition Testing (Тестування переходів станів)?**
   - A) Перехід через державний кордон.
   - B) Здатність системи коректно переходити з одного стану в інший під дією подій, а також блокувати недозволені переходи. [Правильна]
   - C) Швидкість заряджання акумулятора.
   - D) Зміну кольору кнопок.
   *Пояснення: State Transition перевіряє життєвий цикл кінцевих автоматів (State Machines).*

5. **Що таке 'Недозволений перехід' (Invalid State Transition)?**
   - A) Перехід на червоне світло світлофора.
   - B) Спроба виконати дію, яка є логічно забороненою для поточного стану (наприклад, видача товару клієнту зі статусу 'Скасовано'). [Правильна]
   - C) Зависання браузера.
   - D) Перезавантаження комп'ютера.
   *Пояснення: Тестування невалідних переходів захищає систему від пошкодження бізнес-логіки.*

6. **Як AI допомагає проєктувати State Transition тести?**
   - A) AI видаляє всі стани.
   - B) Аналізує ТЗ, генерує граф станів у Mermaid та створює матрицю 0-switch і 1-switch тестових шляхів, включно з негативними переходами. [Правильна]
   - C) AI вимикає базу даних.
   - D) AI не знає про стани.
   *Пояснення: ШІ візуалізує граф та генерує матрицю переходів.*

7. **Що таке покриття 0-switch (0-switch coverage) у тестуванні станів?**
   - A) Відсутність перемикачів.
   - B) Покриття кожного окремого дозволеного переходу між двома станами (стан A -> стан B) хоча б один раз. [Правильна]
   - C) Покриття 100 станів одночасно.
   - D) Вимкнення живлення.
   *Пояснення: 0-switch перевіряє всі поодинокі стрілки графу станів.*

8. **Що таке 1-switch coverage?**
   - A) Тестування послідовності з двох послідовних переходів (стан A -> стан B -> стан C). [Правильна]
   - B) Робота з одним користувачем.
   - C) Один клік мишкою.
   - D) Тестування протягом 1 секунди.
   *Пояснення: 1-switch перевіряє парні ланцюжки переходів.*

9. **Які 4 елементи складають модель переходу станів?**
   - A) Початок, середина, кінець, пауза.
   - B) Початковий стан (Current State) -> Подія (Event / Trigger) -> Дія (Action) -> Цільовий стан (Next State). [Правильна]
   - C) Користувач, пароль, логін, пошта.
   - D) Стіл, стілець, комп'ютер, монітор.
   *Пояснення: State + Event + Action + Next State — формула переходу.*

10. **Чому таблиця прийняття рішень є незамінною для тестування банківського скорингу?**
    - A) Скоринг залежить від комбінацій: рівень доходу, кредитна історія, вік, наявність застави, які разом визначають схвалення або відмову. [Правильна]
    - B) Банки не використовують програми.
    - C) Щоб зекономити папір.
    - D) Таблиці рішень заборонені в банках.
    *Пояснення: Комбінаторні правила скорингу ідеально лягають у Decision Tables.*

11. **Як сформулювати запит до AI для генерації Decision Table за складними правилами знижок?**
    - A) «Порахуй знижки в магазині.»
    - B) «На основі наданого опису правил знижок (клієнт Pro/Basic, сума >500/<=500, є промокод T/F) склади повну Decision Table у Markdown та оптимізуй її через Don't Care.» [Правильна]
    - C) «Напиши таблицю.»
    - D) «Зроби знижку 100%.»
    *Пояснення: Точний перелік умов та вимога оптимізації дають ідеальну таблицю.*

12. **Що є прикладом стану (State) для сутності 'Банківська картка'?**
    - A) `АКТИВНА`, `ЗАБЛОКОВАНА`, `ТЕРМІН_ДІЇ_ЗАКІНЧИВСЯ`, `ЗАКРИТА`. [Правильна]
    - B) Номер картки `4111 2222...`.
    - C) Ім'я власника.
    - D) Колір пластику.
    *Пояснення: Стан визначає дозволену поведінку сутності в поточний момент.*

13. **Що повинно статися при спробі зняти готівку з картки у стані 'ЗАБЛОКОВАНА'?**
    - A) Гроші повинні видатися без проблем.
    - B) Відхилення операції (Invalid Transition), статус помилки 'Картка заблокована' та фіксація інциденту безпеки. [Правильна]
    - C) Картка розблокується автоматично.
    - D) Збільшиться ліміт.
    *Пояснення: Заблокований стан забороняє будь-які дебетові транзакції.*

14. **Як перевірити повноту таблиці прийняття рішень?**
    - A) Переконатися, що сума всіх правил з урахуванням згорнутих комбінацій точно дорівнює $2^N$, і жодна комбінація не пропущена. [Правильна]
    - B) Порахувати кількість літер у таблиці.
    - C) Зробити шрифт жирним.
    - D) Повноту перевірити неможливо.
    *Пояснення: Математична сума $2^N$ гарантує відсутність пропущених комбінацій.*

15. **Як AI допомагає виявляти суперечливі правила (Ambiguous Rules) у Decision Table?**
    - A) AI видаляє суперечливі правила.
    - B) Знаходить два правила з однаковими вхідними умовами, які призводять до різних дій, і сигналізує про логічну дірку в ТЗ. [Правильна]
    - C) AI вигадує власні правила.
    - D) Суперечностей ніколи не буває.
    *Пояснення: Пошук колізій у таблицях — сильна сторона алгоритмічного аналізу ШІ.*

16. **Що таке стан переходу з таймаутом (Time-driven transition)?**
    - A) Закінчення робочого дня.
    - B) Перехід, що спрацьовує автоматично після спливу певного часу без активних дій користувача (наприклад, `PENDING` -> `EXPIRED` через 15 хвилин). [Правильна]
    - C) Повільний інтернет.
    - D) Зміна пір року.
    *Пояснення: Таймаут — часта подія зміни стану в онлайн-системах.*

17. **Чому візуалізація State Machine у Mermaid полегшує комунікацію з розробниками?**
    - A) Діаграма наочно демонструє всі можливі шляхи та робить неможливим різне трактування життєвого циклу об'єкта. [Правильна]
    - B) Картинки займають менше місця.
    - C) Розробники не вміють читати текст.
    - D) Це вимога компанії Microsoft.
    *Пояснення: Графічні моделі усувають різночитання логіки.*

18. **Що є головним підсумком застосування Decision Tables та State Transition?**
    - A) 100% покриття комбінаторних бізнес-правил та повний контроль за життєвим циклом критичних сутностей системи. [Правильна]
    - B) Відмова від юніт-тестів.
    - C) Збільшення часу тестування в 10 разів.
    - D) Випадкове тестування.
    *Пояснення: Системне комбінаторне покриття — основа надійності складних систем.*

# Практичні завдання до Уроку 97: Decision Tables та State Transition

## Мета практики
Опанувати побудову та оптимізацію Decision Tables, проєктування State Machine діаграм у Mermaid та генерацію тестів життєвого циклу за допомогою AI.

---

### Завдання 1. Побудова Decision Table для системи безкоштовної доставки (Базовий рівень)

#### Правила інтернет-магазину:
1. Якщо сума замовлення >= 1500 грн -> Доставка безкоштовна для всіх.
2. Якщо клієнт має підписку Premium -> Доставка безкоштовна незалежно від суми.
3. Якщо застосовано промокод `FREESHIP` -> Доставка безкоштовна.
4. В інших випадках -> Доставка платна (80 грн).

#### Зразок Decision Table:
| Умова / Правило | R1 | R2 | R3 | R4 |
| :--- | :---: | :---: | :---: | :---: |
| **Сума >= 1500 грн** | **True** | False | False | False |
| **Підписка Premium** | - | **True** | False | False |
| **Промокод FREESHIP** | - | - | **True** | False |
| **ДІЯ: Безкоштовна доставка** | ✅ ТАК | ✅ ТАК | ✅ ТАК | ❌ НІ (80 грн) |

### Завдання 2. Проєктування State Transition діаграми для життєвого циклу тікета підтримки (Прикладний рівень)

#### Опис завдання:
Попросіть AI згенерувати діаграму Mermaid `stateDiagram-v2` для тікета сапорту:
- Стани: `NEW` -> `ASSIGNED` -> `IN_PROGRESS` -> `WAITING_FOR_CLIENT` -> `RESOLVED` -> `CLOSED`.
- Можливість повернення: `WAITING_FOR_CLIENT` -> `IN_PROGRESS` (клієнт відповів).
- Перевідкриття: `RESOLVED` -> `REOPENED` -> `IN_PROGRESS` (проблема повторилася протягом 48 год).
- Скласти 3 негативні тести на недозволені переходи (наприклад: `CLOSED` -> `WAITING_FOR_CLIENT`).

Подайте до AI граф станів платіжного шлюзу та згенеруйте повний набір BDD тест-кейсів для 0-switch покриття.

# Контрольні запитання до Уроку 105: Безпека та перевірка AI-коду

1. **Що таке «фальшиво-позитивний» (False Positive) автотест?**
   - A) Тест, який завжди падає.
   - B) Тест, який повідомляє про успіх (Pass), навіть якщо система містить критичний дефект або дія не відбулася. [Правильна]
   - C) Тест, написаний мовою C++.
   - D) Тест без назви.
   *Пояснення: Фальшиво-позитивні тести створюють оманливе відчуття надійності системи.*

2. **Який ризик створює явище Package Hallucination (галюцинація пакетів) у LLM?**
   - A) Комп'ютер почне транслювати музику.
   - B) Модель пропонує імпортувати вигаданий пакет, ім'я якого зловмисники можуть зареєструвати в PyPI/NPM для виконання шкідливого коду (Supply Chain Attack). [Правильна]
   - C) Всі пакети стають безкоштовними.
   - D) Збільшується швидкість інтернету.
   *Пояснення: Зловмисники створюють шкідливі бібліотеки під галюциновані AI назви.*

3. **Який інструмент у світі Python автоматично сканує код на наявність вразливостей безпеки (наприклад, `verify=False` у requests)?**
   - A) Paint.
   - B) Bandit. [Правильна]
   - C) Excel.
   - D) Notepad.
   *Пояснення: Bandit аналізує AST-дерево Python на типові помилки безпеки.*

4. **Чому використання конструкції `try ... except Exception: pass` у тестах є неприпустимим антипатерном?**
   - A) Вона споживає багато пам'яті.
   - B) Вона «ковтає» будь-які винятки та падіння, роблячи тест сліпим до реальних аварій системи. [Правильна]
   - C) Python забороняє блок try.
   - D) Це сповільнює роботу процесора.
   *Пояснення: Приховування винятків маскує помилки і робить тестування марним.*

5. **Що таке мутаційне тестування (Mutation Testing)?**
   - A) Опромінення процесора радіацією.
   - B) Метод оцінки якості самих автотестів шляхом внесення дрібних змін (мутацій) у вихідний код додатку та перевірки, чи зловлять їх тести. [Правильна]
   - C) Генерація вірусів за допомогою AI.
   - D) Зміна кольору інтерфейсу.
   *Пояснення: Якщо після мутації коду тести залишаються зеленими — тести неефективні.*

6. **Який інструмент допомагає запобігти випадковому потраплянню секретів та паролів у Git репозиторій?**
   - A) Gitleaks / TruffleHog. [Правильна]
   - B) WinRAR.
   - C) Adobe Photoshop.
   - D) VLC Player.
   *Пояснення: Сканери секретів перевіряють коміти на наявність регулярних виразів токенів.*

7. **Як правильно передавати конфіденційні дані (логіни, паролі, токени) в автотести?**
   - A) Хардкодити в коментарях до тесту.
   - B) Використовувати змінні оточення (Environment Variables), `.env` файли (додані в `.gitignore`) або сховища секретів на кшталт HashiCorp Vault / GitHub Secrets. [Правильна]
   - C) Публікувати у відкритому чаті команди.
   - D) Записувати в текстовий файл на робочому столі.
   *Пояснення: Змінні оточення та секрет-менеджери захищають чутливі дані.*

8. **Чому прапорець `verify=False` у HTTP-запитах є небезпечним навіть у тестовому середовищі?**
   - A) Він вимикає валідацію SSL/TLS сертифікатів, роблячи трафік вразливим до атак типу Man-in-the-Middle (MitM). [Правильна]
   - B) Він блокує доступ до мережі.
   - C) Він видаляє сертифікати з операційної системи.
   - D) Він не несе жодної небезпеки.
   *Пояснення: Вимкнення SSL маскує реальні проблеми з безпекою на середовищах.*

9. **Яка техніка дозволяє гарантувати, що новий AI-згенерований тест дійсно ловить помилку?**
   - A) Запустити тест 100 разів поспіль.
   - B) Навмисно спровокувати падіння тесту (наприклад, змінити тестові дані або очікування), переконавшись у його «червоному» стані. [Правильна]
   - C) Перейменувати назву тесту.
   - D) Додати коментар «Перевірено».
   *Пояснення: Негативна валідація підтверджує чутливість тесту до дефектів.*

10. **Що означає атака типу Typosquatting на пакетні менеджери (PyPI/NPM)?**
    - A) Введення неправильного пароля користувачем.
    - B) Реєстрація зловмисником шкідливого пакету зі схожою назвою на популярну бібліотеку (або галюцинацію AI) з розрахунком на помилку введення інженера. [Правильна]
    - C) Швидке друкування на клавіатурі.
    - D) Злом серверів Microsoft.
    *Пояснення: Тайпосквотинг використовує неуважність та AI-галюцинації.*

11. **Чому не рекомендується використовувати функцію `eval()` у допоміжному коді автотестів?**
    - A) Вона виконує довільний рядок як код програми, що створює критичну вразливість віддаленого виконання коду (RCE). [Правильна]
    - B) Вона сповільнює тести на 1%.
    - C) Вона вимагає ліцензію.
    - D) Вона недоступна в Python 3.
    *Пояснення: eval() є одним з найнебезпечніших методів динамічного виконання.*

12. **Яку роль відіграють пре-комміт хуки (pre-commit hooks) у безпеці коду автотестів?**
    - A) Видаляють незбережені файли перед комітом.
    - B) Автоматично запускають лінтери безпеки (Bandit, Flake8, Gitleaks) до того, як код потрапить у локальний чи віддалений Git репозиторій. [Правильна]
    - C) Відправляють повідомлення тімліду про кожен коміт.
    - D) Блокують роботу комп'ютера на 5 хвилин.
    *Пояснення: Pre-commit хуки зупиняють потрапляння вразливого коду на ранньому етапі.*

13. **Як перевірити безпеку зовнішнього Docker-образу, що використовується для запуску автотестів у CI?**
    - A) Подивитися на розмір файлу.
    - B) Просканувати образ інструментами аналізу вразливостей (Trivy, Grype, Docker Scout). [Правильна]
    - C) Перейменувати назву тегу образу.
    - D) Docker-образи завжди безпечні.
    *Пояснення: Сканери контейнерів виявляють CVE у базових пакетах ОС.*

14. **Що слід зробити, якщо AI згенерував код з використанням незнайомої сторонньої бібліотеки?**
    - A) Негайно встановити її через `pip install`.
    - B) Перевірити офіційну сторінку пакету на PyPI, кількість завантажень, активність репозиторію на GitHub та наявність CVE перед встановленням. [Правильна]

15. **Чому в автотестах важливо очищати створені тестові дані (Clean up / Teardown)?**
    - A) Щоб диск не заповнювався.
    - B) Щоб запобігти забрудненню тестового середовища (Test Pollution), яке може викликати падіння наступних тестів або спотворення аналітики. [Правильна]
    - C) Це не має значення.
    - D) Очищення потрібне лише раз на рік.

16. **Як AI може допомогти у проведенні Security Code Review автотестів?**

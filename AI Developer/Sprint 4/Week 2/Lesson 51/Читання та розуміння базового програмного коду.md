# Читання та розуміння базового програмного коду: дебагінг, Code Reading патерни, трасування та взаємодія з AI-помічниками

Статистика сучасної інженерії вражає: **розробники витрачають до 70% свого робочого часу не на написання нового коду, а на читання, розуміння та налагодження існуючого коду**.

В епоху генеративного штучного інтелекту ця пропорція змістилася ще сильніше. AI здатен згенерувати сотні рядків коду за кілька секунд. Але якщо розробник не володіє технікою швидкого та глибокого читання коду (Code Comprehension), не розуміє прихованих зв'язків та побічних ефектів — він перетворюється на безпорадного заручника згенерованих спагеті-структур.

У цьому поглибленому фінальному посібнику першого блоку ми розглянемо:

* когнітивні моделі сприйняття коду: Mental Execution, Chunking та читання «зверху-вниз» vs «знизу-вгору»;
* методику ручного трасування коду (Trace Tables / Dry Run) з олівцем і папером;
* роботу з професійними налагоджувачами (Debuggers): Breakpoints, Step Over, Step Into, Watch Expressions;
* швидке сканування чужого репозиторію: аналіз архітектури, точок входу (`main`, `index`), конфігурацій та тестів;
* передові техніки співпраці з AI для аналізу кодових баз (Explain, Rubber Ducking, Dependency Mapping);
* золотий чек-лист аудиту чужого та згенерованого коду.

## 2. Ручне трасування коду (Dry Run / Таблиця трасування)

Коли ви стикаєтеся зі складним алгоритмом або неочевидним багом, створіть **таблицю станів змінних по кроках**:

```
КОД ДЛЯ АНАЛІЗУ:
def mystery_func(arr):
    x = 0
    for i in range(len(arr)):
        if arr[i] % 2 == 0:
            x += arr[i]
    return x

ТАБЛИЦЯ ТРАСУВАННЯ ДЛЯ arr = [3, 4, 7, 2]:
+──────+───────+──────────+─────────────────+───────+
| Крок | i     | arr[i]   | arr[i] % 2 == 0 | x     |
+──────+───────+──────────+─────────────────+───────+
| 0    | -     | -        | -               | 0     |
| 1    | 0     | 3        | false           | 0     |
| 2    | 1     | 4        | true            | 0+4=4 |
| 3    | 2     | 7        | false           | 4     |
| 4    | 3     | 2        | true            | 4+2=6 |
+──────+───────+──────────+─────────────────+───────+
Висновок: Функція рахує суму парних чисел масиву.
```

## 3. Використання Interactive Debugger проти `print()`

```
+───────────────────────────────────────────────────────────────────────────+
|                     PRINT-ДЕБАГ vs ІНТЕРАКТИВНИЙ ДЕБАГЕР                  |
+────────────────────────────────----+──────────────────────────────────────+
| PRINT-ДЕБАГ (Застарілий підхід)    | ПРОФЕСІЙНИЙ ДЕБАГЕР (VS Code / PyCharm)|
+────────────────────────────────----+──────────────────────────────────────+
| - Засмічує код десятками `print()`.| - Ставить точку зупинки (Breakpoint) |
| - Потребує перезапуску програми    |   в один клік.                       |
|   після кожної нової строчки.      | - Зупиняє час: дозволяє інспектувати |
| - Не дає можливості змінити стан   |   всі змінні у пам'яті наживо.       |
|   змінних на льоту.                | - Дозволяє виконувати вирази в консолі|
|                                    |   без перезапуску процесу.           |
+────────────────────────────────----+──────────────────────────────────────+
```

### Ключові кнопки дебагера:
* **Step Over (F10):** Виконати поточний рядок і перейти до наступного.
* **Step Into (F11):** Зайти всередину функції, яка викликається в цьому рядку.
* **Step Out (Shift+F11):** Виконати залишок поточної функції і повернутися у викликаючий код.
* **Continue (F5):** Продовжити вільне виконання до наступного Breakpoint.

```markdown
# ЕФЕКТИВНИЙ ПРОМПТ ДЛЯ РОЗБОРУ СКЛАДНОГО КОДУ:
Ти — Senior Software Architect. 
Проаналізуй наданий фрагмент коду та надай відповідь за схемою:
1. ВИСОКОРІВНЕВА МЕТА: Що цей код робить одним реченням?
2. DATA FLOW: Як вхідні дані трансформуються на кожному етапі?
3. ПРИХОВАНІ ПАСТКИ ТА РИЗИКИ: Чи є тут витоки пам'яті, блокування потоків або проблеми з масштабуванням ($O(N^2)$)?
4. АЛЬТЕРНАТИВНА ЧИСТА РЕАЛІЗАЦІЯ: Напиши версію з кращою читабельністю та анотаціями типів.
```

## Резюме уроку

1. Читання коду — головна навичка розробника в епоху AI.
2. Починайте знайомство з репозиторієм з **моделей даних, точок входу та тестів**.
3. Для складних циклів використовуйте **ручне трасування (Trace Tables)**.
4. Опануйте **інтерактивний дебагер (Breakpoints, Step Over/Into)** замість примітивного розставлення `print()`.

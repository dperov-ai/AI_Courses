# Колекції та структури даних: масиви, зв'язні списки, хеш-таблиці, дерева, графи та Big-O аналіз

У комп'ютерних науках існує непорушний закон: **правильний вибір структури даних вирішує 90% задач ефективності програми**.

Якщо для збереження 1,000,000 користувачів обрати звичайний несортований список, операція перевірки «Чи існує такий email?» вимагатиме перебору мільйона елементів ($O(N)$) і триватиме секунди. Якщо ж обрати хеш-таблицю (Hash Set / Hash Map), перевірка виконається миттєво за одну операцію ($O(1)$) за кілька наносекунд.

Штучний інтелект уміє писати код, але моделі часто обирають неефективні структури за замовчуванням (наприклад, використовують масиви там, де потрібні черги чи дерева). Без розуміння внутрішньої будови структур даних інженер не зможе оптимізувати продуктивність системи.

У цьому поглибленому посібнику ми розглянемо:

* поняття складності алгоритмів: нотація Big-O (Time & Space Complexity);
* лінійні структури: Динамічні масиви (Arrays/Lists) vs Зв'язні списки (Singly/Doubly Linked Lists);
* структури з обмеженим доступом: Стек (LIFO — Last In, First Out) та Черга (FIFO — First In, First Out);
* хеш-таблиці (Hash Maps / Dictionaries / Sets): хеш-функції, колізії (метод ланцюжків та відкрита адресація) та час доступу $O(1)$;
* ієрархічні структури: Дерева (Binary Search Trees, AVL, Red-Black, B-Trees у базах даних);
* графи (Graphs): матриця суміжності, списки суміжності та алгоритми пошуку (BFS / DFS).

## 1. Нотація Big-O: як вимірювати ефективність

Нотація Big-O описує, як зростає час виконання або споживання пам'яті алгоритму при зростанні розміру вхідних даних ($N$):

```
+───────────────────────────────────────────────────────────────────────────+
|                         СПЕКТР СКЛАДНОСТІ BIG-O                           |
+──────────+─────────────────+──────────────────────────────────────────────+
| Нотація  | Назва           | Приклад операції                             |
+──────────+─────────────────+──────────────────────────────────────────────+
| O(1)     | Константна      | Отримання елемента масиву за індексом,       |
|          | (Ідеально)      | пошук за ключем у хеш-таблиці                |
+──────────+─────────────────+──────────────────────────────────────────────+
| O(log N) | Логарифмічна    | Бінарний пошук у відсортованому масиві,      |
|          | (Дуже швидко)   | пошук у збалансованому двійковому дереві     |
+──────────+─────────────────+──────────────────────────────────────────────+
| O(N)     | Лінійна         | Простий перебір масиву, підрахунок суми      |
|          | (Прийнятно)     |                                              |
+──────────+─────────────────+──────────────────────────────────────────────+
| O(N logN)| Квазілінійна    | Швидке сортування (QuickSort, MergeSort,     |
|          | (Стандарт сорту)| Timsort у Python)                            |
+──────────+─────────────────+──────────────────────────────────────────────+
| O(N^2)   | Квадратична     | Вкладені цикли (BubbleSort, наївне порівняння|
|          | (Повільно)      | двох списків)                                |
+──────────+─────────────────+──────────────────────────────────────────────+
| O(2^N)   | Експоненційна   | Повний перебір комбінацій (Brute-force)      |
|          | (Катастрофа)    |                                              |
+──────────+─────────────────+──────────────────────────────────────────────+
```

## 2. Лінійні структури: Масиви vs Зв'язні списки

```
ДИНАМІЧНИЙ МАСИВ (Array / Python list / std::vector):
Пам'ять: [ Елемент 0 ][ Елемент 1 ][ Елемент 2 ][ Елемент 3 ] -> Неперервний блок у RAM
- Доступ за індексом `arr[i]`: O(1) завдяки формулі `адреса = start + i * sizeof(тип)`.
- Вставка на початок `arr.insert(0, val)`: O(N) (треба зсунути всі елементи вправо!).

ЗВ'ЯЗНИЙ СПИСОК (Linked List):
Пам'ять: [ Val 1 | Next ] ──► [ Val 2 | Next ] ──► [ Val 3 | Next ] ──► NULL
- Доступ за індексом: O(N) (треба пройти по ланцюжку від голови).
- Вставка на початок: O(1) (просто перенаправити покажчик Head!).
```

## 3. Хеш-таблиці (Hash Maps / Dictionaries): магія $O(1)$

Хеш-таблиця перетворює довільний ключ (рядок, об'єкт) на числовий індекс у масиві за допомогою математичної **хеш-функції**:

```
[ Ключ: "user_123" ] ──► [ Хеш-функція: hash("user_123") ] ──► [ Індекс: 4 ]
                                                                      │
                                                                      ▼
                                                       [ Масив бакетів (Buckets) ]
                                                       [0] -> NULL
                                                       [1] -> NULL
                                                       [4] -> { "user_123": { "name": "Олена" } }
```

### Проблема колізій (Collisions):
Коли два різні ключі випадково дають однаковий хеш-індекс, система вирішує це:
* **Методом ланцюжків (Separate Chaining):** У комірці зберігається зв'язний список усіх пар із цим індексом.
* **Відкритою адресацією (Open Addressing):** Система шукає наступну вільну комірку в масиві.

## 4. Дерева та Графи: ієрархії та зв'язки

```
                ДВІЙКОВЕ ДЕРЕВО ПОШУКУ (BST)
                            [ 50 ]
                           /      \
                     [ 30 ]        [ 70 ]
                    /      \      /      \
                [ 20 ]   [ 40 ] [ 60 ]   [ 80 ]
  (Всі менші значення — ліворуч, всі більші — праворуч. Пошук за O(log N)!)
```

### Графи (Graphs):
Графи моделюють довільні мережі: соціальні зв'язки друзів, маршрути на карті, залежності пакетів у проекті.
* **BFS (Breadth-First Search / Пошук у ширину):** Шукає найкоротший шлях (через Чергу).
* **DFS (Depth-First Search / Пошук у глибину):** Досліджує лабіринти та перевіряє циклічні залежності (через Стек / Рекурсію).

---

## Резюме уроку

1. Вибір структури даних визначає часову та просторову складність програми за шкалою **Big-O**.
2. **Динамічні масиви** ідеальні для читання за індексом ($O(1)$); **Зв'язні списки** — для швидкої вставки в початок.
3. **Хеш-таблиці (Dict / Set)** забезпечують блискавичний пошук за $O(1)$ і є головною робочою конячкою швидкого коду.
4. **Дерева та Графи** організують складні ієрархії, пошук найкоротших шляхів та зберігання індексів у базах даних.

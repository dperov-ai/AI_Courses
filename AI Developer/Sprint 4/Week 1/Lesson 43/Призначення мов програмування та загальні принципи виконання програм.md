# Призначення мов програмування та загальні принципи виконання програм: від кремнію до нейромережевого кодогенератора

Програмування — це не просто написання тексту англомовними ключовими словами на кшталт `if`, `for` чи `return`. Це фундаментальний процес **формалізації абстрактних людських намірів у суворі математичні інструкції**, які здатний безпомилково виконати фізичний процесор.

Для AI-розробника розуміння того, як саме людський задум транслюється через синтаксис мови програмування у бінарний код процесора, є критичною суперсилою. Мовні моделі (LLM) генерують код зі швидкістю тисяч символів на хвилину, але вони не «розуміють» фізичного середовища виконання. Якщо інженер не знає різниці між компіляцією та інтерпретацією, між виділенням пам'яті у стеку та купі, між системними викликами ОС та віртуальними машинами — він не зможе верифікувати згенерований штучним інтелектом код і виправити критичні архітектурні дефекти.

У цьому поглибленому посібнику ми розберемо:

* чому комп'ютери розуміють лише нулі та одиниці і як виникла багаторівнева ієрархія абстракцій;
* класифікацію мов програмування: низькорівневі vs високорівневі, декларативні vs імперативні;
* фундаментальні моделі виконання коду: Компіляція (AOT), Інтерпретація, Байт-код та Just-In-Time (JIT) компіляція;
* життєвий цикл програми: від вихідного коду (Source Code) до процесу в оперативній пам'яті (Process Memory Layout);
* як сучасні моделі (Claude 3.5 Sonnet, GPT-4o, DeepSeek-Coder) взаємодіють із синтаксичними деревами (AST);
* типові пастки при генерації коду різними мовами (C++, Python, JavaScript, Rust, Go).

## 1. Архітектурна ієрархія: від транзистора до коду

Сучасний комп'ютер — це обчислювач, побудований на мільярдах мікроскопічних напівпровідникових перемикачів (транзисторів). Транзистор може перебувати лише у двох фізичних станах: відкритий (є електрична напруга, логічна `1`) або закритий (немає напруги, логічний `0`).

```
+───────────────────────────────────────────────────────────────────────────+
|                      ІЄРАРХІЯ ОБЧИСЛЮВАЛЬНИХ АБСТРАКЦІЙ                   |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 5: AI-ПРОМПТ / СПЕЦИФІКАЦІЯ                                        |
| "Створи REST API для авторизації користувачів з JWT токенами"             |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 4: ВИСОКОРІВНЕВІ МОВИ (High-Level Languages: Python, JS, Go, Rust) |
| `def authenticate(user, password): return jwt.encode(...)`                |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 3: АСЕМБЛЕР (Assembly Language)                                    |
| `mov eax, [ebp-4]` / `push eax` / `call _jwt_encode`                      |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 2: МАШИННИЙ КОД (Machine Code / OpCodes)                           |
| `10111000 00000100 00000000 00000000 11101000 ...`                       |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 1: АРХІТЕКТУРА МІКРОСХЕМИ ТА ТРАНЗИСТОРИ (Silicon Hardware)        |
| Фізичні логичні вентилі AND, OR, NOT, тригери пам'яті SRAM/DRAM           |
+───────────────────────────────────────────────────────────────────────────+
```

### Чому людина не може писати машинним кодом?
На початку комп'ютерної ери програми вводилися перфокартами або тумблерами у двійковому коді. Це призводило до катастрофічної кількості помилок: один хибний біт ламав усю програму. 

Мови програмування були винайдені як **інструмент керування когнітивною складністю**. Вони дозволяють людині оперувати поняттями предметної області («користувач», «баланс», «відправити лист»), приховуючи від програміста регістри процесора, керування кеш-лініями L1/L2/L3 та таблиці сторінок віртуальної пам'яті.

## 2. Велика класифікація мов програмування

Не існує «найкращої» мови програмування — кожна створювалася під конкретний компроміс між **швидкістю розробки, безпекою пам'яті та продуктивністю виконання**.

```
+─────────────────────────────────────────────────────────────────────────────────────────+
|                                КЛАСИФІКАЦІЯ МОВ ПРОГРАМУВАННЯ                           |
+────────────────────+────────────────────────────+───────────────────────────────────────+
| Категорія          | Представники               | Ключові особливості та призначення   |
+────────────────────+────────────────────────────+───────────────────────────────────────+
| Системні мови      | C, C++, Rust, Zig          | Прямий доступ до пам'яті, відсутність |
| низького рівня     |                            | Garbage Collector (GC), максимальна   |
|                    |                            | швидкість, драйвери, рушії ігор, ОС.  |
+────────────────────+────────────────────────────+───────────────────────────────────────+
| Серверні прикладні | Go, Java, C#, Kotlin       | Висока продуктивність, вбудований GC, |
| мови               |                            | потужні багатопотокові примітиви,     |
|                    |                            | мікросервіси, корпоративний бекенд.   |
+────────────────────+────────────────────────────+───────────────────────────────────────+
| Скриптові динамічні| Python, JavaScript, Ruby,  | Блискавична швидкість прототипування, |
| мови               | PHP                        | динамічна типізація, Data Science,    |
|                    |                            | веб-інтерфейси, автоматизація, AI.    |
+────────────────────+────────────────────────────+───────────────────────────────────────+
| Декларативні мови  | SQL, HTML, CSS, Terraform  | Описують «ЩО отримати», а не «ЯК це   |
| специфікації       |                            | покроково зробити».                   |
+────────────────────+────────────────────────────+───────────────────────────────────────+
```

## 3. Моделі виконання: Компіляція, Інтерпретація та JIT

Як текст програми перетворюється на дію процесора? Існує три головні архітектурні конвеєри:

```
1. ЧИСТА КОМПІЛЯЦІЯ (AOT — Ahead Of Time): C, C++, Rust, Go
   [ Source.cpp ] ──► [ Компілятор (GCC/Clang) ] ──► [ Бінарний файл .exe / ELF ] ──► [ CPU ]
   - Максимальна швидкість виконання.
   - Бінарник прив'язаний до конкретної архітектури (x86-64, ARM64).

2. ЧИСТА ІНТЕРПРЕТАЦІЯ: Базовий Bash, старий JavaScript
   [ Script.sh ] ──► [ Інтерпретатор читає рядок ] ──► [ Миттєво виконує ]
   - Немає кроку попередньої збірки.
   - Низька швидкість: кожен рядок аналізується заново в циклі.

3. ГІБРИДНА БАЙТ-КОД МОДЕЛЬ + JIT: Java (JVM), C# (.NET), Python (CPython), JS (V8)
   [ Code.py/.java ] ──► [ Байт-код (.pyc / .class) ] ──► [ Віртуальна Машина (VM / JIT) ] ──► [ CPU ]
   - Кросплатформність: один і той самий байт-код працює на Windows, Mac, Linux.
   - JIT-компілятор (Just-In-Time) гарячі ділянки коду на льоту перетворює в машинний код.
```

## 4. Життєвий цикл виконання програми в ОС

Коли користувач або скрипт запускає програму, операційна система виконує такі кроки:

```
[ Клік / Виклик ./app ]
          │
          ▼
[ 1. LOADER (Завантажувач ОС) ]: Читає заголовки ELF/PE, виділяє віртуальну пам'ять
          │
          ▼
[ 2. PROCESS MEMORY LAYOUT ]:
    ┌─────────────────────────────────────────────────────────┐
    │ TEXT / CODE SEGMENT : Машинні інструкції (тільки читання)│
    ├─────────────────────────────────────────────────────────┤
    │ DATA / BSS SEGMENT  : Глобальні та статичні змінні      │
    ├─────────────────────────────────────────────────────────┤
    │ HEAP (Купа)         : Динамічна пам'ять (`malloc`/`new`)│
    │                       Росте зверху вниз                 │
    ├─────────────────────────────────────────────────────────┤
    │ STACK (Стек)        : Локальні змінні функцій, адреси   │
    │                       повернення. Росте знизу вгору.    │
    └─────────────────────────────────────────────────────────┘
          │
          ▼
[ 3. EXECUTION ]: Регістр процесора IP (Instruction Pointer) починає виконувати інструкції
```

## 5. Як AI взаємодіє з кодом: концепція AST (Abstract Syntax Tree)

Коли ви просите мовну модель: *«Зроби рефакторинг цієї функції»*, AI не сприймає код просто як букви. Модель моделює структуру **Абстрактного Синтаксичного Дерева (AST)**:

```
                       [ FUNCTION DECLARATION: `add` ]
                                      │
                 ┌────────────────────┴────────────────────┐
                 ▼                                         ▼
      [ PARAMETERS: `a`, `b` ]                     [ BLOCK STATEMENT ]
                                                           │
                                                           ▼
                                               [ RETURN: BINARY OP `+` ]
                                                /                     \
                                       [ IDENTIFIER: `a` ]   [ IDENTIFIER: `b` ]
```

### Чому це важливо знати AI-інженеру:
1. **Синтаксичні помилки (Syntax Errors):** Виникають, коли AST не може бути побудоване (наприклад, пропущена дужка або двокрапка). AI легко їх виправляє.
2. **Семантичні помилки (Semantic Errors):** Дерево AST валідне, код компілюється і запускається, але виконує не ту дію (наприклад, замість додавання множить або виходить за межі масиву). Такі баги потребують глибокої інженерної верифікації та написання тестів.

## Резюме уроку

1. Мови програмування — це **система абстракцій**, яка перетворює людську логіку на команди для кремнієвих транзисторів.
2. **Компіляція (AOT)** дає максимальну швидкодію; **Байт-код та віртуальні машини (JVM, V8, CPython)** забезпечують кросплатформність та гнучкість.
3. Кожна запущена програма функціонує в оперативній пам'яті через строго організовані сегменти: **Text, Data, Heap та Stack**.
4. Професійний AI-розробник використовує моделі штучного інтелекту як прискорювач, але завжди верифікує архітектурну доцільність, споживання пам'яті та модель виконання згенерованого коду.

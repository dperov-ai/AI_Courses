# Змінні та типи даних: фундамент представлення інформації в пам'яті, статична vs динамічна типізація та пастки приведення типів

Будь-яка комп'ютерна програма зводиться до простої формули: **Дані + Алгоритми = Результат**. 

Проте процесор не вміє працювати з абстрактними поняттями на кшталт «ім'я користувача», «ціна зі знижкою» чи «список замовлень». На рівні апаратного забезпечення існують лише послідовності байтів в оперативній пам'яті. **Змінна** — це іменована комірка пам'яті, яка дозволяє розробнику зберігати значення та звертатися до нього за зрозумілою назвою, а **Тип даних** визначає, скільки саме байтів займає значення, як ці байти інтерпретуються (як число, символ чи адреса) і які операції над ними дозволені.

Для розробника, який взаємодіє з AI, розуміння системи типів є критичним. Більше 40% усіх багів у згенерованому штучним інтелектом коді пов'язані з неявним приведенням типів (Type Coercion), переповненням чисел, помилками роботи з плаваючою комою (Floating-Point Precision) або спробами викликати метод для значення `null` / `undefined` / `None`.

У цьому поглибленому посібнику ми розберемо:

* фізичну природу змінної: як пам'ять виділяється на рівні бітів та адрес;
* примітивні типи даних: цілі числа (Integer), дійсні числа (Float/Double), символи та рядки (Char/String), булеві значення (Boolean);
* систему типізації: Статична vs Динамічна, Сильна (Strong) vs Слабка (Weak);
* пастки арифметики з плаваючою комою (IEEE 754) та чому `0.1 + 0.2 != 0.3`;
* мутабельність (Mutability) vs Імутабельність (Immutability) та передачу за значенням / за посиланням;
* концепцію Type Hinting (Python) та TypeScript як стандарт сучасної надійної AI-розробки.

## 1. Анатомія змінної в оперативній пам'яті

Коли в коді оголошується змінна, компілятор або середовище виконання резервує певну кількість байтів:

```
ПРОГРАМА:
int age = 25; // 4 байти в пам'яті (32 біти)

ОПЕРАТИВНА ПАМ'ЯТЬ (RAM):
Адреса пам'яті:   [ 0x7FFF5FBFF410 ] [ 0x7FFF5FBFF411 ] [ 0x7FFF5FBFF412 ] [ 0x7FFF5FBFF413 ]
Бінарне значення: [    00011001    ] [    00000000    ] [    00000000    ] [    00000000    ]
                  (25 у шістнадцятковій системі = 0x19, записано в Little-Endian форматі)
```

Змінна має чотири фундаментальні атрибути:
1. **Ім'я (Ідентифікатор):** Людинозрозуміла назва (`age`, `total_price`).
2. **Адреса (Address):** Фізичний або віртуальний номер першого байта в пам'яті.
3. **Тип (Type):** Правило інтерпретації бітів (ціле число, дробове число тощо).
4. **Значення (Value):** Фактичний стан бітів у виділеному діапазоні.

## 2. Матриця систем типізації

Всі мови програмування поділяються за двома незалежними осями:

```
                             СИЛЬНА ТИПІЗАЦІЯ (Strong)
                                        │
                         Java, C#       │      Python, Ruby
                         Rust, Go       │
                                        │
  СТАТИЧНА ─────────────────────────────┼───────────────────────────── ДИНАМІЧНА
  (Типи перевіряються                   │                      (Типи перевіряються
   під час компіляції)                  │                       під час виконання)
                                        │
                         C, C++         │      JavaScript, PHP
                                        │
                             СЛАБКА ТИПІЗАЦІЯ (Weak)
```

### Порівняльний аналіз поведінки:
* **Динамічна + Слабка (JavaScript):**
  ```javascript
  let result = "5" - 2; // = 3 (Рядок магічно став числом)
  let weird = "5" + 2;  // = "52" (Число магічно стало рядком)
  let fail = [] + {};   // = "[object Object]"
  ```
  *Небезпека:* AI часто генерує такий код, який працює на тестах, але падає на продакшні через непередбачувані мутації типів.
* **Динамічна + Сильна (Python):**
  ```python
  result = "5" + 2  # Викине TypeError: can only concatenate str to str, not "int"
  ```
* **Статична + Сильна (TypeScript / Rust / Go):**
  ```typescript
  let price: number = 100;
  price = "free"; // ПОМИЛКА КОМПІЛЯЦІЇ ще до запуску коду!
  ```

## 4. Пастка фінансових розрахунків: Чому `0.1 + 0.2 != 0.3`

Комп'ютер зберігає дробові числа у двійковій системі. Так само як дріб `1/3` не можна точно записати у десятковій системі (`0.333333...`), дріб `0.1` не має скінченного представлення у двійковій системі.

```python
# Запуск у Python/JS:
print(0.1 + 0.2)
# Результат: 0.30000000000000004
print(0.1 + 0.2 == 0.3)
# Результат: False
```

> **Правило AI-інженера:**  
> Ніколи не дозволяйте AI використовувати звичайний `float` для грошей чи точних білінгових розрахунків!  
> Використовуйте тип **`Decimal`** (Python/C#), **`BigDecimal`** (Java) або зберігайте гроші у **цілих копійках/центах (`int64`)**.

## 5. Передача за значенням (Value) vs Передача за посиланням (Reference)

```
ПЕРЕДАЧА ЗА ЗНАЧЕННЯМ (Примітиви: int, float, bool):
a = 10
b = a      # Створюється ПОВНА КОПІЯ значення 10 у новій комірці
b = 20     # 'a' залишається 10!

ПЕРЕДАЧА ЗА ПОСИЛАННЯМ (Складні об'єкти: списки, словники, об'єкти):
list1 = [1, 2, 3]
list2 = list1  # list2 вказує на ТУ САМУ адресу пам'яті, що й list1!
list2.append(4)
print(list1)   # [1, 2, 3, 4] -> list1 теж змінився!
```

## Резюме уроку

1. Змінна — це іменований доступ до області в пам'яті; тип визначає розмір, форму представлення та набір допустимих операцій.
2. Статична строга типізація (**TypeScript, Rust, Go, Type Hints у Python**) запобігає прихованим багам ще до запуску коду.
3. Числа з плаваючою комою мають похибку округлення — фінансові обчислення вимагають **`Decimal` або збереження у центах**.
4. Розуміння мутабельності та посилань виключає побічні ефекти при передачі масивів і структур у функції.

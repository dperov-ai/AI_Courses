# Умовні конструкції: логіка розгалуження, таблиці істинності, Pattern Matching та захисні патерни проектування

Комп'ютер був би не більше ніж простим кишеньковим калькулятором, якби він умів виконувати інструкції лише строго лінійно: рядок 1 -> рядок 2 -> рядок 3.

Справжній інтелект та адаптивність програмного забезпечення народжуються завдяки **умовним конструкціям (Control Flow / Conditional Branching)**. Вони дозволяють програмі аналізувати стан даних, приймати рішення в реальному часі та спрямовувати потік виконання різними гілками: пускати користувача в систему чи показувати помилку, застосовувати знижку чи стягувати повну вартість, відправляти лід у VIP-чергу чи відхиляти як спам.

У цьому поглибленому посібнику ми розглянемо:

* булеву алгебру: логічні оператори (`AND`, `OR`, `NOT`, `XOR`), пріоритет та закони де Моргана;
* ліниві обчислення (Short-Circuit Evaluation) та як вони рятують від падіння програми;
* базові оператори розгалуження: `if-else`, каскадний `if-elif-else` та тернарний оператор;
* оператори вибору: класичний `switch-case` та сучасний повноцінний **Structural Pattern Matching** (Python 3.10+ `match-case`, Rust `match`);
* антипатерн «Arrow Anti-Pattern» (пекло вкладених умов) та рефакторинг за патерном **Guard Clauses (Захисні умови)**;
* обробку крайових станів (Null-checks, безпечна навігація `?.` та оператор нульового злиття `??`).

## 1. Фундамент розгалуження: Булева логіка та закони де Моргана

Будь-яка складна умова в коді зводиться до єдиного результату: `true` (істина) або `false` (хибність).

```
+───────────────────────────────────────────────────────────────────────────+
|                        ТАБЛИЦЯ ЛОГІЧНИХ ОПЕРАТОРІВ                        |
+───────+───────+─────────────+────────────+─────────────+──────────────────+
| A     | B     | A AND B (&&)| A OR B (||)| NOT A (!)   | A XOR B (^)      |
+───────+───────+─────────────+────────────+─────────────+──────────────────+
| true  | true  | true        | true       | false       | false            |
| true  | false | false       | true       | false       | true             |
| false | true  | false       | true       | true        | true             |
| false | false | false       | false      | true        | false            |
+───────+───────+─────────────+────────────+─────────────+──────────────────+
```

### Закони де Моргана (Спрощення складних умов):
AI часто генерує громіздкі заперечення, які складно читати людині. Закони де Моргана дозволяють їх спростити:
* `not (A and B)` еквівалентно `(not A) or (not B)`
* `not (A or B)` еквівалентно `(not A) and (not B)`

## 2. Ліниві обчислення (Short-Circuit Evaluation)

Сучасні компілятори та інтерпретатори обчислюють логічні вирази зліва направо і **зупиняються, як тільки фінальний результат стає однозначно відомим**:

```python
# 1. При операторі AND: якщо перший операнд FALSE -> другий НАВІТЬ НЕ ОБЧИСЛЮЄТЬСЯ
if user is not None and user.is_authenticated():
    # Безпечно! Якщо user == None, виклик user.is_authenticated() не відбудеться,
    # і програма НЕ впаде з помилкою AttributeError!
    pass

# 2. При операторі OR: якщо перший операнд TRUE -> другий НЕ ОБЧИСЛЮЄТЬСЯ
if is_admin or perform_expensive_database_check():
    # Якщо користувач адмін, важкий запит до бази даних не виконуватиметься!
    pass
```

## 3. Structural Pattern Matching: сучасна заміна громіздким IF-ам

У сучасних мовах програмування (Python 3.10+, Rust, Kotlin, Swift) конструкція `match` здатна розбирати складні структури даних за формою та типами:

```python
def handle_api_event(event):
    match event:
        case {"type": "payment", "amount": amount, "status": "success"} if amount > 10000:
            notify_vip_manager(amount)
        case {"type": "payment", "amount": amount, "status": "success":
            process_standard_order(amount)
        case {"type": "payment", "status": "failed", "reason": reason}:
            log_error(f"Платіж не пройшов: {reason}")
        case {"type": "refund", "order_id": order_id}:
            process_refund(order_id)
        case _: # Wildcard (default case)
            raise ValueError(f"Невідомий тип події: {event}")
```

## 4. Боротьба з «Arrow Anti-Pattern» через Guard Clauses

Коли новачок або недосвідчена модель пише код, вона часто створює глибоку піраміду вкладених умов:

```python
# ПОГАНИЙ КОД (Arrow Anti-Pattern / Спагеті-піраміда):
def process_payout(user, amount):
    if user is not None:
        if user.is_verified:
            if amount > 0:
                if user.balance >= amount:
                    user.balance -= amount
                    send_money(user, amount)
                    return True
                else:
                    return False
            else:
                return False
        else:
            return False
    else:
        return False
```

### Рефакторинг за патерном Guard Clauses (Захисні умови):
Ми інвертуємо умови та завершуємо функцію якомога раніше (*Early Exit*):

```python
# ЧИСТИЙ ІДЕАЛЬНИЙ КОД (Guard Clauses):
def process_payout(user, amount):
    if user is None:
        return False
    if not user.is_verified:
        return False
    if amount <= 0:
        return False
    if user.balance < amount:
        return False

    # Основний успішний сценарій (Happy Path) виконується на верхньому рівні:
    user.balance -= amount
    send_money(user, amount)
    return True
```

## Резюме уроку

1. Умовні оператори керують потоком виконання програми на основі **булевої алгебри**.
2. **Short-Circuit Evaluation** оптимізує продуктивність та захищає код від звернення до `null`-посилань.
3. **Structural Pattern Matching (`match-case`)** значно чистіший за каскади `elif` при обробці складних структур.
4. Завжди використовуйте **Guard Clauses та Early Return**, щоб зробити код лінійним, плоским та легко читабельним.

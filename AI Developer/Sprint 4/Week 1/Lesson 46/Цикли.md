# Цикли: алгоритмічна ітерація, складність обчислень, захист від зациклення та сучасні патерни обходу даних

Однією з головних переваг комп'ютера над людиною є його здатність виконувати одну й ту саму послідовність операцій мільярди разів без втоми, втрати концентрації та помилок.

Ця можливість реалізується за допомогою **циклів (Loops / Iteration)**. Цикли лежать в основі абсолютно будь-якої корисної програми: обробка масивів даних, відтворення кадрів у комп'ютерній грі, навчання нейромереж через градієнтний спуск, робота серверного Event Loop або парсинг тисяч веб-сторінок.

Проте цикли є джерелом найнебезпечніших збоїв: нескінченні зациклення, що викликають 100% завантаження CPU, помилки «зсуву на одиницю» (Off-by-one Errors), випадкові мутації колекції під час ітерації та квадратична часова складність $O(N^2)$, яка «вішає» сервер при зростанні бази даних.

У цьому поглибленому посібнику ми розберемо:

* фундаментальні типи циклів: лічильні (`for`), умовні (`while`), цикли з постумовою (`do-while`);
* керування потоком ітерації: `break`, `continue`, `return` та блок `else` у циклах Python;
* протокол ітерації: Ітератори, Генератори (Yield), ліниві послідовності та споживання оперативної пам'яті;
* типові пастки: Off-by-one помилки, зациклення через неточність `float`, модифікація масиву під час обходу;
* оцінку обчислювальної складності: чому вкладені цикли перетворюють швидкий код на катастрофу ($O(N^2)$ vs $O(N)$);
* декларативні альтернативи: List Comprehensions, методи вищого порядку (`map`, `filter`, `reduce`).

## 3. Проблема споживання пам'яті: Звичайні списки vs Генератори (Yield)

Уявіть, що вам потрібно обробити 10,000,000 лог-файлів транзакцій:

```python
# КАТАСТРОФА ПАМ'ЯТІ (Створення списку в RAM):
def get_all_transactions():
    transactions = []
    for i in range(10_000_000):
        transactions.append(fetch_data(i)) # З'їсть 8 ГБ оперативної пам'яті і вб'є процес!
    return transactions

# ІДЕАЛЬНЕ ВИКОРИСТАННЯ ПАМ'ЯТІ (Генератор / Ліниві обчислення):
def get_transactions_stream():
    for i in range(10_000_000):
        yield fetch_data(i) # Пам'ять: всього кілька кілобайт! Значення генеруються по одному.

for tx in get_transactions_stream():
    process(tx)
```

## 4. Пастка Off-by-one та модифікація під час ітерації

### Пастка 1: Видалення елементів під час обходу
```python
# НЕБЕЗПЕЧНИЙ КОД:
numbers = [1, 2, 3, 4, 5, 6]
for num in numbers:
    if num % 2 == 0:
        numbers.remove(num) # Індекси зсуваються! Частина парних чисел буде пропущена!
# Результат: [1, 3, 5] випадково може спрацювати, але для [2, 4, 6] дасть [4]!

# ПРАВИЛЬНЕ РІШЕННЯ (Створення нового списку через List Comprehension):
numbers = [num for num in numbers if num % 2 != 0]
```

### Пастка 2: Квадратична складність вкладених циклів ($O(N^2)$)
```python
# ПОГАНО: Пошук збігів через два вкладені цикли -> O(N * M)
def find_common_users(list_a, list_b):
    common = []
    for user_a in list_a:
        for user_b in list_b: # При 100,000 користувачах це 10,000,000,000 операцій (15 хвилин)!
            if user_a == user_b:
                common.append(user_a)
    return common

# ПРАВИЛЬНО: Використання хеш-сету (Set) -> O(N + M) — мілісекунди!
def find_common_users_fast(list_a, list_b):
    set_b = set(list_b) # O(M)
    return [user for user in list_a if user in set_b] # Пошук у set відбувається за O(1)!
```

## Резюме уроку

1. Цикли забезпечують багаторазове повторення дій над масивами даних або за умовою.
2. Для величезних масивів даних завжди використовуйте **генератори (`yield`) та потокову обробку** замість завантаження всього в пам'ять.
3. Ніколи не змінюйте довжину колекції всередині прямого циклу `for` по цій самій колекції.
4. Оптимізуйте вкладені цикли через **структури даних швидкого пошуку (`Set`, `Dict` / Hash Table)**, знижуючи складність з $O(N^2)$ до $O(N)$.

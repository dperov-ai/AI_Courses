# Призначення мов програмування та загальні принципи виконання програм: від кремнію до нейромережевого кодогенератора

Програмування — це не просто написання тексту англомовними ключовими словами на кшталт `if`, `for` чи `return`. Це фундаментальний процес **формалізації абстрактних людських намірів у суворі математичні інструкції**, які здатний безпомилково виконати фізичний процесор.

Для AI-розробника розуміння того, як саме людський задум транслюється через синтаксис мови програмування у бінарний код процесора, є критичною суперсилою. Мовні моделі (LLM) генерують код зі швидкістю тисяч символів на хвилину, але вони не «розуміють» фізичного середовища виконання. Якщо інженер не знає різниці між компіляцією та інтерпретацією, між виділенням пам'яті у стеку та купі, між системними викликами ОС та віртуальними машинами — він не зможе верифікувати згенерований штучним інтелектом код і виправити критичні архітектурні дефекти.

У цьому фундаментальному посібнику ми детально розберемо:
1. Фізичну та логічну природу обчислень: від кремнієвих транзисторів і логічних вентилів до багаторівневої ієрархії абстракцій.
2. Класифікацію та парадигми мов програмування: низькорівневі проти високорівневих, імперативні проти декларативних, функціональні та об'єктні.
3. Моделі трансляції та виконання: Компіляція Ahead-Of-Time (AOT), чиста інтерпретація, байт-код та Just-In-Time (JIT) компіляція.
4. Анатомію процесу в операційній системі: внутрішній устрій віртуальної пам'яті (Text, Data, BSS, Heap, Stack).
5. Механіку роботи компіляторів та AI: лексичний аналіз, парсинг, побудова абстрактного синтаксичного дерева (AST) та генерація байт-коду.
6. Практичний порівняльний аналіз мов (C++, Rust, Go, Python, JavaScript) з точки зору швидкодії, безпеки пам'яті та кодогенерації в AI.

## 1. Фізична та логічна природа обчислень: як кремній рахує

Будь-який сучасний комп'ютерний процесор (CPU) — це мікросхема, що містить від кількох сотень мільйонів до десятків мільярдів напівпровідникових транзисторів (наприклад, у чипах Apple M-серії або серверних процесорах AMD EPYC їх кількість перевищує 50–90 мільярдів).

### Від фізики до логіки:
* **Транзистор як перемикач:** Транзистор MOSFET працює як керований електричний ключ. Якщо на затвор подається порогова напруга (зазвичай 0.7–1.2 В), через канал протікає струм — це фізичний стан, який ми позначаємо логічною одиницею (`1`). Якщо напруги немає — струм не тече, що відповідає логічному нулю (`0`).
* **Логічні вентилі (Logic Gates):** Поєднуючи від 2 до 6 транзисторів, інженери створюють базові булеві операції: `AND`, `OR`, `NOT`, `NAND`, `NOR`, `XOR`.
* **Арифметико-логічний пристрій (ALU):** Об'єднуючи вентилі у схеми (наприклад, напівсуматори та повні суматори), процесор отримує здатність додавати двійкові числа, зсувати біти, множити та порівнювати значення.
* **Регістри та тактовий генератор:** Процесор не може працювати хаотично. Тактовий генератор генерує мільярди імпульсів на секунду (тактова частота, наприклад 4.0 ГГц = 4 мільярди тактів на секунду). На кожен такт процесор завантажує інструкцію з оперативної пам'яті в регістри, декодує її, виконує в ALU і записує результат назад.

```
+───────────────────────────────────────────────────────────────────────────+
|                      ІЄРАРХІЯ ОБЧИСЛЮВАЛЬНИХ АБСТРАКЦІЙ                   |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 5: AI-ПРОМПТ / СПЕЦИФІКАЦІЯ                                        |
| "Створи REST API для авторизації користувачів з JWT токенами"             |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 4: ВИСОКОРІВНЕВІ МОВИ (High-Level Languages: Python, JS, Go, Rust) |
| `def authenticate(user, password): return jwt.encode(...)`                |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 3: АСЕМБЛЕР (Assembly Language: x86-64, ARM64)                     |
| `mov eax, [ebp-4]` / `push eax` / `call _jwt_encode`                      |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 2: МАШИННИЙ КОД (Machine Code / OpCodes)                           |
| `10111000 00000100 00000000 00000000 11101000 01001100 ...`              |
+───────────────────────────────────────────────────────────────────────────+
| РІВЕНЬ 1: АРХІТЕКТУРА МІКРОСХЕМИ ТА ТРАНЗИСТОРИ (Silicon Hardware)        |
| Фізичні логічні вентилі, тактовий кварцовий резонатор, шини живлення      |
+───────────────────────────────────────────────────────────────────────────+
```

## 2. Велика класифікація мов програмування

Сьогодні у світі налічується понад 700 мов програмування, але в промисловій розробці активно використовується близько 20–25. Вони класифікуються за рівнем абстракції та парадигмами.

### 2.1. За рівнем абстракції від заліза
1. **Низькорівневі мови (Low-level):**
   * *Асемблер:* прямий людиночитаний запис машинних інструкцій процесора. Повна прив'язка до архітектури (x86_64, ARM, RISC-V).
   * *C, C++:* мови системного рівня, де розробник самостійно керує виділенням та звільненням кожного байта пам'яті (`malloc`/`free`, `new`/`delete`), працює з прямими покажчиками на адреси в RAM та керує потоками процесора.
2. **Мови проміжного та високого рівня з керованою пам'яттю (Managed Languages):**
   * *Go, Java, C#, Kotlin:* код компілюється в машинний код або байт-код, але пам'яттю керує автоматичний **збирач сміття (Garbage Collector)**. Розробник звільнений від ручного очищення пам'яті, що усуває цілий клас фатальних багів (Use-After-Free, Double Free, Memory Leaks).
3. **Високорівневі динамічні та скриптові мови:**
   * *Python, JavaScript, TypeScript, Ruby, PHP:* максимальна швидкість написання коду, динамічна типізація, потужні вбудовані структури даних (списки, хеш-таблиці), автоматичне керування ресурсами.

### 2.2. За парадигмами програмування
* **Імперативне програмування:** фокус на покроковому алгоритмі («Спочатку візьми масив, створи лічильник, у циклі збільш кожне число на 2 і збережи»).
* **Об'єктно-орієнтоване програмування (ООП):** організація системи навколо взаємодіючих сутностей (об'єктів), які поєднують стан (дані) та поведінку (методи).
* **Функціональне програмування (FP):** програма як математична композиція чистих функцій без мутацій глобального стану (Haskell, Elixir, Clojure, сучасні фічі в JS/Python/Rust).
* **Декларативне програмування:** опис бажаного фінального результату, а не способу його досягнення (SQL: `SELECT name FROM users WHERE age > 18;`, HTML, CSS, Terraform).

## 3. Моделі трансляції та виконання коду

Як звичайний текстовий файл із розширенням `.py`, `.cpp` чи `.js` перетворюється на виконання інструкцій у процесорі? Існує три головні архітектурні моделі:

```
+─────────────────────────────────────────────────────────────────────────────────────────+
|                                ТРИ МОДЕЛІ ВИКОНАННЯ КОДУ                                |
+────────────────────────────────----+────────────────────────────────────────────────────+
| 1. ЧИСТА КОМПІЛЯЦІЯ (AOT)          | C, C++, Rust, Go, Zig                              |
|    Ahead-Of-Time                   | Вихідний код перетворюється на готовий бінарний    |
|                                    | файл (.exe / ELF), оптимізований під конкретний CPU|
+────────────────────────────────----+────────────────────────────────────────────────────+
| 2. ЧИСТА ІНТЕРПРЕТАЦІЯ             | Класичний Shell/Bash, старі скриптові рушії        |
|                                    | Інтерпретатор читає код рядок за рядком і відразу  |
|                                    | виконує. Найповільніша модель.                     |
+────────────────────────────────----+────────────────────────────────────────────────────+
| 3. ГІБРИДНА МОДЕЛЬ БАЙТ-КОДУ ТА JIT| Python (CPython), Java (JVM), C# (.NET), JS (V8)   |
|    Just-In-Time Compilation        | Вихідний код транслюється в компактний платформо-  |
|                                    | незалежний байт-код, який виконує Віртуальна Машина|
+────────────────────────────────----+────────────────────────────────────────────────────+
```

### Детальний розбір роботи JIT-компілятора (Just-In-Time):
У сучасних рушіях, таких як Google V8 (Node.js/Chrome) або Java HotSpot JVM:
1. Спочатку код швидко транслюється у байт-код і починає виконуватися інтерпретатором без тривалої паузи на збірку.
2. Спеціальний модуль-профайлер (Profiler) у рантаймі відстежує «гарячі ділянки» коду — функції та цикли, які викликаються найчастіше.
3. JIT-компілятор на льоту бере ці гарячі функції, оптимізує їх з урахуванням реальних типів даних, що проходять через них, і транслює прямо в машинний код конкретного процесора.
4. Якщо типи раптово змінюються (деоптимізація), рушій плавно повертається до байт-коду.

## 4. Анатомія процесу в операційній системі: пам'ять та потоки

Коли ви запускаєте програму, операційна система створює **Процес (Process)** — ізольований контейнер з власним віртуальним адресним простором (Virtual Address Space).

```
+───────────────────────────────────────────────────────────────────────────+
|                     ВНУТРІШНЯ СТРУКТУРА ПАМ'ЯТІ ПРОЦЕСУ                   |
+───────────────────────────────────────────────────────────────────────────+
| 0xFFFFFFFFFFFFFFFF (Верхні адреси віртуальної пам'яті)                    |
|                                                                           |
| ┌───────────────────────────────────────────────────────────────────────┐ |
| │ STACK (Стек викликів)                                                 │ |
| │ - Локальні змінні функцій, аргументи, адреси повернення.              │ |
| │ - Фіксований розмір (зазвичай 1-8 МБ).                                │ |
| │ - Зростає ЗВЕРХУ ВНИЗ. Блискавична швидкість (зсув покажчика RSP).    │ |
| └──────────────────────────────────┬────────────────────────────────────┘ |
|                                    ▼                                      |
|                                                                           |
|                                    ▲                                      |
| ┌──────────────────────────────────┴────────────────────────────────────┐ |
| │ HEAP (Динамічна купа)                                                 │ |
| │ - Динамічно виділена пам'ять (`malloc`, об'єкти в Python/Java/JS).    │ |
| │ - Зростає ЗНИЗУ ВГОРУ. Може займати всі доступні гігабайти RAM.       │ |
| │ - Повільніша за стек, вимагає менеджменту або збирача сміття (GC).    │ |
| ├───────────────────────────────────────────────────────────────────────┤ |
| │ BSS SEGMENT & DATA SEGMENT                                            │ |
| │ - Глобальні та статичні змінні (ініціалізовані та неініціалізовані).  │ |
| ├───────────────────────────────────────────────────────────────────────┤ |
| │ TEXT / CODE SEGMENT                                                   │ |
| │ - Скомпільовані машинний інструкції програми (Тільки для читання!).   │ |
| └───────────────────────────────────────────────────────────────────────┘ |
|                                                                           |
| 0x0000000000000000 (Нижні адреси віртуальної пам'яті)                     |
+───────────────────────────────────────────────────────────────────────────+
```

### Різниця між Стеком (Stack) та Купою (Heap):
* **Стек:** працює за принципом LIFO (Last In, First Out). Виділення пам'яті відбувається миттєво — процесор просто змінює значення у спеціальному регістрі покажчика стека. Коли функція завершує роботу, вся її локальна пам'ять автоматично знищується за 1 такт. Спроба виділити в стеку занадто великий масив або нескінченна рекурсія призводить до аварійного збою **Stack Overflow**.
* **Купа:** це великий неструктурований простір оперативної пам'яті. Виділення пам'яті в купі вимагає системного виклику до ОС для пошуку вільного фрагмента потрібного розміру. Якщо об'єкт у купі більше не потрібен, але програма забула його видалити — виникає **витік пам'яті (Memory Leak)**.

## 5. Як компілятори та AI аналізують код: Концепція AST

Будь-який компілятор або сучасна модель генерації коду (Claude, GPT, DeepSeek) аналізує вихідний текст програми через 4 послідовні фази:

1. **Лексичний аналіз (Lexing / Tokenization):** потік символів розбивається на атомарні токени (ключові слова `def`, `if`, оператори `+`, `=`, ідентифікатори `user_id`, літерали `42`).
2. **Синтаксичний аналіз (Parsing):** перевірка граматики мови та побудова **Абстрактного Синтаксичного Дерева (Abstract Syntax Tree / AST)**.
3. **Семантичний аналіз (Semantic Analysis):** перевірка відповідності типів даних, видимості змінних у поточному Scope, відповідності кількості параметрів у функціях.
4. **Генерація коду (Code Generation & Optimization):** трансформація AST в оптимізований машинний код або байт-код.

```
                  ПРИКЛАД АБСТРАКТНОГО СИНТАКСИЧНОГО ДЕРЕВА (AST)
                            Для виразу: `total = price * (1 + tax)`
                            
                                  [ ASSIGNMENT (=) ]
                                    /            \
                          [ IDENTIFIER: total ]  [ BINARY OP (*) ]
                                                 /             \
                                     [ IDENTIFIER: price ]   [ BINARY OP (+) ]
                                                             /             \
                                                     [ LITERAL: 1 ]   [ IDENTIFIER: tax ]
```

## Резюме уроку

1. Програмування — це **мистецтво побудови абстракцій**, які перетворюють людську логіку на перемикання мільярдів кремнієвих транзисторів.
2. Компіляція **AOT (C++, Rust, Go)** забезпечує максимальну продуктивність; віртуальні машини та **JIT-компілятори (JVM, V8)** дають кросплатформність та гнучкість.
3. Кожна програма працює у віртуальній пам'яті через строго ізольовані області: **Стек (швидкий, локальний) та Купу (динамічна, велика)**.
4. AI оперує синтаксисом через **дерева AST**, тому розуміння синтаксису, типів та семантики дозволяє інженеру безпомилково знаходити та виправляти згенеровані дефекти.

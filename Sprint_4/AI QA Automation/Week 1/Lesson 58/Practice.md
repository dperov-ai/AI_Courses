# Практичні завдання до Уроку 58: Manual testing та automated testing

## Мета практики
Навчитися чітко розмежовувати сфери застосування ручного та автоматизованого тестування, ідентифікувати сильні та слабкі сторони кожного підходу, а також проєктувати комбіновані стратегії тестування (Hybrid Testing Approach).

---

### Завдання 1. Матриця порівняння та класифікації задач тестування (Базовий рівень)

#### Опис завдання:
Для списку з 6 практичних задач тестування визначте оптимальний підхід (`Manual`, `Automated` або `Hybrid`) із коротким обґрунтуванням.

#### Задачі для аналізу:
1. Перевірка коректності відображення колірної палітри, шрифтів та зручності навігації нового лендингу.
2. Щоденна перевірка 1500 API-ендпоінтів на відповідність JSON-схемі та статус 200 OK.
3. Дослідницьке (Exploratory) тестування нестандартної поведінки користувача при оформленні замовлення.
4. Навантажувальне тестування платіжного шлюзу на стійкість до 5000 одночасних транзакцій на секунду.
5. Одноразова перевірка нової тимчасової промо-акції, що діятиме 2 дні.
6. Регресійний прогін критичного шляху покупки (Checkout Flow) перед щотижневим релізом.

#### Зразок розв'язку:
```text
1. Дизайн та UX лендингу -> MANUAL (людське сприйняття, естетика, нестандартні екрани).
2. 1500 API-ендпоінтів -> AUTOMATED (висока повторюваність, швидкість перевірки схем).
3. Дослідницьке тестування -> MANUAL (потрібна інтуїція, евристики, креативність тестувальника).
4. Навантаження 5000 TPS -> AUTOMATED (фізично неможливо протестувати людиною).
5. Тимчасова промо-акція на 2 дні -> MANUAL (автоматизація не окупиться, одноразова задача).
6. Регресія Checkout Flow -> AUTOMATED (критичний бізнес-функціонал з високою частотою запусків).
```

### Завдання 2. Оцінка парадоксу пестициду (Pesticide Paradox) (Прикладний рівень)

#### Опис завдання:
Проаналізуйте проблему застарівання автотестів: автотести зелені, але реальні користувачі знаходять баги в продакшені. Запропонуйте 3 практичні заходи для подолання цього парадоксу в проєкті.

#### Зразок заходів:
1. **Параметризація та динамічні тестові дані**: заміна фіксованих значень генерацією випадкових валідних даних через бібліотеку `Faker`.
2. **Періодичний аудит та оновлення тестових наборів**: додавання перевірок на основі баг-репортів з продакшену.
3. **Комбінація з Exploratory-сесіями**: регулярне проведення сесій дослідницького тестування навколо автоматизованих зон.

---

### Завдання 3. AI-помічник для декомпозиції тест-кейсу на ручну та автоматизовану частини (Робота з AI)

#### Опис завдання:
Надайте AI детальний опис складного User Story та попросіть розбити перевірки на дві частини: що віддати на автоматизацію, а що залишити для ручного контролю.

#### Промпт для AI:
> «Маємо функціонал завантаження та розпізнавання паспорта користувача (KYC). Розбий тест-дизайн на дві категорії: 1) Що обов'язково автоматизувати (API, статуси, формати файлів, тайм-аути). 2) Що перевірити вручну (візуальне сприйняття помилок, складні нетипові фото, UX-підказки).»

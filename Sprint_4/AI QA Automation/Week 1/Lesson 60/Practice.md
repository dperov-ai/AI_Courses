# Практичні завдання до Уроку 60: Test Pyramid та рівні автоматизованого тестування

## Мета практики
Опанувати концепцію піраміди тестування (Test Pyramid), навчитися розподіляти тестове покриття між рівнями Unit, Integration/API та End-to-End (E2E), а також ідентифікувати антипатерни (Ice Cream Cone / Inverted Pyramid).

---

### Завдання 1. Побудова правильного розподілу тестів для інтернет-магазину (Базовий рівень)

#### Опис завдання:
Для фічі «Застосування промокоду на знижку 20%» спроєктуйте набір перевірок на кожному з трьох рівнів піраміди: Unit, Integration/API та UI E2E.

#### Зразок розподілу тестів:
```text
▲ [UI E2E] (1 тест)
  └─ Користувач додає товар у кошик в браузері, вводить промокод 'SALE20', бачить оновлену ціну і завершує покупку.

▲▲ [Integration / API] (3-4 тести)
  ├─ POST /api/v1/cart/apply-promo з валідним кодом 'SALE20' -> 200 OK, перевірка перерахунку сум у відповіді.
  ├─ POST /api/v1/cart/apply-promo з простроченим кодом -> 400 Bad Request, повідомлення 'Promo expired'.
  └─ POST /api/v1/cart/apply-promo для товару-винятку -> 422 Unprocessable Entity.

▲▲▲ [Unit Tests] (10+ тестів)
  ├─ Тестування чистих функцій класу PromoCalculator:
  ├─ calculate_discount(price=100, percent=20) == 20
  ├─ calculate_discount(price=0, percent=20) == 0
  ├─ calculate_discount(price=100, percent=0) == 0
  ├─ calculate_discount(price=100, percent=100) == 100
  ├─ Обробка від'ємних чисел (ValueError)
  └─ Округлення копійок при дробних значеннях (100.55 * 0.20)
```

### Завдання 2. Аналіз та рефакторинг «Перевернутої піраміди» (Ice Cream Cone) (Прикладний рівень)

#### Опис завдання:
У проєкті є 200 повільних та нестабільних UI E2E тестів у Selenium, які виконуються 4 години, і лише 10 Unit-тестів. Запропонуйте план трансформації тестового набору відповідно до Test Pyramid.

#### Кроки оптимізації:
1. **Зсув вліво (Shift-Left)**: винести 70% перевірок бізнес-правил та валідацій форм на рівень швидких Unit-тестів розробників.
2. **Перехід на API рівень**: перетворити тести комбінацій параметрів (позитивні/негативні вхідні дані, права доступу) на API-тести через Pytest / Requests (прискорення в 50-100 разів).
3. **Очищення UI E2E рівня**: залишити 15-20 ключових наскрізних бізнес-сценаріїв (Smoke / Critical Path), що запускаються в паралельних потоках.

### Завдання 3. AI для декомпозиції UI-тесту на рівні піраміди (Робота з AI)

#### Опис завдання:
Подайте на вхід AI довгий і повільний UI E2E сценарій та попросіть запропонувати альтернативну піраміду перевірок.

#### Промпт для AI:
> «Маємо довгий UI-тест у браузері: реєстрація користувача -> підтвердження пошти -> авторизація -> перехід у налаштування -> зміна пароля. Як декомпозувати цей тест за Пірамідою Тестування, щоб зменшити час виконання та підвищити стабільність у CI/CD? Наведи конкретні приклади перевірок для кожного рівня.»

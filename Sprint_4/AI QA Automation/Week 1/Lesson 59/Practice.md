# Практичні завдання до Уроку 59: Визначення сценаріїв, доцільних для автоматизації

## Мета практики
Опанувати методику відбору та пріоритизації сценаріїв для автоматизації за критеріями повторюваності, бізнес-критичності, стабільності інтерфейсу та технічної реалізованості.

---

### Завдання 1. Пріоритизація сценаріїв за матрицею критеріїв (Базовий рівень)

#### Опис завдання:
Оцініть 4 наведені сценарії за шкалою від 1 до 5 за трьома критеріями:
- **Частота виконання (Frequency)**
- **Бізнес-критичність (Criticality)**
- **Стабільність інтерфейсу/API (Stability)**
Обчисліть підсумковий бал (Пріоритет = Frequency * Criticality * Stability) та відсортуйте чергу автоматизації.

#### Сценарії:
1. **Авторизація користувача (Login via Email/Password)**
2. **Оплата замовлення банківською карткою (Stripe/PayPal)**
3. **Експорт фінансового звіту в PDF (експериментальна функція, часто змінюється дизайн)**
4. **Редагування аватара користувача в профілі**

#### Зразок розрахунку:
| Сценарій | Frequency (1-5) | Criticality (1-5) | Stability (1-5) | Підсумковий Score | Пріоритет |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Оплата замовлення** | 5 | 5 | 5 | **125** | P0 (Негайно) |
| **Авторизація** | 5 | 5 | 5 | **125** | P0 (Негайно) |
| **Редагування аватара** | 2 | 2 | 4 | **16** | P2 (Низький) |
| **Експорт в PDF (нестабільний)** | 2 | 3 | 1 | **6** | P3 (Відкласти до стабілізації) |

### Завдання 2. Аналіз сценарію на придатність до автоматизації (Прикладний рівень)

#### Опис завдання:
Проаналізуйте сценарій тестування CAPTCHA та 3D Secure підтвердження від банку через SMS. Визначте, чому автоматизація такого сценарію «в лоб» через UI є неефективною (Flaky), та запропонуйте архітектурне рішення (Bypass / Mocking / Test Mode).

#### Зразок рішення:
- **Проблема**: CAPTCHA спеціально розроблена для блокування ботів; SMS-коди залежать від оператора зв'язку і роблять тест нестабільним.
- **Рішення для автотестів**:
  1. На тестовому середовищі вимикати CAPTCHA за допомогою спеціального секретного заголовка або тестового ключа (Test API Key).
  2. Для 2FA/SMS використовувати фіксований тестовий OTP-код (наприклад, `000000`) або прямий виклик внутрішнього API для отримання згенерованого коду з бази даних / Redis.

### Завдання 3. AI-генерація скорингової моделі беклогу автоматизації (Робота з AI)

#### Опис завдання:
Попросіть AI згенерувати формулу або шаблон скорингу автоматизації для команди тестувальників.

#### Промпт для AI:
> «Створи скорингову таблицю в форматі Markdown для оцінки доцільності автоматизації тест-кейсів. Включи фактори: частота прогону, час ручного виконання, ймовірність багу, стабільність фічі, складність автоматизації. Наведи приклад розрахунку для 3 тест-кейсів інтернет-магазину.»

# Chain-of-Thought як концепція міркування моделей

Коли людина стикається зі складною аналітичною, математичною або стратегічною задачею, вона рідко видає фінальну відповідь за частку секунди. Зазвичай ми беремо аркуш паперу або відкриваємо нотатки, розбиваємо задачу на простіші частини, прораховуємо проміжні результати і лише після цього робимо висновок.

Якщо змусити людину відповідати миттєво, ймовірність помилки різко зростає.

Те саме відбувається і з великими мовними моделями (LLM). Якщо попросити модель дати пряму відповідь на заплутане логічне чи бізнес-питання без проміжних кроків, вона намагається «вгадати» результат за один прохід — і часто припускається грубих помилок.

Підхід, який змушує AI спочатку послідовно розписати логіку своїх роздумів, називається **Chain-of-Thought (CoT, Ланцюжок міркувань)**.

У цьому уроці ми розглянемо:

* чому мовні моделі помиляються без проміжних міркувань (механіка передбачення токенів);
* феномен Zero-shot CoT та магічну фразу «Подумаймо крок за кроком»;
* Few-shot Chain-of-Thought: як навчити модель потрібному стилю мислення;
* сучасні моделі з вбудованим мисленням (Reasoning Models: o1, o3, Gemini Thinking, Claude Thinking);
* просунуті техніки: Tree of Thoughts (Дерево думок) та Self-Consistency;
* бізнес-сценарії: розрахунок юніт-економіки, пошук першопричин збоїв, аналіз складних угод.

---

## Чому мовні моделі помиляються: природа авторегресії

Щоб зрозуміти силу Chain-of-Thought, потрібно згадати, як працює LLM.

Мовна модель генерує текст **токен за токеном зліва направо**. Під час формування кожного нового слова модель спирається на весь попередній текст (контекст + уже згенеровані нею слова).

```
Звичайний промпт (без CoT):
[ Складна багатоетапна задача ] ──► [ Спроба одразу видати фінальну відповідь: 42 ] ──► (ПОМИЛКА)

Промпт із Chain-of-Thought:
[ Складна багатоетапна задача ] ──► [ Крок 1: Обчислюємо А ] ──► [ Крок 2: Знаходимо Б ] ──► [ Фінал: 42 ]
                                         ▲                            ▲                          ▲
                                         │ Спирається на Крок 1        │ Спирається на Крок 1 і 2 │ Правильно!
```

Коли ви вимагаєте: *«Дай тільки фінальне число»*, у моделі немає місця для «робочої пам'яті». Вона мусить згенерувати токен правильної відповіді безпосередньо після умови задачі.

Коли ви спонукаєте модель **міркувати вголос**:
1. Кожен розписаний проміжний крок стає частиною контекстного вікна.
2. Під час генерації фінального висновку модель опирається на власні розрахунки та логічні висновки, зроблені кількома рядками вище.
3. Точність розв'язання складних багатокрокових завдань зростає в рази.

## Еволюція CoT: від магічної фрази до моделей-мислителів

### 1. Класичний Zero-shot CoT («Let's think step by step»)
У 2022 році дослідники (Kojima et al.) виявили дивовижний факт: якщо в кінці будь-якого складного логічного запиту просто додати фразу:

> **«Давай подумаємо крок за кроком» (Let's think step by step)**

точність відповідей на бенчмарках математики та логіки зростала з 17% до понад 78% без жодної зміни ваг моделі!

Ця фраза змушує механізм уваги нейромережі генерувати розгорнуту аналітичну траєкторію перед формулюванням підсумку.

---

### 2. Manual / Few-shot Chain-of-Thought
У цьому підході ви показуєте моделі 1–2 зразки того, **як саме ви очікуєте від неї міркувати**.

```markdown
Задача: У нашому інтернет-магазині є 120 одиниць товару на складі. За першу половину дня ми продали 25% залишку. Потім постачальник довіз ще 40 одиниць. У другій половині дня ми продали 1/3 від нової загальної кількості. Скільки одиниць товару залишилося на кінець дня?

Міркуймо покроково:
1. Початкова кількість товару: 120 одиниць.
2. Продажі в першій половині дня: 25% від 120 = 120 * 0.25 = 30 одиниць.
3. Залишок після першої половини дня: 120 - 30 = 90 одиниць.
4. Постачання товару: 90 + 40 = 130 одиниць.
5. Продажі в другій половині дня: 1/3 від 130 = 130 / 3 ≈ 43.33 одиниці. Оскільки товар штучний, округлюємо до 43 одиниць (або залишаємо точний дріб 130/3).
6. Фінальний залишок: 130 - 43 = 87 одиниць (або 86 і 2/3).

Фінальна відповідь: На складі залишилося 87 цілих одиниць товару.
```

### 3. Reasoning Models (OpenAI o1/o3, Gemini Flash Thinking, Claude 3.7 Thinking)
У 2024–2026 роках відбувся якісний стрибок: розробники інтегрували Chain-of-Thought безпосередньо у процес навчання моделей за допомогою методів підкріпленого навчання (Reinforcement Learning).

```
+-------------------------------------------------------------------+
|              СУЧАСНІ МОДЕЛІ З МІРКУВАННЯМ (REASONING)             |
+-------------------------------------------------------------------+
| 1. Користувач задає питання.                                      |
| 2. Модель генерує "прихований ланцюжок міркувань" (Thinking Chain)|
|    - висуває гіпотези;                                            |
|    - перевіряє себе на помилки;                                   |
|    - відкидає тупикові гілки;                                     |
|    - коригує план дій.                                            |
| 3. Видає користувачу бездоганно вивірений фінальний результат.    |
+-------------------------------------------------------------------+
```

У таких моделях вам уже не обов'язково писати «подумай крок за кроком» — вони навчені робити це на рівні внутрішньої архітектури. Проте для стандартних швидких моделей (GPT-4o mini, Claude Sonnet, Gemini Flash) ручний CoT залишається незамінним інструментом.

## Просунуті техніки міркувань

```
      Chain-of-Thought                    Tree of Thoughts (ToT)
     
        [ Проблема ]                           [ Проблема ]
             │                                 ┌────┴────┐
             ▼                                 ▼         ▼
        [ Крок 1 ]                         [Гілка А]  [Гілка Б]
             │                              ┌──┴──┐      │
             ▼                              ▼     ▼      ▼
        [ Крок 2 ]                       [А-1]  [А-2]  [Відкинуто]
             │                              │
             ▼                              ▼
        [ Висновок ]                   [Висновок]
```

### 1. Tree of Thoughts (Дерево думок / ToT)
Замість одного лінійного ланцюжка модель генерує кілька альтернативних шляхів розв'язання на кожному кроці, оцінює життєздатність кожного і обирає найкращий.

**Як це реалізувати у промпті:**
> Розв'яжи цю задачу методом «Дерева думок»:
> 1. Запропонуй 3 принципово різні стратегії виходу на ринок.
> 2. Для кожної стратегії проаналізуй ризики, необхідний бюджет і потенційний ROI.
> 3. Оціни кожну за 10-бальною шкалою і обери одну найоптимальнішу з детальним обґрунтуванням.

### 2. Self-Consistency (Самоузгодженість)
Техніка, за якої модель генерує 3–5 незалежних ланцюжків міркувань паралельно (іноді з підвищеною температурою для варіативності). Відповідь, яка найчастіше повторюється у висновках більшості гілок (Majority Voting), приймається як істинна.

## Практичні бізнес-кейси застосування CoT

### Кейс 1. Фінансовий аналіз та розрахунок Unit-економіки

**Слабкий промпт:**
> Ми залучаємо клієнта за $45 (CAC). Середній чек $120, маржинальність 40%. Клієнт робить у середньому 2.2 покупки за рік і живе з нами 1.5 роки. Чи сходиться наша економіка?

**Сильний CoT-промпт:**
> **Задача:** Проаналізуй юніт-економіку продукту та визнач життєздатність бізнес-моделі.
> 
> **Вхідні дані:**
> * Вартість залучення клієнта (CAC): $45
> * Середній чек (AOV): $120
> * Маржинальність (Gross Margin): 40%
> * Частота покупок: 2.2 рази на рік
> * Життєвий цикл клієнта (Lifetime): 1.5 роки
> 
> **Інструкція (міркуй крок за кроком):**
> 1. Розрахуй загальну кількість замовлень за весь життєвий цикл клієнта.
> 2. Розрахуй сукупний виторг (LTV Revenue).
> 3. Розрахуй чистий прибуток від клієнта за весь період (LTV Gross Profit).
> 4. Обчисли співвідношення LTV до CAC (LTV:CAC ratio).
> 5. На основі отриманого коефіцієнта зроби висновок про здоровий стан бізнесу (норма: LTV:CAC >= 3). Якщо показник нижчий — запропонуй 2 конкретні важелі його покращення.

---

### Кейс 2. Аналіз першопричин збоїв (Root Cause Analysis / 5 Whys)

CoT ідеально підходить для розслідування інцидентів у команді або системі:

```markdown
Ти — провідний DevOps-архітектор.
Проаналізуй інцидент падіння сервера за методом "5 Чому" (5 Whys), міркуючи послідовно від симптому до фундаментальної системної проблеми:

Інцидент: База даних перестала відповідати на запити у піковий час о 19:30.
Контекст: На диску закінчилося вільне місце через гігантський файл access.log.

Крок 1. Чому база впала? -> Закінчилося місце на диску.
Крок 2. Чому закінчилося місце? -> Лог-файл виріс до 80 ГБ за 2 години.
Крок 3. Чому лог-файл виріс так швидко? -> Увімкнувся DEBUG-рівень логування після ранкового релізу.
Крок 4. Чому DEBUG-рівень потрапив у продакшн? -> Розробник забув змінити конфігурацію, а в CI/CD пайплайні не було перевірки змінних оточення.
Крок 5. Чому в CI/CD не було перевірки? -> Відсутній обов'язковий лінтер та чек-лист для конфігурацій релізу.

Сформулюй 3 превентивні заходи, щоб інцидент ніколи не повторився на рівні процесів та інфраструктури.
```

## Коли Chain-of-Thought НЕ потрібен

Хоча CoT — вкрай потужний інструмент, використовувати його скрізь без розбору є помилкою.

```
+-------------------------------------------------------------------+
|                     КОЛИ CoT ПОТРІБЕН І НЕ ПОТРІБЕН               |
+-------------------------------------------------------------------+
| ПОТРІБЕН:                                                         |
| - Багатокрокові математичні та фінансові розрахунки                |
| - Складні логічні та алгоритмічні задачі                           |
| - Порівняльний аналіз стратегій та оцінка ризиків                 |
| - Дебаг та рефакторинг нетривіального коду                         |
+-------------------------------------------------------------------+
| НЕ ПОТРІБЕН (Зайва витрата часу та токенів):                      |
| - Простий переклад тексту                                         |
| - Рерайтинг або скорочення абзацу                                  |
| - Генерація ідей або тем для постів                                |
| - Прямі фактологічні питання ("Столиця Франції?")                  |
+-------------------------------------------------------------------+
```

## Резюме уроку

1. **Chain-of-Thought (CoT)** — це метод спонукання моделі до покрокового розгортання логіки міркувань перед видачею фінальної відповіді.
2. Оскільки LLM генерують текст послідовно, кожен проміжний крок стає контекстною опорою для наступного, що драматично зменшує ймовірність помилок.
3. Проста інструкція **«Давай подумаємо крок за кроком»** (Zero-shot CoT) активує аналітичний режим навіть у базових моделях.
4. Для критично важливих розрахунків та бізнес-рішень найкраще працює **структурований CoT** із зазначенням конкретних кроків розрахунку.
5. Сучасні **Reasoning Models** містять механізми міркувань «під капотом», але розуміння принципів CoT залишається фундаментальною навичкою якісної роботи з AI.

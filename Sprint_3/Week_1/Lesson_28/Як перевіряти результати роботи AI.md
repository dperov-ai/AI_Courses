# Як перевіряти результати роботи AI

Сучасні великі мовні моделі здатні створювати вражаючі тексти, писати складний програмний код, аналізувати фінансові звіти та будувати маркетингові стратегії. Проте головна пастка полягає в їхній **переконливості**: навіть коли модель генерує цілковиту нісенітницю або припускається грубої помилки в розрахунках, вона робить це впевненим, бездоганним академічним тоном.

Феномен сліпої довіри до автоматизованих систем у психології називається **Automation Bias** (упередження на користь автоматизації). Людина бачить гарно структурований текст і підсвідомо вважає його правильним.

Головне правило професійного AI-оператора та спеціаліста:

> **AI — це високоефективний помічник і генератор чернеток, але фінальна відповідальність за верифікацію та достовірність завжди лежить на людині (Human-in-the-Loop).**

У цьому уроці ми детально розберемо:

* чому виникає ефект сліпої довіри та як його подолати;
* 4 рівні верифікації результатів генерації (формат, факти, логіка, безпека);
* покроковий алгоритм критичного аудиту відповідей моделі;
* техніку зворотного тестування (Reverse Checking);
* типові сліпі зони AI в різних сферах (бізнес, право, аналітика даних).

## Чотири рівні верифікації результату

Щоб перевірка була системною і не забирала зайвого часу, розділіть аудит відповіді моделі на 4 послідовні рівні:

```
+-------------------------------------------------------------------+
|                     4 РІВНІ ВЕРИФІКАЦІЇ AI-ВІДПОВІДІ              |
+-------------------------------------------------------------------+
| 1. СТРУКТУРНИЙ ТА ФОРМАТНИЙ АУДИТ                                 |
|    - Чи відповідає вивід заданому формату (JSON, таблиця, список)?|
|    - Чи дотримано обмежень за обсягом і мовою?                    |
|                                                                   |
| 2. ФАКТОЛОГІЧНИЙ АУДИТ (Fact-Checking)                            |
|    - Чи існують згадані компанії, дати, закони, посилання?        |
|    - Чи не вигадані цифри та статистичні показники?               |
|                                                                   |
| 3. ЛОГІЧНИЙ ТА АРИФМЕТИЧНИЙ АУДИТ                                 |
|    - Чи сходяться проміжні розрахунки та фінальні суми?           |
|    - Чи немає причинно-наслідкових суперечностей?                 |
|                                                                   |
| 4. БЕЗПЕКОВИЙ ТА КОНТЕКСТНИЙ АУДИТ                                |
|    - Чи немає ризиків витоку конфіденційних даних?                |
|    - Чи відповідає тон специфіці цільової аудиторії?              |
+-------------------------------------------------------------------+
```

## Рівень 1. Формат та структура: автоматичні фільтри

Первинна перевірка — це відповідність формальним вимогам вашого початкового промпту:

1. **Цілісність синтаксису:** Якщо ви просили JSON — чи валідний він? Чи закриті всі дужки `{}`, чи немає коментарів або зайвих лапок?
2. **Повнота структури:** Якщо ви просили 5 пунктів або 3 обов'язкові колонки в таблиці — переконайтеся, що модель не «забула» останній пункт через ліміт токенів.
3. **Дотримання негативних обмежень:** Якщо ви вказували *«Не використовувати емодзі та вступні слова»* — чи дійсно модель дотрималася цієї заборони?

---

## Рівень 2. Фактологічний аудит: відловлювання галюцинацій

Фактологічні помилки — найнебезпечніші, тому що модель подає їх максимально авторитетно.

### Головні зони ризику для фактчекінгу:
* **Імена, посади та біографії:** Модель може приписати реальній людині чужу книгу або неіснуючу посаду.
* **Законодавство та норми права:** Моделі часто цитують статті законів, яких ніколи не існувало, або плутають редакції кодексів різних років.
* **Посилання та URL-адреси:** Модель знає структуру URL (наприклад, `https://site.com/articles/slug`), але не має гарантії, що конкретна сторінка існує. Вона статистично «генерує схожий URL», який веде на помилку 404.
* **Цитати:** Прямі цитати відомих людей часто є парафразом або взагалі вигадкою.

> **Правило:**  
> Кожне число, власну назву, посилання чи юридичну статтю необхідно перевіряти в незалежному авторитетному першоджерелі (офіційний реєстр, документація, пошуковик).

---

## Рівень 3. Логіка та арифметика: робота над обчисленнями

Мовні моделі не мають вбудованого математичного калькулятора (якщо не використовують сторонні інструменти / Python Code Interpreter). Вони генерують цифри на основі ймовірностей наступного токена.

### Як перевіряти обчислення:
1. **Ручний або скриптовий перерахунок:** Ніколи не довіряйте складним математичним розрахункам (відсотки, середні чеки, конверсії, кредитні ставки), якщо вони не були виконані через виконання коду (наприклад, Advanced Data Analysis / Code Interpreter).
2. **Перевірка суми компонентів:** Якщо модель наводить структуру витрат у 5 пунктах і пише фінальну суму — додайте ці 5 пунктів на звичайному калькуляторі. Дуже часто сума пунктів відрізняється від підсумку.
3. **Логічні суперечності:** Шукайте випадки, коли у вступі модель стверджує одне, а у висновку — протилежне (наприклад: *«Рентабельність проекту зросла на 12%... Отже, через падіння маржинальності рекомендується закрити напрямок»*).

## Техніка зворотного тестування (Reverse Verification)

Один із найефективніших методів швидкої перевірки — змусити іншу (або ту саму) модель виступити незалежним ревізором.

### Промпт зворотного аудиту:
```markdown
Ти — незалежний аудитор якості та фактчекер.
Уважно прочитай наданий текст відповіді та вихідний документ.

Твоя задача — знайти:
1. Будь-які невідповідності між вихідними даними та фінальним текстом.
2. Непідтверджені припущення або вигадані деталі.
3. Арифметичні помилки в розрахунках.
4. Логічні суперечності.

Оформи звіт у вигляді таблиці:
| Проблемний фрагмент | У чому полягає помилка | Ступінь критичності (Низький/Середній/Критичний) | Як виправити |
```

## Чек-лист перевірки роботи AI перед публікацією / відправкою

- [ ] **Чи дотримано всі умови початкового запиту?** (Формат, стиль, мова, довжина).
- [ ] **Чи перевірені всі цифри, дати, формули та суми?**
- [ ] **Чи відкриваються всі надані гіперпосилання?**
- [ ] **Чи відповідають згадані закони та регламенти діючому законодавству?**
- [ ] **Чи немає у тексті внутрішніх логічних суперечностей?**
- [ ] **Чи не просочилися у відповідь конфіденційні дані або внутрішні системні промпти?**

---

## Резюме уроку

1. **Automation Bias** змушує людей сліпо довіряти авторитетно звучним відповідям AI, що створює високі бізнес-ризики.
2. Верифікація має проходити 4 системні рівні: **Формат -> Факти -> Логіка та розрахунки -> Безпека**.
3. Особливу увагу слід звертати на математичні обчислення, дати, власні назви, закони та URL-посилання.
4. Техніка **зворотного аудиту** (використання моделі як суворого рецензента) допомагає швидко виявити приховані вади тексту.
5. Принцип **Human-in-the-Loop** є обов'язковим стандартом для будь-яких відповідальних завдань.

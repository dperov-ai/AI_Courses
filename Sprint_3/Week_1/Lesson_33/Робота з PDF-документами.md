# Робота з PDF-документами: вилучення знань, аналіз та RAG

Формат **PDF (Portable Document Format)** є світовим стандартом для електронного документообігу, звітів, договорів, наукових публікацій та презентацій. Проте для систем штучного інтелекту PDF історично є одним із найскладніших форматів для обробки.

Головна причина: PDF створювався не для того, щоб комп'ютери легко читали текст, а для того, щоб документ виглядав **абсолютно однаково під час друку на будь-якому принтері**. Усередині PDF немає понять «абзац», «заголовок» чи «таблиця» — там є лише набір літер і фігур, розміщених за точними координатами на віртуальній сторінці.

У цьому уроці ми розберемо:

* чому мовні моделі та парсери «ламаються» на складних PDF;
* різницю між текстовими (цифровими) та сканованими (растровими) PDF;
* проблему багатоколонкових текстів, колонтитулів та складних таблиць;
* як сучасні мультимодальні моделі (Vision) читають PDF очима людини;
* практичні алгоритми аналізу багатосторінкових звітів, договорів та специфікацій.

## Анатомія PDF: чому виникають проблеми з парсингом

```
+-------------------------------------------------------------------+
|                     ТИПОВІ ПАСТКИ ПАРСИНГУ PDF                    |
+-------------------------------------------------------------------+
| 1. БАГАТОКОЛОНКОВИЙ ТЕКСТ (Злиття рядків зліва направо)           |
|    - Замість читання спочатку лівої колонки, а потім правої,      |
|      простий парсер читає по горизонталі через обидві колонки     |
|                                                                   |
| 2. РОЗРИВИ СТОРІНОК ТА КОЛОНТИТУЛИ                                |
|    - Номери сторінок та назви розділів вклинюються посеред речень |
|                                                                   |
| 3. ТАБЛИЦІ БЕЗ ЧІТКИХ МЕЖ                                         |
|    - Дані з сусідніх колонок злипаються в один рядок              |
|                                                                   |
| 4. СКАНОВАНИЙ ДОКУМЕНТ (Текстовий шар відсутній)                  |
|    - Документ є просто фотографією паперу -> Потрібен OCR         |
+-------------------------------------------------------------------+
```

## Два типи PDF-документів та методи їх обробки

### 1. Текстовий (Digital-native PDF)
Створений експортом із Word, Google Docs чи LaTeX. Текст можна виділити мишкою і скопіювати.
* **Як обробляти:** Сучасні AI-інтерфейси (ChatGPT, Claude, Gemini) швидко парсять такий текст напряму або через текстовий шар.

### 2. Сканований (Image-based / Scanned PDF)
Скан паперового документа або фотографія сторінки. Текст не виділяється.
* **Як обробляти:** Потрібен модуль **OCR (Optical Character Recognition / Оптичне розпізнавання символів)** або використання мультимодальних Vision-моделей (GPT-4o, Gemini 2.0 Flash, Claude 3.5 Sonnet), які «дивляться» на сторінку як на зображення.

## Стратегії роботи з великими PDF (від 50 до 500+ сторінок)

Якщо завантажити в чат документ на 300 сторінок, навіть моделі з великим вікном контексту можуть пропустити дрібні деталі або вичерпати ліміти генерації.

```
                    [ ВЕЛИКИЙ PDF НА 200 СТОРІНОК ]
                                   │
                                   ▼
+───────────────────────────────────────────────────────────────────+
| СТРАТЕГІЯ 1: MAP-REDUCE (Посторінковий аналіз та синтез)          |
| 1. Модель розбиває документ на розділи.                           |
| 2. Робить коротке саммарі кожного розділу.                        |
| 3. Синтезує фінальний звіт на основі вичавок.                     |
+───────────────────────────────────────────────────────────────────+
                                   │
                                   ▼
+───────────────────────────────────────────────────────────────────+
| СТРАТЕГІЯ 2: VECTOR RAG (Пошук точних фрагментів)                 |
| 1. Документ індексується у векторній базі даних.                  |
| 2. За запитом користувача витягуються тільки 3-5 релевантних      |
|    сторінок (наприклад, "пункт про розірвання договору").         |
| 3. Модель відповідає виключно на основі знайдених цитат.          |
+───────────────────────────────────────────────────────────────────+
```

## Практичні промпти для роботи з PDF

### Промпт для аудиту складного договору:
```markdown
Ти — провідний корпоративний юрист.
Я завантажив PDF-файл договору поставки.

Проаналізуй документ та підготуй висновок за такою структурою:
1. Загальні умови: предмет договору, загальна сума, строки виконання.
2. Зони підвищеного ризику для нашої сторони (Покупець):
   - штрафні санкції та неустойки;
   - умови одностороннього розірвання;
   - форс-мажорні застереження.
3. Невідповідності та двозначні формулювання: вкажи номери пунктів та сторінок, де формулювання допускають подвійне тлумачення.
4. Рекомендації: конкретний текст правок до ризикованих пунктів.
```

## Резюме уроку

1. PDF — це формат візуального представлення, що створює труднощі для вилучення таблиць і колонок.
2. Розрізняйте **текстові PDF** (виділяються мишкою) та **скановані PDF** (потребують Vision/OCR).
3. Для роботи з великими документами (100+ сторінок) використовуйте **мультимодальні моделі з гігантським контекстом (Gemini Pro)** або **RAG-системи**.
4. Завжди вимагайте від моделі посилатися на **конкретні номери сторінок та пунктів** у вихідному PDF для швидкої ручної верифікації.

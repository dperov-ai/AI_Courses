# Робота з PDF-документами: поглиблений посібник з вилучення даних, OCR, аналізу таблиць та RAG

Формат **PDF (Portable Document Format)** є абсолютним світовим стандартом для електронного документообігу. У PDF зберігаються річні фінансові звіти, наукові монографії, технічні регламенти, креслення, рахунки та юридичні договори.

Проте для систем штучного інтелекту PDF історично є **найбільш проблемним форматом серед усіх існуючих**.

Головна причина: PDF створювався понад 30 років тому не для того, щоб машини читали структуру тексту, а для того, щоб документ виглядав **абсолютно ідентично при друку на будь-якому принтері у світі**. Усередині PDF немає семантичних понять «абзац», «заголовок», «колонка» чи «таблиця» — там є лише набір літер і векторних ліній, розташованих за точними фізичними координатами `(x, y)` на віртуальному аркуші.

У цьому поглибленому посібнику ми розберемо:

* чому класичні парсери зазнають краху на складних PDF;
* різницю між текстовими (цифровими) та сканованими (растровими) PDF;
* як оптичне розпізнавання (OCR) та мультимодальні моделі (Vision) змінили роботу з документами;
* проблему багатоколонкових макетів, об'єднаних таблиць та колонтитулів;
* архітектуру роботи з великими документами на 100–500+ сторінок (Map-Reduce vs Vector RAG);
* практичні промпти для аналізу складних договорів та фінансових звітів.

## 1. Анатомія PDF та пастки парсингу

```
+───────────────────────────────────────────────────────────────────────────+
|                       ТИПОВІ ПАСТКИ ПАРСИНГУ PDF-ФАЙЛІВ                   |
+───────────────────────────────────────────────────────────────────────────+
| 1. БАГАТОКОЛОНКОВИЙ ТЕКСТ (Multi-column flow)                             |
|    - Простий парсер читає рядок по горизонталі зліва направо,             |
|      зливаючи текст лівої та правої колонок в абсурдну кашу.              |
|                                                                           |
| 2. СКЛАДНІ ТАБЛИЦІ БЕЗ ЯВНИХ ЛІНІЙ (Border-less tables)                   |
|    - Дані з сусідніх стовпців злипаються в один рядок тексту.             |
|                                                                           |
| 3. КОЛОНТИТУЛИ ТА НОМЕРИ СТОРІНОК (Headers/Footers)                       |
|    - Назва розділу або номер сторінки вклинюються посеред важливого       |
|      речення або юридичного пункту, розриваючи контекст.                  |
|                                                                           |
| 4. СКАНИ ТА ФОТОГРАФІЇ (Scanned / Raster PDF)                             |
|    - У файлі взагалі немає текстового шару -> Без OCR модель бачить порожнечу.|
+───────────────────────────────────────────────────────────────────────────+
```

## 2. Два типи PDF: Digital-Native vs Scanned

```
                         [ ВХІДНИЙ PDF-ДОКУМЕНТ ]
                                     │
                 ┌───────────────────┴───────────────────┐
                 ▼                                       ▼
    [ DIGITAL-NATIVE PDF ]                      [ SCANNED PDF ]
    (Створено в Word/Docs)                      (Скан паперу / Фото)
    - Текст виділяється мишкою                  - Текстовий шар відсутній
    - Є вбудовані шрифти                        - Файл складається з картинок
                 │                                       │
                 ▼                                       ▼
    [ Прямий парсинг тексту ]                  [ ПОТРІБЕН OCR / VISION AI ]
```

### Як мультимодальний Vision AI змінив роботу з PDF:
Раніше для розпізнавання сканів використовувалися старі OCR-системи (наприклад, Tesseract), які часто видавали помилки при перекошених сторінках або складному фоні.

Сучасні мультимодальні моделі (**GPT-4o, Claude 3.5 Sonnet, Gemini 2.0**) «дивляться» на сторінку PDF як людина — через нейромережевий зір. Вони одночасно розуміють просторове розташування блоків, табличні рамки, шрифтові акценти та рукописні позначки на полях.

## 3. Стратегії обробки великих документів (від 50 до 500+ сторінок)

Коли ви завантажуєте в систему документ на сотні сторінок, перед вами постає інженерний вибір між двома підходами:

```
+─────────────────────────────────────────────────────────────────────────────────────────+
|                        СТРАТЕГІЇ ОБРОБКИ ВЕЛИКИХ PDF-ДОКУМЕНТІВ                         |
+────────────────────────────────----+────────────────────────────────────────────────----+
| 1. ПІДХІД MAP-REDUCE (Синтез)      | 2. ПІДХІД VECTOR RAG (Точковий пошук)              |
+────────────────────────────────----+────────────────────────────────────────────────----+
| - Документ ділиться на розділи.    | - Увесь PDF нарізається на чанки (фрагменти)       |
| - Кожен розділ аналізується окремо.|   і зберігається у векторній базі даних.           |
| - Робиться вичавка кожного блоку.  | - Користувач задає питання -> Система знаходить    |
| - Фінальний синтез збирає єдиний   |   3-5 найрелевантніших сторінок.                   |
|   звіт по всьому документу.        | - Модель відповідає точно за знайденими сторінками.|
|                                    |                                                    |
| Ідеально для: Створення повного    | Ідеально для: Пошуку конкретних умов, дат, сум у   |
| Executive Summary книги чи посібника| гігантських архівах документів.                    |
+────────────────────────────────----+────────────────────────────────────────────────----+
```

## 4. Практичний промпт для юридичного аудиту багатосторінкового договору

```markdown
Ти — провідний корпоративний юрист із 15-річним досвідом у сфері міжнародних контрактів.
Я завантажив PDF-документ договору генерального підряду.

Проведи комплексний аудит документа за такими блоками:

1. БАЗОВА ПАСПОРТНА ЧАСТИНА:
   - Сторони угоди, загальна вартість робіт, кінцеві строки виконання.

2. ЗОНИ КРИТИЧНОГО ЮРИДИЧНОГО РИЗИКУ ДЛЯ ЗАМОВНИКА:
   - Штрафні санкції та пені (вкажи точні номери пунктів і сторінок).
   - Порядок приймання робіт (чи немає пунктів про «автоматичне прийняття робіт через 3 дні»?).
   - Умови одностороннього розірвання договору та повернення авансу.
   - Форс-мажорні застереження та порядок повідомлення про форс-мажор.

3. ПРИХОВАНІ ПАСТКИ ТА ДВОЗНАЧНІ ФОРМУЛЮВАННЯ:
   - Знайди формулювання, які допускають подвійне тлумачення в суді.

4. РЕКОМЕНДАЦІЇ З ПРАВОК:
   - Склади таблицю: [Пункт договору] -> [Поточна ризикована редакція] -> [Рекомендована безпечна редакція] -> [Юридичне обґрунтування].

ВИМОГА: Для кожного зауваження обов'язково наводь пряму цитату та номер сторінки з PDF-файлу!
```

## Резюме уроку

1. PDF — це візуальний, а не текстовий формат, що вимагає використання **мультимодальних Vision-моделей або просунутих OCR-пайплайнів**.
2. Для роботи зі сканами обов'язково використовуйте моделі з підтримкою комп'ютерного зору (GPT-4o, Claude Sonnet, Gemini Flash).
3. Для документів до 500 сторінок підхід **Vector RAG** забезпечує точний пошук, а підхід **Map-Reduce** — створення комплексних саммарі.
4. Завжди вимагайте від моделі посилатися на **конкретні сторінки та пункти вихідного PDF-файлу** для швидкої верифікації людиною.

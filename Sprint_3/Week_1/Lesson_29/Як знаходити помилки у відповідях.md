# Як знаходити помилки у відповідях AI: поглиблений посібник із діагностики та виявлення прихованих дефектів

Виявити грубу або абсурдну помилку в тексті штучного інтелекту зазвичай не складає труднощів. Якщо модель стверджує, що швидкість світла становить 60 км/год або що Київ розташований в Австралії, будь-яка людина миттєво помітить збій.

Справжня небезпека сучасних мовних моделей полягає в **тонких, замаскованих та правдоподібних дефектах**. Це ситуації, коли текст виглядає на 98% ідеальним, логіка здається переконливою, але в 2% зашита критична підміна понять, перекручена формула або пропущений крайовий випадок, який повністю руйнує весь висновок.

У цьому детальному посібнику ми розберемо:

* анатомію та глибинні причини виникнення помилок у нейромережах;
* повну типологію прихованих дефектів у коді, текстах та розрахунках;
* непрямі лінгвістичні маркери («детектори брехні»), які видають галюцинацію моделі;
* 5 передових інженерних методик виявлення помилок (Inversion, Socratic Audit, Red Teaming, Trap Testing, Boundary Analysis);
* реальні виробничі кейси з детальним розбором допущених помилок.

---

## 1. Анатомія помилок: чому нейромережі помиляються

Щоб ефективно шукати дефекти, необхідно розуміти математичну природу великих мовних моделей (LLM).

Модель — це не база знань і не логічний процесор. Це **авторегресійний ймовірнісний апарат**, навчений прогнозувати наступний токен (слово або частину слова) на основі попереднього контексту.

```
+───────────────────────────────────────────────────────────────────────────+
|                       МАТЕМАТИЧНИЙ МЕХАНІЗМ ПОМИЛКИ                       |
+───────────────────────────────────────────────────────────────────────────+
| 1. Модель генерує слово A -> потім слово B -> потім слово C.             |
| 2. Якщо на етапі B модель обрала статистично ймовірне, але фактично       |
|    помилкове слово (наприклад, сплутала прізвище або знак операції),      |
| 3. УСІ НАСТУПНІ СЛОВА (C, D, E...) БУДУТЬ ПІДЛАШТОВУВАТИСЯ ПІД ПОМИЛКУ B! |
|                                                                           |
| ВИСНОВОК: Модель не зупиниться і не визнає помилку сама — вона почне      |
| геніально виправдовувати та "математично доводити" свій хибний крок!      |
+───────────────────────────────────────────────────────────────────────────+
```

Цей ефект називається **помилковим каскадом (Error Cascade)**. Якщо перший крок міркувань виявився хибним, уся наступна красива аргументація є лише ілюзією.

## 2. Повна типологія прихованих помилок AI

```
+───────────────────────────────────────────────────────────────────────────+
|                     КЛАСИФІКАЦІЯ ДЕФЕКТІВ У ВІДПОВІДЯХ AI                 |
+───────────────────────────────────────────────────────────────────────────+
| 1. ENTITY CONFUSION (Змішування сутностей)                                |
|    - Об'єднання характеристик схожих брендів, компаній, фреймворків       |
|                                                                           |
| 2. PREMISE COMPLIANCE (Сліпа згода з хибною передумовою)                  |
|    - Модель підтакує помилці, закладеній у запиті користувача             |
|                                                                           |
| 3. NON-SEQUITUR LOGIC (Логічний розрив)                                   |
|    - Висновки суперечать вхідним даним або не випливають із них           |
|                                                                           |
| 4. SEMANTIC DRIFT (Зсув значень термінів)                                 |
|    - Використання терміна в різних значеннях на початку та в кінці тексту |
|                                                                           |
| 5. BOUNDARY CONDITION FAILURE (Крайові збої)                              |
|    - Ігнорування нульових, від'ємних значень, порожніх списків у коді     |
+───────────────────────────────────────────────────────────────────────────+
```

---

### Детальний опис кожного типу помилок:

#### 1. Змішування сутностей (Entity Confusion)
Виникає, коли два об'єкти мають схожі назви або функціонують в одній ніші. Наприклад, модель може описати функції хмарного сховища *Google Cloud Storage*, приписавши йому специфічні API-методи від *Amazon S3*, або сплутати положення двох різних версій стандарту ISO.

#### 2. Сліпа згода з хибною передумовою (Premise Compliance / Sycophancy)
Якщо ви випадково або навмисно напишете в промпті: *«Чому в 2018 році Білл Гейтс продав Microsoft компанії Google?»*, модель зі слабким вирівнюванням не скаже «Це неправда». Вона почне вигадувати причини цієї угоди, створюючи переконливу альтернативну історію.

#### 3. Зсув значень термінів (Semantic Drift)
У довгих текстах модель може почати використовувати слово «прибуток» як синонім «виторгу», а через кілька абзаців — як «маржинальний дохід», що робить увесь фінансовий звіт абсолютно невірним.

## 3. Непрямі мовні маркери («Детектори брехні» в тексті)

Коли нейромережа не має точних фактів або намагається згладити суперечність, її стиль мовлення зазнає характерних змін:

| Маркер | Як це виглядає в тексті | Що це означає насправді |
| :--- | :--- | :--- |
| **Маркер абстрактного авторитету** | *«Провідні експерти галузі одностайно стверджують...»* | У моделі немає конкретних імен, досліджень та цифр. |
| **Маркер розмитого часу** | *«Останнім часом спостерігається стійка тенденція...»* | Модель не знає точного року чи місяця події. |
| **Маркер надмірної дипломатичності** | *«З одного боку це так, але з іншого боку може бути зовсім інакше...»* | Модель уникає точної відповіді через брак знань. |
| **Маркер повторення промпту** | Дослівне переказування ваших же слів іншими синонімами без додавання нових фактів. | Модель не зрозуміла запит або вичерпала інформацію. |

## 4. П'ять передових методик діагностики помилок

```
    ┌─────────────────────────────────────────────────────────────┐
    │ 1. ІНВЕРСІЙНИЙ АУДИТ (Пошук контрприкладів та спростувань)  │
    └──────────────────────────────┬──────────────────────────────┘
                                  ▼
    ┌─────────────────────────────────────────────────────────────┐
    │ 2. СОКРАТИЧНИЙ ДІАЛОГ (Покрокове розкриття доказів)         │
    └──────────────────────────────┬──────────────────────────────┘
                                  ▼
    ┌─────────────────────────────────────────────────────────────┐
    │ 3. СТРЕС-ТЕСТ НА КРАЙОВІ ДАНІ (Boundary & Edge Case Testing)│
    └──────────────────────────────┬──────────────────────────────┘
                                  ▼
    ┌─────────────────────────────────────────────────────────────┐
    │ 4. RED TEAMING (Навмисні спроби зламати логіку рішення)     │
    └─────────────────────────────────────────────────────────────┘
```

---

### Методика 1. Інверсійний аудит (Inversion Audit)
Замість того щоб питати «Чи правильний цей текст?», змусьте модель атакувати власну відповідь:

```markdown
Ось чернетка нашої стратегії виходу на новий ринок:
"""
[Вставте згенерований текст]
"""

Твоя задача — провести безжальний інверсійний аудит.
Знайди 5 найслабших припущень у цій стратегії, які при реалізації призведуть до фінансових збитків. Поясни для кожного пункту:
1. Яке хибне припущення зроблено?
2. Який реальний ризик виникає?
3. Яких даних бракує для підтвердження гіпотези?
```

---

### Методика 2. Стрес-тест на крайові дані (Edge Case Testing)
Якщо AI написав код, формулу для Excel чи бізнес-правило, протестуйте його на крайнощах:

1. **Нульові та від'ємні значення:** Що буде, якщо кількість товару = 0 або -5?
2. **Гігантські числа:** Що станеться, якщо оборот компанії складе 1 трильйон?
3. **Порожні рядки та спеціальні символи:** Як система обробить введення ієрогліфів, лапок `"` чи коду `<script>`?
4. **Нетипова поведінка:** Що робити, якщо клієнт одночасно натиснув кнопку оплати двічі?

## 5. Практичний розбір: пошук прихованої помилки у бізнес-кейсі

### Згенерований AI фрагмент:
> «Для збільшення прибутку нашого SaaS-сервісу рекомендується знизити ціну підписки з $50 до $30 на місяць. Це дозволить збільшити кількість користувачів на 50% (з 1,000 до 1,500 клієнтів), що забезпечить суттєве зростання щомісячного виторгу компанії».

### Покроковий аудит розрахунку:
* **Початковий стан:** 1,000 користувачів * $50 = **$50,000 на місяць**.
* **Новий стан після змін:** 1,500 користувачів * $30 = **$45,000 на місяць**.
* **Реальний результат:** Виторг компанії **впаде на $5,000 щомісяця (-10%)**, незважаючи на зростання клієнтської бази на 50%!

> **Висновок:** Модель використала правильні маркетингові слова про «зростання клієнтів», але припустилася елементарної економічної помилки, яка коштувала б компанії 10% доходу.

## Резюме уроку

1. Головна небезпека LLM — **правдоподібні та приховані помилки**, які маскуються під грамотний текст.
2. Ефект **каскадної помилки** означає, що один хибний крок на початку призводить до повної неправдивості всіх наступних висновків.
3. Звертайте увагу на **мовні маркери невпевненості**: посилання на абстрактних «експертів» та розмиті часові рамки.
4. Застосовуйте **інверсійний аудит** та обов'язковий **стрес-тест на крайові випадки (Edge Cases)**.
5. Завжди перераховуйте базові економічні формули на калькуляторі або через скрипти Python.

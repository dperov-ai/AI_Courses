# Коли не можна довіряти моделі: зони високого ризику, безпека даних та межі застосування AI

Штучний інтелект створює відчуття універсального всезнаючого інструменту, здатного миттєво написати позовну заяву, розрахувати схему прийому антибіотиків, спроектувати електромережу будинку або спланувати інвестиційний портфель.

Проте вміння професіонала полягає не лише в тому, щоб знати, де AI приносить максимальну користь, а насамперед у тому, щоб чітко розуміти **червоні лінії — сфери, де пряме використання мовних моделей є неприпустимим, небезпечним або незаконним**.

У цьому фундаментальному посібнику ми розглянемо:

* концепцію завдань із високою ціною помилки (High-Stakes Decisions);
* детальну матрицю толерантності до галюцинацій у бізнесі;
* ризики в юриспруденції, медицині, фінансах та інженерії;
* захист персональних даних (GDPR, HIPAA) та комерційної таємниці (NDA);
* техніки анонімізації та безпечного використання хмарних AI-сервісів.

---

## 1. Концепція High-Stakes завдань та ціна помилки

Усі завдання в бізнесі та житті мають різну **ціну помилки (Cost of Failure)**:

```
+───────────────────────────────────────────────────────────────────────────+
|                        СПЕКТР ЦІНИ ПОМИЛКИ В AI                           |
+───────────────────────────────────────────────────────────────────────────+
| НИЗЬКА ЦІНА ПОМИЛКИ (Low-Stakes):                                         |
| - Помилка в пості для соцмереж ──► Максимум пара правок від колеги        |
| - Невдала метафора в статті     ──► Зниження конверсії на 0.1%            |
|                                                                           |
| ВИСОКА ЦІНА ПОМИЛКИ (High-Stakes):                                        |
| - Помилка в дозуванні ліків     ──► Загроза життю пацієнта                |
| - Пропущений пункт договору    ──► Мільйонні штрафи та судові позови      |
| - Помилка в коді смарт-контракту ──► Миттєва крадіжка всіх коштів хакерами|
+───────────────────────────────────────────────────────────────────────────+
```

Якщо в Low-Stakes задачах генеративний AI є ідеальним інструментом, то в High-Stakes задачах AI може виступати **виключно як допоміжний асистент для чорнового пошуку інформації, а остаточне рішення має приймати тільки дипломований спеціаліст із повною юридичною та фаховою відповідальністю**.

## 3. Детальний розбір зон критичного ризику

```
                       +─────────────────────────────────+
                       |     ЗОНИ КРИТИЧНОГО РИЗИКУ      |
                       +─────────────────────────────────+
                       | 1. Медицина та охорона здоров'я |
                       | 2. Юриспруденція та контракти   |
                       | 3. Фінансовий та податковий облік|
                       | 4. Промислова та авіаційна безпека|
                       | 5. Інформаційна безпека (SecOps)|
                       +─────────────────────────────────+
```

### 1. Медицина та фармакологія
* **Чому AI небезпечний:** Модель може сплутати схожі назви препаратів, не врахувати протипоказання, хронічні захворювання або небезпечну взаємодію двох діючих речовин.
* **Допустиме використання:** Переклад медичних термінів простою людською мовою, структурування щоденника симптомів перед візитом до лікаря.
* **Категорично заборонено:** Призначення або скасування лікування, самодіагностика за порадою чат-бота.

### 2. Юриспруденція та складання договорів
* **Чому AI небезпечний:** Модель не несе цивільної, адміністративної чи кримінальної відповідальності. Вона легко може вставити в договір пункт, який прямо суперечить імперативним нормам чинного законодавства конкретної країни, зробивши весь контракт недійсним.
* **Допустиме використання:** Пошук друкарських помилок, структурування чернеток за наданим шаблоном, скорочення довгих пунктів.

### 3. Фінансовий та податковий облік
* **Чому AI небезпечний:** Податкове законодавство постійно змінюється, містить тисячі локальних підзаконних актів та роз'яснень. Модель із застарілою базою знань порахує податок на прибуток або ПДВ за старими правилами, що призведе до блокування рахунків та штрафів від податкової служби.

## 4. Конфіденційність та безпека даних (GDPR, NDA, PII)

Коли ви відправляєте запит у хмарний сервіс (наприклад, ChatGPT, Claude, Gemini у безкоштовних або стандартних тарифах), ваші дані за замовчуванням можуть використовуватися для донавчання майбутніх версій моделей.

```
+───────────────────────────────────────────────────────────────────────────+
|                    ЩО КАТЕГОРИЧНО ЗАБОРОНЕНО ВІДПРАВЛЯТИ В AI             |
+───────────────────────────────────────────────────────────────────────────+
| 1. ПЕРСОНАЛЬНІ ДАНІ (PII):                                                |
|    - Паспортні дані, номери банківських карток, CVV-коди                  |
|    - Медичні виписки, діагнози пацієнтів                                  |
|    - Номери телефонів та домашні адреси клієнтів (штрафи за GDPR)         |
|                                                                           |
| 2. СЕКРЕТИ РОЗРОБКИ ТА ІНФРАСТРУКТУРИ:                                    |
|    - Паролі до баз даних, приватні SSH-ключі                              |
|    - API-токени платіжних систем (Stripe, LiqPay, PayPal)                 |
|                                                                           |
| 3. КОМЕРЦІЙНА ТАЄМНИЦЯ ТА ДОКУМЕНТИ ПІД NDA:                              |
|    - Закриті фінансові звіти до офіційної публікації                      |
|    - Плани злиття та поглинання компаній (M&A)                            |
|    - Унікальні патентовані алгоритми та вихідні коди продукту             |
+───────────────────────────────────────────────────────────────────────────+
```

## 5. Техніка санітизації (анонімізації) даних перед завантаженням в AI

Якщо вам конче необхідно проаналізувати договір або клієнтську таблицю за допомогою AI, проведіть процедуру **санітизації (Data Sanitization)**.

### Алгоритм заміни конфіденційних сутностей:

```
[ ОРИГІНАЛЬНИЙ ТЕКСТ ]
"ТОВ 'ФармХім', директор Іванов І.І., код ЄДРПОУ 12345678, замовляє 
поставку сировини на суму 2,500,000 грн на адресу м. Київ, вул. Польова 12."
                           │
                           ▼ (Анонімізація за шаблоном)
[ САНІТИЗОВАНИЙ ТЕКСТ ДЛЯ AI ]
"ТОВ [КОМПАНІЯ_А], директор [ДИРЕКТОР_1], код [КОД_1], замовляє 
поставку сировини на суму [СУМА_1] на адресу [АДРЕСА_1]."
```

Після отримання відповіді від AI ви просто робите зворотну заміну плейсхолдерів на реальні дані у своєму локальному редакторі.

---

## Резюме уроку

1. Чітко розділяйте задачі за **ціною помилки**: у High-Stakes задачах AI може бути лише асистентом, але ніколи — суддею.
2. Керуйтеся **матрицею толерантності до галюцинацій**: від повної свободи у творчості до нульової толерантності в праві та медицині.
3. Ніколи не завантажуйте у відкриті чати **паролі, ключі, персональні дані клієнтів та комерційну таємницю під NDA**.
4. Використовуйте техніку **санітизації (анонімізації)** перед завантаженням реальних документів у мовні моделі.
5. Юридична та фінансова відповідальність за рішення завжди залишається за людиною.

# Коли достатньо промпта, а коли потрібен workflow або AI-агент

Сьогодні навколо теми штучного інтелекту багато шуму: маркетологи закликають створювати «автономних AI-агентів» для кожної задачі. Проте на практиці більшість проектів зазнають невдачі саме через надмірну складність архітектури.

Якщо ви будуєте складного мультиагентного бота для задачі, яку можна вирішити звичайним промптом або лінійним 3-кроковим сценарієм, ви отримуєте ненадійну, повільну та дорогу систему, яка ламається на кожному кроці.

Професійний підхід полягає у виборі **мінімально необхідного рівня складності** під кожну бізнес-задачу.

У цьому уроці ми розберемо:

* три рівні зрілості AI-рішень (Промпт -> Воркфлоу -> Агент);
* що таке автономний AI-агент і чим він відрізняється від звичайного конвеєра;
* матрицю прийняття архітектурних рішень;
* антипатерн Over-engineering та як уникнути зайвих витрат;
* реальні сценарії вибору між промптом, воркфлоу та агентом.

## Три рівні системності у роботі з AI

```
+-----------------------------------------------------------------------------------------+
|                                ТРИ РІВНІ AI-АРХІТЕКТУРИ                                 |
+--------------------------+------------------------------+-------------------------------+
| Рівень                   | Принцип роботи               | Ідеальні сценарії застосування|
+--------------------------+------------------------------+-------------------------------+
| 1. SINGLE PROMPT         | Людина вручну пише запит у   | - Разові творчі задачі        |
| (Разовий промпт)         | чат і сама оцінює відповідь. | - Брейнштормінг, пошук ідей   |
|                          | Немає автоматизації.         | - Написання статті чи коду    |
+--------------------------+------------------------------+-------------------------------+
| 2. STRUCTURED WORKFLOW   | Жорстко заданий ланцюжок дій | - Повторювана бізнес-рутина   |
| (Фіксований конвеєр)     | (Крок А -> Крок Б -> Крок В).| - Парсинг лідів, збереження   |
|                          | Логіка зафіксована людиною.  |   даних у CRM, дайджести      |
+--------------------------+------------------------------+-------------------------------+
| 3. AUTONOMOUS AI AGENT   | Модель САМА обирає інструменти| - Задачі з високою            |
| (Автономний агент)       | та вирішує, що робити далі   |   варіативністю               |
|                          | (ReAct: Думка -> Дія -> Спо- | - Глибокий ресьорч, автономне |
|                          | стереження -> Нова дія).     |   програмування, техпідтримка |
+--------------------------+------------------------------+-------------------------------+
```

## Чим AI-Агент відрізняється від Workflow

Головна різниця — **у тому, хто приймає рішення про наступний крок**:

* **У Workflow (Воркфлоу):** Людина-інженер заздалегідь прописала всі стрілочки: «Якщо лист містить слово "Оплата" — піти на Вузол 2, потім на Вузол 3». Модель не може змінити порядок дій. Це забезпечує **передбачуваність і надійність 99.9%**.
* **У AI-Агенті:** Моделі надається набір інструментів (пошук у Google, відправка email, запуск коду, доступ до бази даних) та кінцева мета: *«Знайди 5 найкращих постачальників зерна в Польщі та домовся про дзвінок»*. Модель сама думає, який інструмент викликати першим, оцінює проміжний результат і вирішує, що робити далі.

```
WORKFLOW: [Крок 1] ────► [Крок 2] ────► [Крок 3] (Завжди однаковий фіксований шлях)

AGENT:    [Мета] ──► [Думає: який крок зробити?] ──► [Викликає Tool A]
                          ▲                                │
                          └─────── [Оцінює результат] ◄────┘
```

## Матриця вибору архітектурного рішення

```
Чи повторюється задача щодня?
│
├── НІ ────────────────────────────────────────► РІВЕНЬ 1: Звичайний промпт у чаті
│
└── ТАК: Чи відомий заздалегідь чіткий алгоритм кроків?
    │
    ├── ТАК (Алгоритм фіксований) ─────────────► РІВЕНЬ 2: Автоматизований Workflow (n8n / Make)
    │
    └── НІ (Потрібне дослідження та вибір дій) ─► РІВЕНЬ 3: Автономний AI-Агент
```

## Резюме уроку

1. Завжди починайте з найпростішого рішення: **Промпт -> якщо повторюється, робіть Workflow -> якщо непередбачуваний алгоритм, будуйте Агента**.
2. **Workflow (n8n / Make)** — це робоча конячка сучасного бізнесу: надійна, передбачувана та швидка.
3. **AI-Агенти** потрібні лише тоді, коли системі потрібна повна свобода вибору інструментів та динамічне планування.
4. Уникайте **Over-engineering**: створення агента замість простого воркфлоу збільшує вартість і ризик збоїв у 10 разів.

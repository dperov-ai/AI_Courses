# Аналіз інформації та витягування даних: перетворення хаосу на структуру

Близько 80% усієї інформації в бізнесі існує у **неструктурованому вигляді**: листи електронної пошти, повідомлення в чатах підтримки, коментарі в соцмережах, текстові нотатки, аудіозаписи дзвінків та скани договорів. Традиційні програми не вміють ефективно аналізувати цей масив, тому компанії змушені наймати сотні операторів для ручного перенесення даних у таблиці та CRM.

Штучний інтелект здійснює революцію в напрямку **Information Extraction (IE / Вилучення інформації)**: він здатний прочитати хаотичний лист і миттєво перетворити його на бездоганно структурований JSON із виділеними сутностями, тональністю, наміром клієнта та рівнем терміновості.

У цьому уроці ми розглянемо:

* основи вилучення сутностей (Named Entity Recognition / NER);
* класифікацію намірів клієнта (Intent Classification) та аналіз емоцій (Sentiment Analysis);
* перетворення неструктурованого тексту на машиночитані бази даних;
* методи обробки неповних та суперечливих даних;
* побудову практичного конвеєра автоматичної обробки лідів.

---

## Ключові технології аналізу тексту

```
+-------------------------------------------------------------------+
|               АРХІТЕКТУРА ВИЛУЧЕННЯ ІНФОРМАЦІЇ (IE)               |
+-------------------------------------------------------------------+
| 1. NAMED ENTITY RECOGNITION (NER / Розпізнавання сутностей)       |
|    - Імена людей, компанії, локації, дати, суми, номери замовлень |
|                                                                   |
| 2. INTENT CLASSIFICATION (Визначення наміру)                      |
|    - [Купівля], [Скарга], [Запит повернення], [Технічна проблема] |
|                                                                   |
| 3. SENTIMENT & URGENCY (Тональність та терміновість)              |
|    - Рівень задоволеності (1-5), емоційний тон, пріоритет (P1-P4) |
+-------------------------------------------------------------------+
```

## Практичний приклад: обробка хаотичного звернення клієнта

### Вхідне неструктуроване повідомлення з чату:
> «Добрий день, це Віталій із ТОВ "АгроПром". Ми вчора замовляли у вас 10 мішків добрива на склад у Вінниці за накладною #4412. Сьогодні відкрили — а там зовсім не той бренд! Терміново зв'яжіться зі мною за номером 067 555 44 33, бо у нас посівна зупинилася!»

### Промпт для екстракції:
```markdown
Ти — автоматичний бекенд-парсер звернень клієнтів.
Проаналізуй вхідне повідомлення та витягни всі дані за заданою схемою JSON.

Схема:
{
  "client": {
    "name": string,
    "company": string or null,
    "phone": string (у форматі +380...) or null
  },
  "order": {
    "order_id": string or null,
    "product_mentioned": string,
    "quantity": string or null,
    "city": string or null
  },
  "issue": {
    "category": "wrong_item" | "delivery_delay" | "damaged" | "other",
    "summary": string (1 речення),
    "urgency": "low" | "medium" | "critical"
  }
}

Повертай ВИКЛЮЧНО валідний JSON без додаткових коментарів.
```

### Згенерований результат:
```json
{
  "client": {
    "name": "Віталій",
    "company": "ТОВ \"АгроПром\"",
    "phone": "+380675554433"
  },
  "order": {
    "order_id": "#4412",
    "product_mentioned": "добриво",
    "quantity": "10 мішків",
    "city": "Вінниця"
  },
  "issue": {
    "category": "wrong_item",
    "summary": "Клієнту доставили добриво іншого бренду за накладною #4412.",
    "urgency": "critical"
  }
}
```

## Обробка прогалин та суперечностей у даних

Під час автоматичного парсингу часто виникають ситуації, коли клієнт не вказав телефон або назвав суперечливі дати.

### Правила побудови надійного промпту екстракції:
1. **Явна робота з `null`:** Якщо модель не знаходить даних — вона має повертати `null`, а не вигадувати значення за замовчуванням.
2. **Вимога нормалізації:** Завжди вимагайте нормалізації форматів (наприклад, дати у форматі `YYYY-MM-DD`, телефони у міжнародному форматі).
3. **Використання Enums (обмежених списків):** Задавайте фіксований список допустимих категорій, щоб база даних не засмічувалася випадковими синонімами.

## Резюме уроку

1. **Information Extraction (IE)** перетворює 80% неструктурованого бізнес-листування на готові машиночитані бази даних.
2. **NER (Named Entity Recognition)** надійно ідентифікує людей, компанії, адреси, суми та номери документів.
3. Поєднання екстракції сутностей із визначенням **наміру (Intent)** та **терміновості (Urgency)** дозволяє автоматично маршрутизувати тікети у відділи компанії.
4. Використання суворих JSON-схем із зафіксованими типами даних виключає помилки під час інтеграції з CRM.

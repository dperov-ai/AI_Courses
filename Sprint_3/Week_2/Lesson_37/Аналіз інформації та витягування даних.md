# Аналіз інформації та витягування даних: поглиблений посібник з Information Extraction, NER та структурування неструктурованого хаосу

У сучасному бізнес-середовищі понад 80% усіх цінних даних існують у **неструктурованому або напівструктурованому вигляді**: листи електронної пошти, коментарі в соціальних мережах, стенограми телефонних дзвінків, вхідні повідомлення в месенджерах, PDF-рахунки, відгуки на маркетплейсах та нотатки в CRM.

Класичні реляційні бази даних (SQL) та корпоративні системи не вміють самостійно обробляти вільний людський текст. Через це компанії змушені витрачати колосальні бюджети на ручну працю операторів, які вручну копіюють номери телефонів, суми замовлень, імена клієнтів та категорії звернень із чатів у CRM-системи.

Штучний інтелект здійснює фундаментальну революцію в напрямку **Information Extraction (IE / Вилучення інформації)**: він здатний миттєво прочитати будь-яке хаотичне повідомлення, зрозуміти його контекст, визначити намір і повернути бездоганно структурований JSON, готовий до автоматичного запису в базу даних.

У цьому поглибленому посібнику ми розглянемо:

* архітектуру вилучення інформації: Named Entity Recognition (NER), Intent Recognition та Sentiment Analysis;
* як перетворити хаотичний вхідний текст на валідний машиночитаний JSON;
* надійні методи роботи з неповними даними, пропущеними полями (`null`) та суперечностями;
* типізацію та валідацію за допомогою JSON Schema та Enums;
* реальний бізнес-пайплайн автоматичної маршрутизації вхідних лідів.

## 1. Архітектурні компоненти вилучення інформації (Information Extraction)

Сучасний процес екстракції даних будується на трьох взаємопов'язаних когнітивних шарах:

```
+───────────────────────────────────────────────────────────────────────────+
|                  ТРИ ШАРИ АНАЛІЗУ НЕСТРУКТУРОВАНОГО ТЕКСТУ                |
+───────────────────────────────────────────────────────────────────────────+
| ШАР 1: NAMED ENTITY RECOGNITION (NER / Виділення іменованих сутностей)    |
| - Знаходження конкретних об'єктів: Імена людей, Назви брендів, Номери     |
|   телефонів, Суми у валюті, Дати та географічні назви.                    |
|                                                                           |
| ШАР 2: INTENT CLASSIFICATION (Визначення наміру користувача)              |
| - Розуміння мети звернення: [Замовлення], [Скарга], [Питання щодо оплати],|
|   [Запит на повернення коштів], [Спам].                                   |
|                                                                           |
| ШАР 3: SENTIMENT & URGENCY (Аналіз емоційного фону та терміновості)       |
| - Визначення тональності (Positive / Neutral / Negative) та пріоритету    |
|   (Low / Medium / High / Critical).                                       |
+───────────────────────────────────────────────────────────────────────────+
```

## 2. Від хаосу до структури: практичний приклад екстракції

### Вхідне неструктуроване повідомлення від B2B-клієнта:
> «Привіт! Це Сергій, фінансовий директор ТОВ "ТехноБуд" (ЄДРПОУ 38921455). Ми розглянули вашу комерційну пропозицію за договором #ТБ-2024 і готові підписати контракт на закупівлю 50 ліцензій вашого ПЗ на суму $12,500 з річною оплатою. Проте у нас є критична вимога: доставка рахунку та актів має бути виключно через систему "Вчасно" до наступної п'ятниці. Передзвоніть моєму помічнику Олександру за номером +38 050 999 88 77 для фіналізації».

---

### Промпт для промислової екстракції даних:

```markdown
Ти — провідний бекенд-парсер корпоративних лідів та контрактів.
Твоя задача — витягти з вхідного тексту всі ключові сутності та структурувати їх за схемою JSON.

СУВОРІ ПРАВИЛА:
1. Повертай ТІЛЬКИ валідний JSON, без жодних вступних фраз, коментарів чи блоків коду.
2. Якщо будь-яке значення не вказано в тексті — повертай null, категорично заборонено вигадувати дані.
3. Усі номери телефонів нормалізуй до міжнародного стандарту (+380...).
4. Усі грошові суми конвертуй у числові значення (number).

СХЕМА ВИВЕДЕННЯ (JSON SCHEMA):
{
  "company": {
    "name": string,
    "edrpou": string or null
  },
  "primary_contact": {
    "name": string,
    "role": string or null
  },
  "secondary_contact": {
    "name": string or null,
    "phone": string or null
  },
  "deal": {
    "contract_id": string or null,
    "item": string,
    "quantity": integer,
    "total_amount_usd": number,
    "billing_period": "monthly" | "annually" | "one_time"
  },
  "requirements": {
    "electronic_doc_service": string or null,
    "deadline_text": string or null
  },
  "meta": {
    "intent": "purchase_intent" | "support_request" | "complaint" | "spam",
    "urgency": "low" | "medium" | "high"
  }
}

ВХІДНЕ ПОВІДОМЛЕННЯ:
[Текст повідомлення]
```

## 3. Обробка крайових випадків та відсутніх даних

Під час автоматичного парсингу система постійно стикається з неповними або брудними вхідними даними.

```
+───────────────────────────────────────────────────────────────────────────+
|               ЗОЛОТІ ПРАВИЛА ОБРОБКИ КРАЙОВИХ ВИПАДКІВ                    |
+───────────────────────────────────────────────────────────────────────────+
| 1. ПРИНЦИП ЯВНОГО NULL:                                                   |
|    - Замість вигадування випадкового телефону модель повертає `null`.     |
|                                                                           |
| 2. ВИКОРИСТАННЯ ENUMS (Фіксованих категорій):                             |
|    - Поле "категорія" має приймати тільки заздалегідь визначені значення: |
|      `"status": "new" | "in_progress" | "closed"`.                        |
|                                                                           |
| 3. НОРМАЛІЗАЦІЯ ДАТ ТА ТЕЛЕФОНІВ:                                         |
|    - Всі "сьогодні о третій" перетворюються на ISO-формат:                |
|      `2024-06-15T15:00:00Z`.                                              |
+───────────────────────────────────────────────────────────────────────────+
```

## Резюме уроку

1. **Information Extraction (IE)** автоматизує до 80% рутинної роботи операторів із внесення даних у CRM.
2. Поєднання **NER (сутності)**, **Intent (намір)** та **Sentiment (тональність)** дозволяє повністю автоматизувати первинну обробку звернень.
3. Використовуйте суворі **JSON-схеми** з фіксованими типами даних (`number`, `string`, `null`, `enums`), щоб виключити помилки під час запису в базу даних.
4. Обов'язково вимагайте **нормалізації форматів** телефонів, сум та дат.

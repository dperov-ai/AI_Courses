# Що таке workflow: архітектура автоматизованих робочих процесів

Коли ви щодня вручну відкриваєте чат-бот, копіюєте туди текст листа, вставляєте промпт, копіюєте відповідь і переносите її в таблицю — це ручна праця, яка відбирає години часу. Використання AI в такому режимі залишається індивідуальною «милицею», а не системним бізнес-інструментом.

Справжнє зростання ефективності починається тоді, коли взаємодія з AI упаковується у **Workflow (робочий процес / конвеєр)**.

**Workflow** — це заздалегідь налаштований, автоматичний ланцюжок дій, який запускається за певною подією (тригером), передає дані через послідовність кроків (включно з обробкою через AI) і зберігає результат у потрібному місці без участі людини.

У цьому уроці ми розглянемо:

* різницю між разовим запитом у чат та автоматизованим Workflow;
* анатомію будь-якого бізнес-воркфлоу: Тригер -> Обробка -> Дія;
* поєднання детермінованої логіки (IF/ELSE) та штучного інтелекту;
* поняття пайплайнів (Pipelines) та маршрутизації даних (Routers);
* як знаходити процеси у своїй компанії, які варто перетворити на Workflow.

## Анатомія сучасного AI-Workflow

Будь-який автоматизований робочий процес складається з 5 обов'язкових блоків:

```
+─────────────────────────────────────────────────────────────────────────────+
|                        АНАТОМІЯ АВТОМАТИЗОВАНОГО WORKFLOW                   |
+─────────────────────────────────────────────────────────────────────────────+
| 1. ТРИГЕР (Trigger)          ──► Новий лист на пошті / Форма на сайті / Таймер |
|                                                                             |
| 2. ЗБІР ДАНИХ (Input)        ──► Вилучення тексту, вкладень, контактів       |
|                                                                             |
| 3. AI-ОБРОБКА (Enrichment)   ──► Класифікація, парсинг, саммарі, переклад    |
|                                                                             |
| 4. РОУТИНГ (Router / Logic)  ──► Якщо лід гарячий -> в CRM; якщо спам -> кошик|
|                                                                             |
| 5. ДІЯ (Action / Output)     ──► Відправка повідомлення в Telegram / Slack   |
+─────────────────────────────────────────────────────────────────────────────+
```

## Детермінований код vs AI-вузли: ідеальний симбіоз

Головна помилка початківців — намагатися вирішити абсолютно все через штучний інтелект.

AI дорогий, має затримку (latency) і є ймовірнісним. Прості операції повинні виконуватися класичним програмним кодом, а AI має підключатися **тільки там, де потрібне людське розуміння сенсу**.

| Тип задачі | Хто повинен виконувати | Приклад |
| :--- | :--- | :--- |
| **Детермінована логіка** | Класичний код / фільтр | Перевірити, чи заповнене поле «Email»; відправити вебхук; перевірити поточний час. |
| **Когнітивна задача** | AI-вузол (LLM) | Визначити тональність скарги; витягти суть проблеми; перекласти складний текст; написати чернетку відповіді. |

```
[ Новий лід ] ──► [ Перевірка email (Код) ] ──► [ Аналіз наміру (AI) ] ──► [ Запис у CRM (Код) ]
```

## Покроковий алгоритм проектування власного Workflow

Перед тим як збирати процес у Make або n8n, дайте відповідь на 4 інженерні питання:

1. **Що є стартом (Тригером)?** (Отримання оплати, заповнення форми, натискання кнопки, розклад щопонеділка о 9:00).
2. **Які сирі дані надходять на вхід?** (Текст, аудіофайл, PDF-рахунок, рядок у базі даних).
3. **Яку саме трансформацію має зробити AI?** (Який чіткий системний промпт та JSON-схема потрібні).
4. **Куди має піти фінальний результат?** (Telegram-канал, таблиця Google Sheets, задача в Notion, відповідь клієнту).

---

## Резюме уроку

1. **Workflow** перетворює хаотичні ручні запити до AI на стабільні, повторювані конвеєри обробки даних.
2. Будь-який процес будується за схемою: **Тригер -> Вхідні дані -> AI-обробка -> Маршрутизація -> Фінальна дія**.
3. Найкращі воркфлоу поєднують **швидкий надійний код** для рутинної логіки та **AI-вузли** для аналізу смислів і генерації контенту.
4. Проектування воркфлоу завжди починається на папері або в блок-схемі, а вже потім реалізується на платформах автоматизації.

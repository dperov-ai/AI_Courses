# Контрольні запитання: Обмеження AI в UI/UX дизайні

1. Чому повна довіра до згенерованих AI інтерфейсів без ручної перевірки дизайнером створює критичні бізнес-ризики?
2. Опишіть 5 найпоширеніших дефектів макетів, згенерованих інструментами штучного інтелекту.
3. Що таке стандарти веб-доступності **WCAG 2.2** та чому їхнє дотримання є юридичною вимогою в багатьох країнах?
4. Які мінімальні норми контрастності кольорів (Contrast Ratio) встановлені стандартом WCAG для звичайного та великого тексту?
5. Чому мінімальний розмір сенсорної зони (Tap Target) для мобільних пристроїв повинен становити не менше 44x44px?
6. Що таке Safe Area на смартфонах (Dynamic Island, смуга жестів Home Bar) і як AI-макети порушують ці зони?
7. Чому використання тільки зникаючого плейсхолдера всередині поля введення без постійного лейбла є грубою UX-помилкою?
8. Поясніть різницю між нативними гайдлайнами Apple Human Interface Guidelines (HIG) та Google Material Design.
9. Що таке симуляція дальтонізму (Color-Blindness Testing) і як перевірити макет на читабельність для людей із порушенням сприйняття кольорів?
10. Як перевірити адаптивність згенерованого компонента за допомогою Auto-Layout (властивості Hug / Fill) у Figma?
11. Чому AI часто обирає нереалістично короткі тексти для макетів і що станеться при локалізації німецькою мовою?
12. Що таке фокусний стан (Focus Ring) для навігації з клавіатури і чому видалення обводки в CSS є антипатерном?
13. Складіть промпт для перевірки згенерованого екрану на відповідність стандартам доступності WCAG 2.2 AA.
14. Складіть чек-лист перевірки інтерфейсу мобільного додатку на реальному пристрої через Figma Mirror.
15. Що робити, якщо згенерована AI ілюстрація містить візуальні артефакти або анатомічні спотворення?
16. Як організувати єдине джерело правди (Single Source of Truth) для дизайн-токенів між Figma та кодом розробників?
17. Чому використання занадто блідих сірих кольорів для другорядного тексту шкодить читабельності на сонці?
18. Як взаємодіяти з фронтенд-розробниками під час передачі макетів (Design Handoff) для уникнення розбіжностей?
19. Опишіть порядок дій дизайнера при проведенні фінального дизайн-аудиту згенерованого інтерфейсу.
20. Складіть фінальний протокол якості дизайну (Design QA Checklist) перед запуском продукту в розробку.

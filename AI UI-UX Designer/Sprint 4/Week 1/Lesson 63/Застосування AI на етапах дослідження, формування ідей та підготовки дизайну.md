# Застосування AI на етапах дослідження, формування ідей та підготовки дизайну: персони, CJM, JTBD, мудборди та бенчмаркінг

Найдорожча помилка в дизайні — створити бездоганно красивий інтерфейс, який **вирішує неіснуючу проблему або не потрібен жодному реальному користувачу**.

Фаза дослідження (User Research & Discovery) традиційно вимагала тижнів роботи: ручний аналіз сотень коментарів конкурентів, розшифровка інтерв'ю, складання карт шляху користувача (Customer Journey Maps) та підбір візуальних референсів (Moodboards).

Штучний інтелект здійснює революцію на етапі Discovery. Він здатний миттєво синтезувати терабайти інформації, виявити приховані болі аудиторії, згенерувати деталізовані профілі персон за фреймворком **Jobs To Be Done (JTBD)** та підібрати сотні естетичних концепцій за хвилини.

У цьому поглибленому посібнику ми розглянемо:

* автоматизований аналіз конкурентів та відгуків клієнтів (Competitive Benchmarking & Review Mining);
* генерацію дата-орієнтованих персон користувачів (Proto-Personas) та формулювання JTBD-гіпотез;
* побудову детальних карт клієнтського шляху (**Customer Journey Maps / CJM**) з емоційними кривими та точками тертя (Friction Points);
* створення динамічних мудбордів та концепт-арту в Midjourney / DALL-E за професійними дизайн-промптами;
* техніку генерації дизайн-ідей методом «Crazy 8s» за участю AI.

---

## 1. Автоматизований збір інсайтів: Review Mining

Замість того, щоб читати 2,000 відгуків про додатки конкурентів вручну, дизайнер завантажує вивантаження з App Store / Google Play в AI:

```markdown
# ПРОМПТ ДЛЯ REVIEW MINING:
Ти — провідний UX Researcher.
Проаналізуй 500 негативних (1-2 зірки) відгуків про додаток доставки їжі конкурента.

Виділи:
1. ТОП-5 ГОЛОВНИХ ТОЧОК БОЛЮ (Pain Points) користувачів.
2. Емоційні тригери роздратування (де саме користувачі кидають замовлення?).
3. 3 неочевидні можливості для нашого нового додатку: що ми можемо зробити набагато зручніше, щоб забрати цих клієнтів собі?
```

## 2. Фреймворк Jobs To Be Done (JTBD) та Персони

AI допомагає формулювати потреби не за демографією («Олена, 30 років, домогосподарка»), а за реальними життєвими завданнями (**Jobs To Be Done**):

```
  ФОРМУЛА JOBS TO BE DONE (JTBD):
  
  ┌─────────────────────────────────────────────────────────────┐
  │ "КОЛИ [Ситуація / Контекст]..."                            │
  │ "...Я ХОЧУ [Конкретна дія / Мотивація]..."                  │
  │ "...ЩОБ [Очікуваний емоційний та практичний результат]".    │
  └─────────────────────────────────────────────────────────────┘
```

*Приклад:*  
*«Коли я стою в заторі ввечері після важкого робочого дня, я хочу замовити готову вечерю додому у 2 кліки, щоб не думати про готування і відпочити з родиною»*.

## 3. Побудова Customer Journey Map (CJM)

AI миттєво структурує шлях користувача за 5 класичними етапами:

```
+─────────────────────────────────────────────────────────────────────────────────────────+
|                           МАТРИЦЯ КЛІЄНТСЬКОГО ШЛЯХУ (CJM)                              |
+──────────────────+──────────────────+──────────────────+──────────────────+─────────────+
| 1. УСВІДОМЛЕННЯ  | 2. ПОШУК ТА ВИБІР| 3. ОФОРМЛЕННЯ    | 4. ОЧІКУВАННЯ    | 5. СПОЖИВАННЯ|
| (Awareness)      | (Consideration)  | (Checkout)       | (Delivery/Wait)  | (Usage)     |
+──────────────────+──────────────────+──────────────────+──────────────────+─────────────+
| Дія користувача: | Шукає ресторан   | Вводить адресу   | Дивиться трекінг | Їсть страву |
+──────────────────+──────────────────+──────────────────+──────────────────+─────────────+
| Точка тертя:     | Довгий пошук     | Складна форма    | Немає зв'язку з  | Остигла їжа |
| (Pain Point)     | без фільтрів     | введення карти   | кур'єром         |             |
+──────────────────+──────────────────+──────────────────+──────────────────+─────────────+
| UX-Рішення:      | AI-рекомендації  | Apple/Google Pay | Жива карта кур'єра| Термобокс  |
|                  | "Швидко поїсти"  | в 1 клік         | в реальному часі | підтримка   |
+──────────────────+──────────────────+──────────────────+──────────────────+─────────────+
```

## 4. Генерація візуальних мудбордів у Midjourney

Щоб узгодити візуальний стиль із клієнтом до початку роботи у Figma, дизайнер генерує концепт-борди:

```
# ПРОМПТ ДЛЯ MIDJOURNEY:
Mobile banking app UI screen, clean minimal aesthetic, dark mode with neon cyan and lime green accents, sleek frosted glass cards, modern typography, sophisticated finance interface, high quality UI/UX mockup, Dribbble trending, Figma presentation --ar 9:16 --v 6.0
```

---

## Резюме уроку

1. AI прискорює етап **UX Discovery у 5-10 разів**, аналізуючи тисячі відгуків та формуючи точні гіпотези.
2. Фреймворк **Jobs To Be Done (JTBD)** фокусує дизайн на вирішенні реальних життєвих завдань користувачів.
3. Карта шляху клієнта (**CJM**) наочно показує емоційні спади та точки тертя, де дизайн повинен запропонувати простіші рішення.
4. Швидка генерація **мудбордів та референсів у Midjourney** дозволяє затвердити візуальний вектор проекту за один день.

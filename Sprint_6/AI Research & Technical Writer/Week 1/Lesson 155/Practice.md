# Практичні завдання до Уроку 155: Робота з довгими документами

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Створення управлінського Executive Summary з 80-сторінкового аудиторського звіту

**Мета:** Опанувати трансформацію великого масиву технічного тексту у лаконічне керівне резюме за стандартом 5 блоків.

**Вхідний контекст та бізнес-сценарій:**
Зовнішня аудиторська компанія надала великий звіт про відповідність корпоративної хмарної інфраструктури стандарту SOC 2 Type II. Документ перевантажений таблицями та юридичним жаргоном. Керівництву потрібна 1.5-сторінкова вичавка для ради директорів.

**Покроковий алгоритм виконання:**
1. Виділіть ключові розділи звіту: статус проходження аудиту, виявлені вразливості, терміни усунення, бюджет.
2. Сформулюйте бізнес-проблему та статус комплаєнсу.
3. Опишіть 3 критичні виявлені дефекти конфігурації хмари AWS із цифровими оцінками ризиків.
4. Складіть перелік із 4 конкретних рекомендацій із дедлайнами та відповідальними підрозділами.

**Рекомендований системний AI-промпт:**
```text
Дій як Senior Technical Writer & Technology Analyst. Опрацюй вихідні дані аудиторського звіту SOC 2 Type II:
[Контекст: аудит безпеки AWS, виявлено відкриті S3 бакети без шифрування, відсутність обов'язкової 2FA для частини розробників, незахищені бекапи бази даних PostgreSQL].
Склади Executive Summary для СТО та Ради директорів за стандартом:
1. Контекст та мета аудиту (1 абзац).
2. Загальний вердикт (Qualified vs Unqualified opinion).
3. Топ-3 критичні знахідки з оцінкою ризиків для бізнесу.
4. План дій з дедлайнами (таблиця: Ініціатива | Відповідальний | Термін | Бюджет).
Стиль: діловий, лаконічний, жодної 'води'.
```

**Очікуваний результат:**
Готове до презентації Executive Summary обсягом 1.5 сторінки у форматі Markdown.

**Критерії самоперевірки та оцінювання:**
- [ ] Суворе дотримання 5-компонентної структури
- [ ] Повна відсутність канцеляризмів та абстрактних міркувань
- [ ] Чітка таблиця рекомендацій із вимірюваними термінами
- [ ] Точна фіксація ризиків для бізнесу

## Завдання 2: Побудова пайплайну ієрархічного аналізу (Map-Reduce) за допомогою AI

**Мета:** Навчитись розбивати великий документ на сегменти та писати системні промпти для проміжного та підсумкового узагальнення.

**Вхідний контекст та бізнес-сценарій:**
Необхідно проаналізувати щорічний регуляторний звіт про безпеку штучного інтелекту (EU AI Act, 140 сторінок). Спроба надіслати весь файл цілком призводить до поверхневих відповідей.

**Покроковий алгоритм виконання:**
1. Розробіть схему поділу документа на 4 логічні модулі (Класифікація ризиків, Обов'язки провайдерів, Штрафи, Перехідні періоди).
2. Складіть системний промпт для етапу 'Map' (аналіз окремого розділу з фіксацією статей закону).
3. Складіть системний промпт для етапу 'Reduce' (консолідація знахідок у єдину матрицю впливу на компанію).
4. Опишіть чеклист валідації відсутності галюцинацій у фінальному звіті.

**Рекомендований системний AI-промпт:**
```text
Дій як AI Research Architect. Розроби інженерний пайплайн аналізу довгого регуляторного акту (EU AI Act):
1. Опиши стратегію розбиття (Chunking strategy) на логічні розділи.
2. Напиши системний промпт для Map-стадії (витяг вимог високого ступеня ризику, штрафних санкцій та дедлайнів для кожного розділу).
3. Напиши системний промпт для Reduce-стадії (зведення результатів у єдину корпоративну матрицю комплаєнсу).
4. Опиши протокол верифікації (Fact-checking Protocol) для перевірки цитат статей закону.
```

**Очікуваний результат:**
Повноцінний протокол Map-Reduce аналізу документів із готовими текстами промптів.

**Критерії самоперевірки та оцінювання:**
- [ ] Логічна схема сегментації без розриву контексту
- [ ] Професійні системні промпти з чіткими обмеженнями
- [ ] Наявність матриці кінцевого комплаєнсу
- [ ] Методика верифікації вихідних даних проти першоджерела

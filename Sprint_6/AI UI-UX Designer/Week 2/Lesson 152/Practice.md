# Практичні завдання до Уроку 152: Проєктування навігації

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Проєктування адаптивної навігаційної системи для B2B SaaS платформи

**Мета:** Навчитись створювати специфікацію навігаційної системи з підтримкою десктопного сайдбара та мобільного таб-бару.

**Вхідний контекст та бізнес-сценарій:**
Хмарна ERP-система для логістики містить 12 функціональних модулів (Замовлення, Склад, Водії, Фінанси, Аналітика, Налаштування тощо). Необхідно спроєктувати ергономічну систему навігації для менеджерів на десктопі та водіїв на смартфонах.

**Покроковий алгоритм виконання:**
1. Розподіліть 12 модулів на первинні (щоденні) та вторинні (адміністративні).
2. Спроєктуйте десктопний дворівневий сайдбар з можливістю згортання в компактний режим.
3. Спроєктуйте мобільний Bottom Navigation Bar на 4 ключові модулі з винесенням решти в панель 'Більше'.
4. Опишіть логіку станів активності, підсвічування та переходу між рівнями.

**Рекомендований системний AI-промпт:**
```text
Дій як Principal Product Designer. Склади специфікацію навігаційної системи для логістичної ERP-платформи:
Модулі: Замовлення, Маршрути, Склад, Водії, Документи, Рахунки, Аналітика, Сповіщення, Клієнти, Інтеграції, Користувачі, Налаштування компанії.
Вимоги:
1. Десктоп: Вертикальний лівий сайдбар з групуванням модулів на секції (Операційна діяльність, Фінанси, Адміністрування) та режимом згортання.
2. Мобільна версія: Нижній таб-бар на 4 головні дії водія + вкладка 'Меню'.
3. Склади опис у Mermaid.js або текстову специфікацію навігаційних станів (Default, Hover, Active, Expanded).
4. Опиши доступність: роботу клавіші Tab, комбінації стрілок для переходу між вкладками та Focus ring.
```

**Очікуваний результат:**
Комплексний документ навігаційної специфікації з десктопною та мобільною адаптацією.

**Критерії самоперевірки та оцінювання:**
- [ ] Логічне групування 12 модулів без інформаційного перевантаження
- [ ] Чітке розділення сценаріїв офісного менеджера та водія на мобільному
- [ ] Дотримання ергономіки зони великого пальця (Thumb Zone)
- [ ] Врахування вимог доступності WCAG 2.2 для клавіатурної навігації

## Завдання 2: Аудит та редизайн навігації маркетплейсу з оптимізацією Breadcrumbs

**Мета:** Опанувати редизайн хлібних крихт та контекстних навігаційних посилань для інтернет-магазину зі складною таксономією.

**Вхідний контекст та бізнес-сценарій:**
На сторінці товару 'Бездротові навушники Sony WH-1000XM5' користувачі скаржаться, що не можуть повернутися до загального списку навушників бренду Sony або знайти аксесуари (амбушури). Поточні крихти обриваються на категорії верхнього рівня.

**Покроковий алгоритм виконання:**
1. Проаналізуйте поточний шлях навігації: `Головна > Каталог`.
2. Розробіть повний ланцюжок таксономічних хлібних крихт.
3. Додайте контекстні блоки переходу: 'Інші навушники бренду Sony', 'Супутні чохли та кабелі'.
4. Опишіть поведінку крихт на мобільних пристроях (обрізка або горизонтальний скрол).

**Рекомендований системний AI-промпт:**
```text
Дій як Staff UX Architect. Проведи редизайн навігації для сторінки товару електроніки:
1. Спроєктуй повний ланцюжок хлібних крихт (Breadcrumbs) від кореня до поточної моделі товару.
2. Опиши правила адаптивності хлібних крихт на мобільному екрані шириною 375px (як уникнути перенесення на 4 рядки).
3. Спроєктуй блок контекстної навігації на сторінці товару для швидкого переходу між суміжними підкатегоріями.
4. Опиши розмітку Schema.org BreadcrumbList для пошукових роботів Google.
```

**Очікуваний результат:**
Специфікація оновленої системи хлібних крихт та контекстної навігації зі схемою SEO-розмітки.

**Критерії самоперевірки та оцінювання:**
- [ ] Елегантне рішення мобільного відображення крихт без visual clutter
- [ ] Коректна логіка активного та неактивного стану кінцевої крихти
- [ ] Зв'язок структурної та контекстної навігації
- [ ] Валідна JSON-LD розмітка Schema.org для SEO

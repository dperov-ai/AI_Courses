# Практичні завдання до Уроку 154: Виявлення нетипових і граничних сценаріїв взаємодії

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Побудова матриці станів (State Matrix) для компонента оплати замовлення

**Мета:** Опанувати повне проєктування 9 станів інтерфейсу для критичного бізнес-віджета.

**Вхідний контекст та бізнес-сценарій:**
Необхідно спроєктувати віджет швидкої оплати замовлення банківською карткою, охопивши всі нештатні ситуації: відхилення банком, нестача коштів, таймаут 3D-Secure, відсутність зв'язку та подвійний клік.

**Покроковий алгоритм виконання:**
1. Опишіть Default та Active стани віджета.
2. Спроєктуйте стан завантаження (Loading) з блокуванням кнопки проти повторного кліку.
3. Опишіть 3 сценарії помилок: банківська відмова, таймаут шлюзу, офлайн клієнта.
4. Для кожного стану помилки запропонуйте людиноорієнтоване повідомлення та кнопку дії виходу.

**Рекомендований системний AI-промпт:**
```text
Дій як Staff Product Designer. Створи вичерпну матрицю станів (UI State Matrix) для компонента оплати замовлення:
Покриття обов'язкових станів:
1. Default: Початковий вигляд з вибором збереженої картки.
2. In Progress / Loading: Спінер на кнопці, захист від подвійного кліку.
3. User Error: Недостатньо коштів на балансі (з дією поповнення або вибору іншої картки).
4. Gateway Timeout: Банківський шлюз не відповів за 30 секунд (з кнопкою 'Спробувати знову' без повторного списання).
5. Offline / Network Lost: Зник інтернет під час транзакції.
6. Success: Анімація успіху та номер чека.
Опиши кожен стан: візуальні елементи, колірне кодування, текст повідомлення, CTA кнопка.
```

**Очікуваний результат:**
Аналітична таблиця або структурований документ специфікації станів платіжного компонента.

**Критерії самоперевірки та оцінювання:**
- [ ] Опис усіх 6 зазначених станів без пропусків
- [ ] Людиноорієнтовані формулювання без системного сленгу
- [ ] Наявність конструктивного виходу (Actionable CTA) у кожній помилці
- [ ] Врахування захисту від подвійного кліку та стану офлайн

## Завдання 2: Стрес-тестування сценарію бронювання квитків за допомогою AI 'Devil's Advocate'

**Мета:** Навчитись використовувати генеративний AI для виявлення прихованих Edge та Corner Cases.

**Вхідний контекст та бізнес-сценарій:**
Команда розробила сценарій вибору місць та покупки квитків у кінотеатрі. Здається, що все враховано. Потрібно задіяти AI для генерації 10 екстремальних ситуацій взаємодії.

**Покроковий алгоритм виконання:**
1. Опишіть стандартний 4-кроковий сценарій купівлі квитка.
2. Складіть системний промпт для AI в ролі зловмисного тестувальника надійності.
3. Згенеруйте 10 нетипових сценаріїв (одночасний викуп місця іншим користувачем, зміна сеансу, відкат транзакції тощо).
4. Спроєктуйте UX-рішення для трьох найбільш критичних знайдених кейсів.

**Рекомендований системний AI-промпт:**
```text
Дій як Principal QA & UX Stress Tester. Проведи стрес-аудит сценарію онлайн-купівлі квитків у кінотеатр:
Сценарій: Вибір фільму -> Вибір сеансу -> Вибір місць на схемі зали (блокування на 10 хв) -> Оплата карткою -> Отримання QR-квитка.
Завдання:
1. Сформулюй 10 екстремальних крайових та кутових випадків (Edge & Corner Cases), які можуть зламати користувацький досвід або викликати подвійний продаж.
2. Для 3 найнебезпечніших кейсів (наприклад, сплив таймауту бронювання за 2 секунди до підтвердження оплати банком) запропонуй детальні UX-сценарії розв'язання проблеми з текстами інтерфейсу та алгоритмом дій системи.
```

**Очікуваний результат:**
Звіт стрес-аудиту з переліком 10 ризикових сценаріїв та детальним UX-описом виходу з 3 критичних колізій.

**Критерії самоперевірки та оцінювання:**
- [ ] Глибокі, реалістичні технічні та поведінкові кейси (таймаути, паралельні транзакції)
- [ ] Спроєктовані рішення захищають інтереси користувача та гроші бізнесу
- [ ] Зрозумілі текстові повідомлення інтерфейсу
- [ ] Відсутність тупикових станів для покупця

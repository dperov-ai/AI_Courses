# Практичні завдання до Уроку 151: Організація інформації та структури продукту

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Розробка карти сайту (Sitemap) та таксономії для медичного порталу

**Мета:** Навчитись проєктувати багаторівневу інформаційну архітектуру за допомогою нотації Mermaid.js.

**Вхідний контекст та бізнес-сценарій:**
Приватна клініка створює пацієнтський портал. Необхідно структурувати контент: запис до лікарів, перегляд аналізів, телемедицина, аптека, блог про здоров'я та фінансові звіти про оплати.

**Покроковий алгоритм виконання:**
1. Визначте 4-5 ключових розділів глобальної навігації верхнього рівня.
2. Декомпозуйте розділи на підкатегорії 2-го та 3-го рівнів.
3. Визначте типи доступу для кожної сторінки (Public vs Private Patient Area).
4. Опишіть карту сайту у вигляді графа Mermaid.js.

**Рекомендований системний AI-промпт:**
```text
Дій як Principal Information Architect. Створи інформаційну архітектуру для цифрового медичного порталу 'HealthHub':
Вимоги:
1. Виділи глобальні розділи: Лікарі та послуги, Онлайн-запис, Особистий кабінет пацієнта, Аптека/Препарати, База знань.
2. Деталізуй Особистий кабінет: Електронна медична картка, Результати лабораторних досліджень, Історія візитів, План лікування, Фінанси та страховка.
3. Опиши структуру за допомогою діаграми Mermaid.js (graph TD).
4. Надай обґрунтування вибору назв розділів (Labeling) відповідно до мови пацієнтів, а не внутрішнього медичного жаргону.
```

**Очікуваний результат:**
Валідна діаграма Mermaid.js та супровідний документ таксономії з обґрунтуванням системи маркування.

**Критерії самоперевірки та оцінювання:**
- [ ] Дотримання балансу глибини та ширини ієрархії (не більше 3 рівнів вглиб)
- [ ] Використання пацієнтоорієнтованих назв (Labeling)
- [ ] Логічне розділення публічного та захищеного контенту
- [ ] Повна валідність коду Mermaid

## Завдання 2: Проєктування та аналіз плану тестування дерева (Tree Testing Protocol)

**Мета:** Опанувати методику підготовки та аналізу Tree Testing для перевірки спроєктованої структури контенту.

**Вхідний контекст та бізнес-сценарій:**
Команда розробила нову структуру налаштувань безпеки фінансового додатку. Потрібно перевірити, чи зможуть користувачі знайти розділ налаштування біометрії (FaceID) та екстреного відкликання сесій з інших пристроїв.

**Покроковий алгоритм виконання:**
1. Підготуйте текстове дерево розділів налаштувань додатку.
2. Сформулюйте 3 реалістичні завдання для респондентів без використання слів-підказок.
3. Визначте очікувані шляхи успіху (Optimal Paths) для кожного завдання.
4. Опишіть метрики оцінки: Success Rate, Directness, Time on Task.

**Рекомендований системний AI-промпт:**
```text
Дій як Lead UX Researcher. Склади протокол тестування дерева (Tree Testing) для перевірки інформаційної архітектури розділу 'Безпека та акаунт':
Дерево:
- Мій профіль
  - Персональні дані
  - Документи
- Налаштування входу
  - Зміна пароля
  - Двоетапна автентифікація
  - Біометричний доступ
- Безпека та пристрої
  - Активні сесії
  - Журнал підозрілих дій
  - Блокування доступу
Завдання:
1. Сформулюй 3 тестові завдання для респондентів (без прямих слів 'біометрія' чи 'сесії' в умові).
2. Зазнач еталонний шлях для кожного завдання.
3. Опиши, які результати вважатимуться провалом структури та потребуватимуть зміни назв розділів.
```

**Очікуваний результат:**
Готовий до запуску протокол Tree Testing з аналітичними критеріями оцінки.

**Критерії самоперевірки та оцінювання:**
- [ ] Завдання сформульовані мовою життєвих потреб без підказок у тексті
- [ ] Визначено точні оптимальні шляхи в дереві
- [ ] Зафіксовано порогові значення метрик успіху (наприклад, Success > 80%, Directness > 70%)
- [ ] Описано план дій у разі виявлення блукань користувачів

# Контрольні запитання до Уроку 169: Use Case та сценарії використання

Даний блок містить перелік запитань для самоконтролю, перевірки глибини засвоєння матеріалу та самостійної підготовки.

---

1. Хто є автором концепції Use Case (Прецедент використання) і в якому році вона з'явилася?

2. У чому полягає фундаментальна відмінність між User Story та Use Case?

3. Хто такий 'Первинний актор' (Primary Actor) у специфікації Use Case?

4. Хто такий 'Вторинний актор' (Secondary / Supporting Actor)?

5. Що таке Передумова (Precondition) у специфікації прецеденту?

6. У чому різниця між відношеннями `<<include>>` та `<<extend>>` на UML-діаграмі прецедентів?

7. Що описує розділ 'Мінімальні гарантії' (Minimal Guarantees) за стандартом Алістера Кокберна?

8. Чому назва Use Case обов'язково повинна починатися з дієслова в активному стані?

9. Що таке System Boundary (Межа системи) на UML діаграмі прецедентів?

10. Чим корисний двоколонковий формат опису основного сценарію Use Case?

11. Що таке Extension Point (Точка розширення) у зв'язку `<<extend>>`?

12. Чи може інша програмна система або фоновий таймер бути Актором?

13. Коли в проєкті варто писати повноформатні Use Cases замість легких User Stories?

14. Як Use Case допомагає в проєктуванні архітектури мікросервісів?

15. Що таке 'Основний успішний потік' (Main Success Scenario / Happy Path)?

16. Як AI допомагає трансформувати складний Use Case у набір User Stories для спринту?

17. Чому графічна UML-діаграма прецедентів не замінює текстову специфікацію Use Case?

18. Що таке постумова успіху (Success Guarantees)?

19. Як визначити рівень масштабу Use Case (Концепція морських рівнів Кокберна)?

20. Який головний критерій повноти та якості специфікації Use Case?

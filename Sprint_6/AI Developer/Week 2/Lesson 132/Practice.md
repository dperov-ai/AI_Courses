# Практичні завдання до Уроку 132: Створення сторінок та компонентів інтерфейсу

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Проєктування дизайн-системи та розробка сімейства компонентів картки (Card)

**Мета:** Створити масштабований компонент картки згідно з методологією Atomic Design та патерном Compound Components.

**Вхідний контекст та бізнес-сценарій:**
Необхідно реалізувати гнучкий компонент картки для платформи, що підтримує заголовки, опис, медіа-блок, бейджі та блок дій.

**Покроковий алгоритм виконання:**
1. Визначте дизайн-токени для карток: колір фону, радіус заокруглення (border-radius), тіні (box-shadow) через CSS змінні.
2. Розробіть базовий контейнер `Card`, а також дочірні компоненти: `Card.Header`, `Card.Body`, `Card.Footer`, `Card.Image`.
3. Реалізуйте стилізацію з підтримкою варіантів відображення: `variant='elevated'`, `variant='outlined'`, `variant='flat'`.
4. Забезпечте правильні семантичні теги (`<article>`, `<header>`, `<footer>`) та доступність клавіатурного фокусу при клікабельності всієї картки.

**Рекомендований системний AI-промпт:**
```text
Створи гнучкий компонент картки на TypeScript/React (або чистому Web Components) з використанням патерну Compound Components. Опиши Card, Card.Header, Card.Body, Card.Footer. Застосуй чисті CSS змінні та семантичну розмітку article.
```

**Очікуваний результат:**
Повноцінний код компонента з детальними інтерфейсами TypeScript та прикладом використання у дашборді.

**Критерії самоперевірки та оцінювання:**
- [ ] Чиста компонентна композиція без props drilling
- [ ] Семантична відповідність розмітки вимогам a11y
- [ ] Гнучка кастомізація через варіанти та токени

## Завдання 2: Рефакторинг монолітної спагеті-сторінки у дерево атомів та молекул

**Мета:** Розбити неструктурований HTML-код сторінки профілю на чисту компонентну ієрархію.

**Вхідний контекст та бізнес-сценарій:**
У спадковій кодовій базі знайдено файл розміром 800 рядків div-верстки, де змішано логіку аватара, форми зміни пароля та списку сесій.

**Покроковий алгоритм виконання:**
1. Проведіть аудит розмітки та виділіть атоми: `Avatar`, `Badge`, `TextField`, `PrimaryButton`.
2. Згрупуйте атоми у функціональні молекули: `UserBioCard`, `PasswordChangeForm`, `SessionItem`.
3. Створіть головний організм `ProfileSettingsOrganism` та шаблон сторінки.
4. Сформулюйте контракт Props для кожного виділеного компонента з суворою типізацією.

**Рекомендований системний AI-промпт:**
```text
Ти — Frontend Architect. Проаналізуй спагеті-код сторінки налаштувань користувача і запропонуй чітку компонентну декомпозицію за методологією Atomic Design: виділи атоми, молекули та організми з описом їх Props інтерфейсів.
```

**Очікуваний результат:**
Архітектурна діаграма та набір типізованих інтерфейсів для кожного виділеного компонента.

**Критерії самоперевірки та оцінювання:**
- [ ] Повне дотримання принципу Single Responsibility
- [ ] Чітке розмежування обов'язків між молекулами та організмами
- [ ] Готовність компонентів до повторного використання

# Практичні завдання до Уроку 129: Принципи роботи вебзастосунків

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Глибокий аудит Critical Rendering Path за допомогою Chrome DevTools

**Мета:** На практиці дослідити та розрахувати мережеві фази запиту (DNS, TCP, TLS, TTFB) і виявити блокуючі ресурси.

**Вхідний контекст та бізнес-сценарій:**
Enterprise SaaS платформа фіксує падіння конверсії через повільне перше відображення дашборду. Необхідно провести профілювання.

**Покроковий алгоритм виконання:**
1. Відкрийте вкладку Network у DevTools та увімкніть емуляцію Slow 4G та 'Disable cache'.
2. Виконайте перезавантаження сторінки та знайдіть головний HTML-документ.
3. Проаналізуйте таймінги: Queuing, DNS Lookup, Initial Connection, SSL, TTFB, Content Download.
4. Знайдіть стилі та скрипти, які блокують перший рендер (render-blocking), зафіксуйте метрики FCP та LCP у вкладці Performance.

**Рекомендований системний AI-промпт:**
```text
Ти — Senior Performance Engineer. Проаналізуй наступні показники завантаження HTML:
DNS: 90ms, TCP: 140ms, TLS: 120ms, TTFB: 820ms, Download: 30ms.
Запропонуй технічний план оптимізації TTFB та CRP з використанням HTTP/3, CDN Edge caching та оптимізації SQL-запитів.
```

**Очікуваний результат:**
Детальний інженерний звіт з архітектурними рекомендаціями щодо усунення блокування рендерингу та прискорення TTFB.

**Критерії самоперевірки та оцінювання:**
- [ ] Правильно розраховано сумарний час мережевого рукостискання
- [ ] Ідентифіковано різницю між затримкою мережі та часом генерації на сервері (TTFB)
- [ ] Складено перелік превентивних заходів для оптимізації Critical Rendering Path

## Завдання 2: Проєктування захищеної політики CORS та CSP для багаторівневого вебзастосунку

**Мета:** Створити зразкову конфігурацію HTTP-заголовків безпеки для веб-сервера з відокремленим SPA та API.

**Вхідний контекст та бізнес-сценарій:**
Frontend розгорнуто на `https://app.fintech.ua`, а бекенд API працює на `https://api.fintech.ua`. Необхідно дозволити обмін авторизаційними cookies та заблокувати XSS-загрози.

**Покроковий алгоритм виконання:**
1. Складіть перелік заголовків CORS для API: Access-Control-Allow-Origin, Allow-Credentials, Allow-Methods, Allow-Headers.
2. Спроєктуйте політику Content-Security-Policy (CSP), яка дозволяє завантаження скриптів лише з власного домену та забороняє eval().
3. Налаштуйте прапорці безпеки для сесійних Cookie: Secure, HttpOnly, SameSite=Lax.

**Рекомендований системний AI-промпт:**
```text
Створи production-ready конфігурацію заголовків безпеки для Nginx, включаючи строгий CSP, HSTS на 2 роки з preload, захист від clickjacking (X-Frame-Options: DENY) та надійний CORS для клієнта https://app.fintech.ua.
```

**Очікуваний результат:**
Повний конфігураційний файл Nginx з детальними коментарями щодо кожного заголовка безпеки.

**Критерії самоперевірки та оцінювання:**
- [ ] Відсутність небезпечних wildcard '*' у комбінації з credentials
- [ ] Коректний синтаксис директив CSP
- [ ] Повне розуміння захисту від XSS та CSRF

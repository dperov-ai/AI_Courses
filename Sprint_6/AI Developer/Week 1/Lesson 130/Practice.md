# Практичні завдання до Уроку 130: Клієнтська та серверна частини застосунку

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Проєктування REST API контракту та DTO-валідації для системи замовлень

**Мета:** Розробити специфікацію API ендпоінтів для інтернет-магазину та створити схему валідації вхідних даних.

**Вхідний контекст та бізнес-сценарій:**
Команда розробляє мікросервіс оформлення замовлень. Необхідно чітко розмежувати обов'язки клієнта і сервера та описати JSON-контракти.

**Покроковий алгоритм виконання:**
1. Визначте ресурси та HTTP-методи: `POST /api/v1/orders`, `GET /api/v1/orders/{id}`, `PATCH /api/v1/orders/{id}/status`.
2. Опишіть структуру тіла запиту на створення замовлення (товари, кількість, адреса доставки, спосіб оплати).
3. Створіть схему валідації бекенду на базі Zod або Pydantic з обов'язковими обмеженнями (ціна > 0, кількість >= 1, валідний email).
4. Спроєктуйте структуру відповідей при успіху (201 Created) та помилці валідації (422 Unprocessable Entity).

**Рекомендований системний AI-промпт:**
```text
Ти — Lead Backend Architect. Створи строгу схему валідації замовлення за допомогою бібліотеки Zod (TypeScript) для ендпоінта POST /api/orders. Включи валідацію вкладених масивів товарів, санітизацію текстових полів від XSS та опис кодів помилок HTTP.
```

**Очікуваний результат:**
Готовий код валідаційного модулю TypeScript з повною типізацією DTO та прикладом обробника помилок для клієнта.

**Критерії самоперевірки та оцінювання:**
- [ ] Правильне використання статусів HTTP (201, 400, 422)
- [ ] Коректна обробка граничних значень у схемі валідації
- [ ] Ізоляція доменної моделі від клієнтського представлення

## Завдання 2: Реалізація стрімінгу даних між сервером і клієнтом через Server-Sent Events (SSE)

**Мета:** Створити міні-сервіс, який транслює текстовий потік у реальному часі від бекенду до браузера.

**Вхідний контекст та бізнес-сценарій:**
Необхідно реалізувати інтерфейс генерації тексту AI, де відповідь з'являється по словах у реальному часі без перезавантаження.

**Покроковий алгоритм виконання:**
1. Створіть простий серверний обробник (Node.js/Express або Python/FastAPI) для ендпоінта `/api/stream` із заголовком `Content-Type: text/event-stream`.
2. Налаштуйте відправку порцій даних кожні 200 мс у форматі `data: {chunk}\n\n`.
3. На клієнті використовуйте стандартний API `EventSource` для підключення до потоку та динамічного додавання тексту в DOM.
4. Реалізуйте коректне закриття з'єднання після завершення генерації.

**Рекомендований системний AI-промпт:**
```text
Напиши повноцінний приклад роботи з Server-Sent Events (SSE): мінімальний бекенд на Node.js/Express, що стрімить випадковий текст кожні 150мс, та клієнтський JS код з обробкою подій onmessage, onerror та закриттям з'єднання.
```

**Очікуваний результат:**
Працююча пара серверного та клієнтського скриптів із детальними коментарями щодо буферизації та CORS-заголовків.

**Критерії самоперевірки та оцінювання:**
- [ ] Правильне встановлення заголовків Cache-Control: no-cache та text/event-stream
- [ ] Коректна робота клієнтського EventSource
- [ ] Обробка обриву мережевого з'єднання

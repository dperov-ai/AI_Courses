# Практичні завдання до Уроку 144: Actions та Assertions

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

## Завдання 1: Побудова надійного сценарію заповнення багатоетапної форми

**Мета:** Опанувати повний спектр дій введення (fill, selectOption, check, setInputFiles) та Web-First Assertions.

**Вхідний контекст та бізнес-сценарій:**
Необхідно протестувати форму створення резюме: ім'я, стать (radio), навички (checkboxes), країна проживання (select), завантаження фотографії профілю та відправка форми.

**Покроковий алгоритм виконання:**
1. Відкрийте сторінку форми створення профілю.
2. Заповніть текстові поля за допомогою `.fill()`.
3. Виберіть стать за допомогою `.check()`.
4. Виберіть країну зі спадного списку за допомогою `.selectOption()`.
5. Завантажте тестовий аватар через `.setInputFiles()`.
6. Натисніть кнопку відправки та перевірте успішне створення профілю через `.toBeVisible()`.

**Рекомендований системний AI-промпт:**
```text
Дій як Senior SDET. Напиши тест на TypeScript для Playwright, який тестує створення анкети користувача:
URL: /onboarding/profile
Поля форми:
- Текстове поле 'Повне ім'я' (Label) -> ввести 'Марія Квітка'
- Радіокнопка 'Жіноча' (getByRole 'radio') -> check()
- Прапорець 'Погоджуюсь з правилами' (getByRole 'checkbox') -> check()
- Селект 'Країна' (getByLabel 'Країна') -> вибрати 'Україна' (код 'UA')
- Поле завантаження файлу (input[type='file']) -> завантажити файл 'tests/fixtures/avatar.png'
- Кнопка 'Зберегти профіль' -> click()
Перевірки:
1. URL змінився на /onboarding/success.
2. Повідомлення 'Анкету успішно надіслано' видиме.
Вимоги: виключно Web-first assertions.
```

**Очікуваний результат:**
Повноцінний тест Playwright із правильним використанням усіх типів дій та асертів.

**Критерії самоперевірки та оцінювання:**
- [ ] Коректне використання check() замість звичайного click() для radio та checkbox
- [ ] Правильне завантаження файлу через setInputFiles
- [ ] Використання toHaveURL та toBeVisible
- [ ] Чистий TypeScript код без помилок

## Завдання 2: Реалізація валідації дашборду за допомогою Soft Assertions

**Мета:** Навчитись застосовувати `expect.soft()` для комплексної перевірки показників аналітичного віджета.

**Вхідний контекст та бізнес-сценарій:**
На фінансовому дашборді відображається 6 ключових метрик (Баланс, Дохід, Витрати, Активні користувачі, Конверсія, Відтік). Необхідно перевірити всі 6 показників, зібравши повний звіт про розбіжності за один прогін тесту.

**Покроковий алгоритм виконання:**
1. Створіть тестовий сценарій перевірки віджета аналітики.
2. Використайте `expect.soft()` для кожної з 6 метрик.
3. Додайте кастомні текстові описи до кожного твердження для зручності аналізу звіту.
4. Переконайтесь, що тест продовжує перевірку навіть у разі падіння першої метрики.

**Рекомендований системний AI-промпт:**
```text
Дій як Lead Automation Engineer. Напиши тест на TypeScript для Playwright, що демонструє використання Soft Assertions:
Сторінка: /dashboard/finances
Необхідно перевірити 4 показники:
1. Загальний баланс: має дорівнювати '₴ 1,250,000'
2. Кількість операцій: має дорівнювати '342'
3. Статус підписки: має містити 'Active Enterprise'
4. Індикатор ризику: повинен мати атрибут data-risk зі значенням 'low'
Вимоги:
- Використовуй `expect.soft` з описовими повідомленнями українською мовою.
- Забезпеч, щоб падіння першого показника не блокувало перевірку решти трьох.
```

**Очікуваний результат:**
Тест на Playwright з використанням expect.soft та кастомними повідомленнями.

**Критерії самоперевірки та оцінювання:**
- [ ] Використано виключно expect.soft для метрик
- [ ] Кожен асерт має зрозуміле людиночитне повідомлення про помилку
- [ ] Правильно використано toHaveText, toContainText та toHaveAttribute
- [ ] Дотримано архітектурні стандарти написання тестів

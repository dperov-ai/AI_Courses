## Завдання 1: Рефакторинг нестабільних XPath/CSS локаторів у семантичні Playwright Locators

**Мета:** Опанувати трансформацію крихких технічних селекторів у надійні, орієнтовані на доступність локатори.

**Вхідний контекст та бізнес-сценарій:**
У спадковому проєкті (legacy codebase) набір автотестів містить понад 20 падінь щотижня через редизайн стилів. Вам передано фрагмент HTML-розмітки картки товару та старі тести. Необхідно провести повний рефакторинг.

**Покроковий алгоритм виконання:**
1. Проаналізуйте наданий фрагмент HTML-розмітки каталогу інтернет-магазину.
2. Знайдіть крихкі селектори: `//div[@class='item-382']/div[2]/button`, `.btn-checkout-v2`.
3. Перепишіть локатори з використанням `getByRole`, `getByLabel` та фільтрації контейнерів.
4. Перевірте усунення порушень Strict Mode шляхом ланцюжкового звуження контексту.

**Рекомендований системний AI-промпт:**
```text
Дій як Senior SDET. Проведи рефакторинг наступних застарілих локаторів:
1. `page.locator('//div[@id="main"]/div[1]/form/div[2]/input')` -> Поле введення корпоративного email.
2. `page.locator('.btn-red-style-rounded.w-full')` -> Кнопка 'Видалити акаунт'.
3. `page.locator('//table/tbody/tr[3]/td[4]/a')` -> Посилання 'Деталі' у рядку користувача 'Іван Франко'.
Запропонуй сучасні еквіваленти Playwright з поясненням, чому саме такий підхід гарантує стійкість до змін у верстці.
```

**Очікуваний результат:**
Оновлений фрагмент коду TypeScript із сучасними локаторами та детальним інженерним поясненням вибору кожного з них.

**Критерії самоперевірки та оцінювання:**
- [ ] Використано виключно getByRole, getByLabel або filter
- [ ] Повна відсутність абсолютних XPath та утилітарних класів
- [ ] Для рядка таблиці використано фільтрацію за контекстом тексту
- [ ] Обґрунтовано вибір з точки зору принципів W3C WAI-ARIA

## Завдання 2: Побудова складного фільтра для таблиці замовлень

**Мета:** Навчитись використовувати методи `.filter({ hasText, has })` для точного вибору динамічних рядків даних.

**Вхідний контекст та бізнес-сценарій:**
На сторінці кабінету адміністратора відображається таблиця з 50 замовленнями. Необхідно знайти замовлення з номером `#84920`, яке має статус 'Очікує оплати', та натиснути кнопку 'Надіслати нагадування', не зачепивши інші рядки.

**Покроковий алгоритм виконання:**
1. Створіть базовий локатор рядків таблиці за допомогою `page.getByRole('row')`.
2. Застосуйте перший рівень фільтрації за номером замовлення `#84920`.
3. Застосуйте другий рівень фільтрації за наявністю статусу або кнопки дії.
4. Виконайте клік по кнопці дії всередині відфільтрованого рядка та додайте асерт оновлення статусу.

**Рекомендований системний AI-промпт:**
```text
Дій як Lead Automation Engineer. Напиши тест на TypeScript для Playwright:
Сторінка: /admin/orders
Завдання:
1. Знайти рядок таблиці, який одночасно містить номер '#84920' та бейдж зі статусом 'Очікує оплати'.
2. Переконатися, що рядок містить кнопку 'Надіслати нагадування', та клікнути по ній.
3. Перевірити, що після кліку статус змінюється на 'Нагадування надіслано'.
Вимоги:
- Використовуй getByRole('row') та метод .filter().
- Забезпеч суворе дотримання Strict Mode без використання жорстких індексів nth(x).
```

**Очікуваний результат:**
Тестовий сценарій Playwright, що демонструє багатоетапну фільтрацію та асерт результату.

**Критерії самоперевірки та оцінювання:**
- [ ] Коректне використання page.getByRole('row').filter()
- [ ] Відсутність прив'язки до статичних номерів індексів рядків
- [ ] Використання web-first асерту expect(locator).toHaveText()
- [ ] Повний захист від Strict Mode Violation

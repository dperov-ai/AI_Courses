# Практичні завдання до Уроку 148: Створення UI-автотестів за допомогою AI

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Створення виробничого промпту та генерація повного Page Object набору

**Мета:** Опанувати написання високоточних інженерних системних промптів для генерації тестового коду за стандартами Playwright.

**Вхідний контекст та бізнес-сценарій:**
Вам надано розмітку складної форми оформлення кредиту (поля: сума кредиту, термін у місяцях, офіційне працевлаштування, згода з БКІ). Необхідно скласти системний промпт, згенерувати за його допомогою POM-клас на TypeScript та провести його аудит.

**Покроковий алгоритм виконання:**
1. Складіть системний промпт за 5-компонентною моделлю (Роль, Контекст, Дані, Обмеження, Артефакт).
2. Згенеруйте клас `LoanApplicationPage.ts` з використанням семантичних локаторів.
3. Згенеруйте тестовий сценарій `loan.spec.ts` з позитивним потоком та перевіркою валідації мінімальної суми.
4. Проведіть інженерне рев'ю згенерованого коду: перевірте відсутність waitForTimeout, force-кліків та наявність строгих типів.

**Рекомендований системний AI-промпт:**
```text
Дій як Staff SDET. Розглянь наступний HTML фрагмент форми кредитного калькулятора:
<section aria-labelledby="calc-title">
  <h2 id="calc-title">Кредитний калькулятор</h2>
  <label for="amount">Сума кредиту (від 5 000 до 200 000 грн)</label>
  <input id="amount" type="number" min="5000" max="200000" />
  <label for="term">Термін (місяців)</label>
  <select id="term"><option value="6">6 місяців</option><option value="12">12 місяців</option></select>
  <label><input type="checkbox" name="employed" /> Офіційно працевлаштований</label>
  <button type="button">Розрахувати щомісячний платіж</button>
  <div role="status" id="monthly-payment">Очікуваний платіж: 0 грн</div>
</section>

Згенеруй:
1. Типізований клас Page Object `LoanCalculatorPage.ts` для Playwright.
2. Тест на TypeScript із перевіркою розрахунку платежу для суми 50 000 грн на 12 місяців.
3. Дотримуйся вимог: семантичні локатори, web-first assertions, відсутність жорстких пауз.
```

**Очікуваний результат:**
Документ із детальним системним промптом, згенерованим класом Page Object та файлом тестів.

**Критерії самоперевірки та оцінювання:**
- [ ] Промпт містить усі 5 обов'язкових компонентів
- [ ] Клас Page Object використовує getByRole, getByLabel без технічних селекторів
- [ ] Тест написаний за структурою AAA з перевіркою ролі status
- [ ] Повна відсутність антипатернів (waitForTimeout, force click)

## Завдання 2: Діагностика падіння тесту за логом та усунення race condition за допомогою AI

**Мета:** Навчитись використовувати AI для Root Cause Analysis реального дефекту розсинхронізації у тестовому сценарії.

**Вхідний контекст та бізнес-сценарій:**
Тест перевірки кошика падає у нічному прогоні з помилкою: `Error: locator.click: Target closed. Call log: waiting for locator('button.checkout-btn')`. Необхідно передати стек-трейс та контекст у AI, виявити справжню причину падіння та реалізувати надійне виправлення.

**Покроковий алгоритм виконання:**
1. Проаналізуйте наданий лог падіння тесту та стек викликів Playwright.
2. Сформулюйте запит до AI на проведення Root Cause Analysis.
3. Виявіть дві потенційні причини: закриття сторінки через попереднє падіння навігації або перекриття елемента ререндерингом React.
4. Реалізуйте виправлений тестовий сценарій із використанням `Promise.all` та очікування відповіді API.

**Рекомендований системний AI-промпт:**
```text
Дій як QA Automation Architect. Проведи Root Cause Analysis наступного падіння тесту Playwright:
Лог:
```text
Error: locator.click: Test timeout of 30000ms exceeded.
Call log:
  - waiting for getByRole('button', { name: 'Підтвердити замовлення' })
  - locator resolved to <button disabled class="btn-primary">Підтвердити замовлення</button>
  - unexpected value "disabled"
  - element was not enabled for 29800ms
```
Контекст: кнопка залишається disabled, доки бекенд не поверне відповідь на розрахунок вартості доставки /api/delivery/calculate.
1. Поясни причину зависання тесту.
2. Запропонуй виправлений фрагмент коду з правильною синхронізацією через очікування відповіді мережі.
```

**Очікуваний результат:**
Аналітичний висновок щодо причин виникнення розсинхронізації та виправлений фрагмент коду Playwright.

**Критерії самоперевірки та оцінювання:**
- [ ] Точна ідентифікація блокування кнопки атрибутом disabled через повільний бекенд
- [ ] Виправлення через очікування завершення API запиту перед взаємодією з кнопкою
- [ ] Коректний синтаксис waitForResponse
- [ ] Усунення потенційного повторного виникнення Flakiness

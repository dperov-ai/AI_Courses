# Контрольні запитання до Уроку 146: Page Object Model

Даний блок містить перелік аналітичних та практичних запитань для самоконтролю, перевірки глибини засвоєння матеріалу та підготовки до технічних інтерв’ю.

---

### 1. Яка головна мета використання патерну Page Object Model (POM)?

**Відповідь:** Ізоляція логіки пошуку елементів сторінки від бізнес-логіки тестів, запобігання дублюванню коду (DRY) та спрощення підтримки тестів при змінах дизайну.

---

### 2. Де рекомендується ініціалізувати локатори у класі Page Object на TypeScript?

**Відповідь:** У конструкторі класу, зберігаючи їх у публічних або захищених `readonly Locator` полях.

---

### 3. Чому локатори у Page Object Playwright не застарівають (не викликають StaleElement)?

**Відповідь:** Тому що локатори є лінивими обгортками (lazy pointers) і шукають актуальні елементи в DOM лише в момент виклику методів дії.

---

### 4. Чому розміщення більшості бізнес-тверджень (expect) рекомендується в тестах, а не всередині Page Object?

**Відповідь:** Це зберігає класи сторінок гнучкими для повторного використання у різних контекстах і робить тестовий файл самодостатнім для розуміння критеріїв успіху.

---

### 5. Що таке Component Object Model і чим він відрізняється від класичного Page Object?

**Відповідь:** Це підвищення модульності через виділення повторюваних блоків інтерфейсу (хедер, футер, модальне вікно) в окремі класи компонентів, які вбудовуються у сторінки.

---

### 6. Як правильно передавати екземпляр `Page` у Page Object?

**Відповідь:** Через параметр конструктора: `constructor(public readonly page: Page)`.

---

### 7. Як реалізувати перехід на іншу сторінку після дії у методі Page Object?

**Відповідь:** Метод дії може повертати новий інстанс цільової сторінки (Fluent Interface) або залишати ініціалізацію наступної сторінки тесту чи фікстурам.

---

### 8. Що таке Fluent Interface (ланцюжковий виклик методів) у POM?

**Відповідь:** Патерн, де методи класу повертають `this` або новий екземпляр наступної сторінки, що дозволяє викликати дії ланцюжком: `await page.enterName().enterEmail().submit()`.

---

### 9. Як організувати структуру папок для проєкту з великою кількістю Page Objects?

**Відповідь:** Зазвичай використовується структура: `/pages` (повносторінкові об'єкти), `/components` (модульні віджети) та `/tests` (специфікації тестів).

---

### 10. Чи повинен Page Object відкривати браузер або керувати його запуском?

**Відповідь:** Ні, керування життєвим циклом браузера повністю делеговано тестовому ранеру Playwright та його фікстурам.

---

### 11. Як у Page Object обробляти динамічні елементи списку (наприклад, картки за назвою)?

**Відповідь:** Через параметризовані методи, що повертають локатор: `getProductCard(title: string): Locator { return this.page.getByRole('article', { name: title }); }`.

---

### 12. Як уникнути створення гігантських 'божественних об'єктів' (God Objects) у POM?

**Відповідь:** Декомпозувати складні сторінки на окремі логічні компоненти (вкладки, секції, фільтри, таблиці) через вкладені Component Objects.

---

### 13. Як у Page Object організувати роботу з формами, що мають багато необов'язкових полів?

**Відповідь:** Створити метод, який приймає об'єкт опцій (DTO або інтерфейс FormData) із необов'язковими полями, заповнюючи лише надані значення.

---

### 14. Чи можна використовувати спадкування (BasePage) для спільних методів?

**Відповідь:** Так, базовий клас `BasePage` може містити спільне поле `page`, базовий метод `goto(path)` та спільні компоненти (хедер, повідомлення сповіщень).

---

### 15. Як перевикористати перевірку завантаження сторінки у POM?

**Відповідь:** Створити метод `async waitForLoaded()`, який очікує відображення ключового опорного елемента сторінки (Hero section або H1).

---

### 16. Як Page Object допомагає при міграції з одного фреймворку на інший?

**Відповідь:** Зміни вносяться лише у внутрішню реалізацію методів та локаторів Page Object класів, тоді як бізнес-сценарії тестів залишаються практично незмінними.

---

### 17. Що робити, якщо дія на сторінці викликає відкриття модального вікна?

**Відповідь:** Метод дії повертає екземпляр класу цього модального вікна: `return new ConfirmationModal(this.page);`.

---

### 18. Як типізувати повернені значення методів Page Object у TypeScript?

**Відповідь:** Явно вказувати асинхронні повернені типи: `async login(...): Promise<void>` або `Promise<DashboardPage>`.

---

### 19. Як AI полегшує створення Page Objects з нуля?

**Відповідь:** AI може прийняти фрагмент HTML/DOM або скріншот сторінки та миттєво згенерувати типізований TypeScript клас із семантичними локаторами та методами дій.

---

### 20. Які типові антипатерни зустрічаються при реалізації POM?

**Відповідь:** Збереження статичних селекторів у вигляді рядків-констант, надмірна кількість асертів усередині методів дій, дублювання коду між сторінками та відсутність композиції.

---

## Завдання 1: Створення фікстури автоматичної авторизації через API з очищенням стану

**Мета:** Опанувати розширення `test.extend` для створення авторизованої сесії без проходження повільної форми входу через UI.

**Вхідний контекст та бізнес-сценарій:**
У додатку є 100 тестів особистого кабінету. Вхід через форму займає 3 секунди на кожен тест (разом 5 хвилин марного часу). Необхідно створити фікстуру `authenticatedUser`, яка авторизує користувача через швидкий API POST запит та встановлює cookie у контекст браузера.

**Покроковий алгоритм виконання:**
1. Створіть файл `fixtures/authFixture.ts` з розширенням `base.extend`.
2. Реалізуйте фікстуру `authenticatedUser`, яка робить POST запит до `/api/login` через фікстуру `request`.
3. Встановіть отриманий токен у cookies через `context.addCookies()`.
4. Напишіть тест особистого кабінету, який використовує готову сторінку без потреби у виклику форми логіну.

**Рекомендований системний AI-промпт:**
```text
Дій як Senior SDET. Напиши розширення Playwright з кастомною фікстурою авторизації на TypeScript:
1. Фікстура `authPage`:
   - Використовує фікстури `context` та `request`.
   - Виконує POST /api/auth/token з тестовими креденшелами.
   - Отримує токен 'jwt_secret_token_123'.
   - Додає cookie 'auth_token' до контексту браузера.
   - Відкриває нову сторінку `context.newPage()`.
   - Передає сторінку через `await use(page)`.
2. Напиши тест `profile.spec.ts`, який приймає `{ authPage }` та перевіряє, що користувач миттєво потрапляє на /profile без проходження /login.
```

**Очікуваний результат:**
Повноцінний типізований модуль фікстури та зразок тесту на TypeScript.

**Критерії самоперевірки та оцінювання:**
- [ ] Коректне використання test.extend з типами TypeScript
- [ ] Використання context.addCookies для безшовної авторизації
- [ ] Гарантоване закриття сторінки або очищення сесії після use
- [ ] Тест успішно верифікує профіль без зайвих кліків по формі входу

## Завдання 2: Створення авто-фікстури для аудиту консольних помилок браузера

**Мета:** Навчитись створювати фікстури з прапорцем `{ auto: true }` для автоматичного контролю відсутності Unhandled Exceptions.

**Вхідний контекст та бізнес-сценарій:**
Команда розробників вимагає, щоб жоден автотест не проходив успішно, якщо під час його виконання в консолі браузера з'явилася критична помилка JavaScript (наприклад, `TypeError: Cannot read properties of undefined`).

**Покроковий алгоритм виконання:**
1. Створіть авто-фікстуру `consoleErrorChecker` з `{ auto: true }`.
2. Підпишіться на подію `page.on('console')` та збирайте повідомлення типу 'error'.
3. Підпишіться на подію `page.on('pageerror')` для перехоплення неперехоплених помилок.
4. Після `await use()` перевірте, що масив помилок порожній, і викиньте інформативну помилку, якщо були збої.

**Рекомендований системний AI-промпт:**
```text
Дій як Lead QA Automation Engineer. Створи авто-фікстуру для перевірки чистоти консолі браузера на Playwright (TypeScript):
Вимоги:
1. Фікстура має запускатися автоматично для кожного тесту (`auto: true`).
2. Вона повинна перехоплювати всі консольні помилки рівня 'error' та глобальні pageerror.
3. Ігнорувати відомі некритичні попередження сторонніх скриптів (наприклад, фавіконки або рекламні трекери).
4. У блоці Teardown (після use) перевірити: якщо знайдено хоча б одну помилку, позначити тест як Failed з виведенням списку консольних помилок.
```

**Очікуваний результат:**
Модуль авто-фікстури Playwright з чистою логікою фільтрації помилок.

**Критерії самоперевірки та оцінювання:**
- [ ] Правильне використання { auto: true } у визначенні фікстури
- [ ] Коректний збір помилок через слухачі console та pageerror
- [ ] Фільтрація безпечних/сторонніх помилок
- [ ] Зрозумілий асерт у блоці Teardown після завершення тесту

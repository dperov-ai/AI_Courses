# Практичні завдання до Уроку 145: Очікування та синхронізація

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Реалізація надійної синхронізації при оформленні замовлення з фоновим API

**Мета:** Опанувати використання `Promise.all` з `waitForResponse` для усунення Flakiness при роботі з асинхронними кнопками.

**Вхідний контекст та бізнес-сценарій:**
При натисканні кнопки 'Підтвердити оплату' фронтенд відправляє POST запит на `/api/checkout`. Обробка триває від 1 до 4 секунд, після чого показується екран успіху. Раніше тест часто падав, оскільки намагався перевірити екран успіху до повернення відповіді бекенду.

**Покроковий алгоритм виконання:**
1. Ініціалізуйте тестовий сценарій на TypeScript.
2. Налаштуйте синхронне очікування API відповіді `/api/checkout` з кодом 200 одночасно з кліком по кнопці.
3. Витягніть номер транзакції з тіла JSON-відповіді.
4. Перевірте відображення екрана успіху та співпадіння отриманого номера транзакції в інтерфейсі.

**Рекомендований системний AI-промпт:**
```text
Дій як Senior SDET. Напиши тест на Playwright з надійною синхронізацією:
Сторінка: /checkout/payment
Дія: Клік по кнопці 'Сплатити замовлення'.
Вимоги:
1. Використай `Promise.all` для зв'язування кліку та `page.waitForResponse`.
2. Переконайся, що перехоплюється саме POST запит до ендпоінту `/api/v2/payments` зі статусом 200.
3. Отримай з відповіді JSON поле `orderNumber`.
4. Дочекайся появи фінального блоку замовлення та перевір, що на екрані відображається текст із цим номером.
```

**Очікуваний результат:**
Стабільний тестовий сценарій без жорстких затримок із повною синхронізацією мережевого рівня.

**Критерії самоперевірки та оцінювання:**
- [ ] Коректне використання Promise.all для запобігання race condition
- [ ] Фільтрація URL та статусу у waitForResponse
- [ ] Витяг даних із JSON payload відповіді
- [ ] Web-first assertion для перевірки фінального інтерфейсу

## Завдання 2: Синхронізація обробки завантаження звітів та спливаючих вікон

**Мета:** Навчитись синхронізувати тестовий потік із системними подіями завантаження файлів (Download event) та новими вкладками.

**Вхідний контекст та бізнес-сценарій:**
У модулі звітності клік по 'Завантажити річний звіт' ініціює генерацію важкого PDF-документа на сервері, після чого браузер отримує файл через подію Download. Необхідно дочекатися завантаження та перевірити ім'я збереженого файлу.

**Покроковий алгоритм виконання:**
1. Перейдіть на сторінку звітів `/reports`.
2. Зв'яжіть клік по кнопці з подією `page.waitForEvent('download')`.
3. Дочекайтеся завершення завантаження та перевірте назву файлу через регулярний вираз.
4. Збережіть файл у тимчасову директорію для подальшої валідації.

**Рекомендований системний AI-промпт:**
```text
Дій як Principal SDET. Напиши сценарій тестування завантаження файлу на Playwright:
Сторінка: /reports/annual
Кнопка: 'Згенерувати та завантажити звіт'
Вимоги:
1. Застосуй `page.waitForEvent('download')` у зв'язці з дією кліку.
2. Перевір, що ім'я файлу відповідає патерну `report_2026_*.pdf`.
3. Збережи завантажений файл за шляхом `test-results/downloads/temp_report.pdf`.
4. Переконайся у відсутності будь-яких штучних пауз `waitForTimeout`.
```

**Очікуваний результат:**
Готовий тестовий метод із правильною обробкою об'єкта Download у Playwright.

**Критерії самоперевірки та оцінювання:**
- [ ] Правильне використання waitForEvent('download')
- [ ] Перевірка назви файлу за допомогою регулярного виразу
- [ ] Збереження файлу за вказаним шляхом
- [ ] Повна відсутність жорстких затримок

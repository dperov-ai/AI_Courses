# Практичні завдання до Уроку 137: Expected vs Actual Result

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Формулювання високоточних Expected та Actual Result для фінансової операції

**Мета:** Навчитися описувати технічну розбіжність станів платіжного переказу з кодами помилок та станом БД.

**Вхідний контекст та бізнес-сценарій:**
При переказі коштів між рахунками гроші з одного рахунку списалися, але на інший не зарахувалися через помилку таймауту мікросервісу.

**Покроковий алгоритм виконання:**
1. Визначте бізнес-правило транзакційності (ACID: або обидва рахунки змінюються, або жоден).
2. Сформулюйте суворий Expected Result, включаючи відкат транзакції (Rollback) та сповіщення користувача.
3. Опишіть Actual Result з фіксацією порушення цілісності балансу, кодом HTTP 504 та відсутністю автоматичного повернення коштів.
4. Зіставте результати з вимогами безпеки банківських операцій.

**Рекомендований системний AI-промпт:**
```text
Склади бездоганні описи Expected Result та Actual Result для баг-репорту про зависання банківського переказу. Включи опис поведінки UI, статуси HTTP, записи транзакцій у БД та посилання на вимогу атомарності фінансових операцій.
```

**Очікуваний результат:**
Глибокий інженерний опис двох станів системи з повною термінологічною точністю.

**Критерії самоперевірки та оцінювання:**
- [ ] Чіткий опис обох частин банківської транзакції
- [ ] Фіксація статусів мережевого та сервісного шарів
- [ ] Повна відсутність розмитих формулювань

## Завдання 2: Аудит та виправлення слабких формулювань Expected/Actual у базі Jira

**Мета:** Провести рев'ю 3 неякісних баг-репортів та переписати їх на рівні вимог Senior QA.

**Вхідний контекст та бізнес-сценарій:**
У проектному беклозі накопичилися тікети від бізнес-користувачів із незрозумілими описами результатів.

**Покроковий алгоритм виконання:**
1. Проаналізуйте надані описи: 1. 'Форма не працює', 2. 'Картинка з'їхала', 3. 'Помилка доступу'.
2. Для кожного кейсу сформулюйте технічно грамотний Actual Result із зазначенням конкретних артефактів.
3. Напишіть відповідний Expected Result з прив'язкою до дизайн-системи чи документації.
4. Додайте критерії перевірки виправлення для етапу валідації.

**Рекомендований системний AI-промпт:**
```text
Ти — QA Lead. Перепиши три неякісні описи: 'кнопка зламалася', 'не пускає в кабінет', 'відео не вантажиться'. Перетвори кожен у строгу пару Expected Result та Actual Result з конкретними технічними деталями (коди помилок, поведінка компонентів, стан системи).
```

**Очікуваний результат:**
Три професійно переписані блоки дефектів із високим рівнем інженерної деталізації.

**Критерії самоперевірки та оцінювання:**
- [ ] Повне усунення суб'єктивних слів
- [ ] Додавання конкретних кодів та текстових повідомлень
- [ ] Відповідність стандартам індустрії

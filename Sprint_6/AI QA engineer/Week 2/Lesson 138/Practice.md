# Практичні завдання до Уроку 138: Попередній аналіз причин дефекту

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Локалізація та аналіз причин падіння замовлення за логами Kibana

**Мета:** На практиці розібрати реальний серверний стектрейс та визначити першопричину збою.

**Вхідний контекст та бізнес-сценарій:**
У логах бекенду зафіксовано сплеск помилок HTTP 500 під час спроби застосування купона на знижку.

**Покроковий алгоритм виконання:**
1. Проаналізуйте наданий стектрейс: `NullPointerException at OrderService.applyCoupon(OrderService.java:142)`.
2. Зіставте тіло вхідного POST-запиту: поле `couponCode` має значення `null` замість очікуваного рядка.
3. Перевірте, чому фронтенд надіслав null (неочищене поле вводу чи відсутність валідації).
4. Сформулюйте вичерпний висновок Root Cause Analysis для включення у баг-репорт.

**Рекомендований системний AI-промпт:**
```text
Ти — Senior QA Engineer. Проаналізуй наступний лог помилки: 'java.lang.NullPointerException: Cannot invoke String.toUpperCase() because couponCode is null at com.shop.service.DiscountService.calculate(DiscountService.java:88)'. Визнач першопричину дефекту, зону відповідальності (фронтенд чи бекенд) та запропонуй рекомендації щодо захисного кодування.
```

**Очікуваний результат:**
Детальний технічний висновок із зазначенням конкретного рядка коду, причин збою та заходів превентивного захисту (Null-safety).

**Критерії самоперевірки та оцінювання:**
- [ ] Точна ідентифікація місця падіння в коді
- [ ] Розподіл відповідальності між клієнтом та сервером
- [ ] Професійна аргументація без здогадок

## Завдання 2: Діагностика мережевого збою та витоку ресурсів у DevTools

**Мета:** Виявити причину зависання сторінки каталогу товарів через нескінченний цикл запитів.

**Вхідний контекст та бізнес-сценарій:**
При переході на сторінку каталогу вентилятори ноутбука починають шуміти, вкладка зависає, браузер споживає 100% CPU.

**Покроковий алгоритм виконання:**
1. Відкрийте вкладку Network і зафіксуйте аномалію: постійно відправляються сотні запитів `GET /api/products` щосекунди.
2. Визначте причину: нескінченний цикл у реактивному хуку `useEffect` через неправильно вказаний масив залежностей.
3. Зробіть профіль продуктивності (Performance Profile) та зафіксуйте тривалість операцій ре-рендерингу.
4. Складіть звіт про дефект із додаванням таймінгів та вказівкою на проблемний хук у фронтенді.

**Рекомендований системний AI-промпт:**
```text
Склади Root Cause Analysis для бага нескінченного циклу запитів на фронтенді. Поясни, як відсутність мемоізації або циклічна зміна стейту в useEffect призводить до DDoS власного сервера та блокування браузера користувача.
```

**Очікуваний результат:**
Повноцінний технічний аналіз інциденту з детальним описом механіки роботи React Reconciliation та мережевих метрик.

**Критерії самоперевірки та оцінювання:**
- [ ] Ідентифікація циклу рендерингу як першопричини
- [ ] Опис впливу на ресурси клієнта та сервера
- [ ] Конкретні рекомендації щодо виправлення хука

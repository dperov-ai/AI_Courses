# Практичні завдання до Уроку 140: Підготовка evidence та технічного контексту

Практичний блок розроблено для закріплення навичок роботи з AI-інструментами, аналізу реальних виробничих кейсів та створення професійних артефактів.

---

## Завдання 1: Збір та санітизація повного технічного пакету доказів (Evidence Package)

**Мета:** Опанувати експорт HAR-файлу, логів консолі та команди cURL із маскуванням конфіденційних даних.

**Вхідний контекст та бізнес-сценарій:**
На тестовому стенді при оформленні замовлення клієнта виник збій API (HTTP 500). Необхідно зібрати технічні докази для бекендера.

**Покроковий алгоритм виконання:**
1. Відкрийте будь-який веб-додаток у Chrome DevTools та увімкніть `Preserve log`.
2. Зробіть емуляцію мережевого запиту (через fetch або дію на сторінці).
3. Експортуйте HAR-файл та скопіюйте команду `Copy as cURL`.
4. Проведіть санітизацію: знайдіть у cURL заголовок `Authorization: Bearer ...` та замініть токен на `[REDACTED_TOKEN]`.
5. Оформіть блок Evidence для вставки у Jira.

**Рекомендований системний AI-промпт:**
```text
Ти — QA Automation / Performance Engineer. Створи стандартизовану інструкцію для тестувальників щодо експорту та маскування HAR-файлів і cURL-команд у Chrome DevTools. Поясни, які саме заголовки є небезпечними з точки зору безпеки (Cookies, Bearer tokens) та як їх безпечно знешкоджувати перед додаванням у відкриті тікети.
```

**Очікуваний результат:**
Покроковий інженерний гайд із прикладами очищених cURL-запитів та правилами санітизації PII.

**Критерії самоперевірки та оцінювання:**
- [ ] Повне розуміння роботи механізмів Preserve log та HAR
- [ ] Правильне маскування авторизаційних заголовків
- [ ] Готовність інструкції до використання в команді

## Завдання 2: Аналіз інтерактивного трейсу Playwright Trace Viewer

**Мета:** Дослідити упавший автотест за допомогою Playwright Trace та витягти докази для баг-репорту.

**Вхідний контекст та бізнес-сценарій:**
У CI/CD впав E2E автотест оформлення замовлення. У звіті згенеровано файл `trace.zip`.

**Покроковий алгоритм виконання:**
1. Відкрийте файл трейсу через `npx playwright show-trace trace.zip` (або trace.playwright.dev).
2. Знайдіть червоний крок, на якому впав тест (Action Timeout).
3. Перегляньте стан DOM-знімка у момент падіння (Snapshot Before/After).
4. Знайдіть відповідний запит у вкладці Network трейсу та витягніть код помилки API.
5. Складіть звіт про дефект на основі даних із трейсу Playwright.

**Рекомендований системний AI-промпт:**
```text
Опиши покроковий алгоритм розслідування падіння автотесту за допомогою Playwright Trace Viewer: як знайти упалий крок, переглянути стан DOM дерева, перевірити логи консолі та сформувати баг-репорт для розробника.
```

**Очікуваний результат:**
Детальний інженерний посібник із роботи з Playwright Trace Viewer із прикладом виявлення прихованого дефекту.

**Критерії самоперевірки та оцінювання:**
- [ ] Чіткий опис роботи з DOM снапшотами та таймлайном
- [ ] Використання вбудованих інструментів перевірки селекторів
- [ ] Формування готового баг-репорту з трейсу

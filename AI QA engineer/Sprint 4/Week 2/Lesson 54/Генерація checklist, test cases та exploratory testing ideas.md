# Генерація checklist, test cases та exploratory testing ideas: швидкісне створення артефактів тестування, чартери та евристики

У повсякденній роботі перед QA-інженером постійно постає дилема: написати деталізовані покрокові тест-кейси (на що йдуть дні) чи обмежитися швидким чек-листом (ризикуючи пропустити важливі деталі).

Штучний інтелект остаточно знімає це протиріччя. За лічені секунди AI здатний згенерувати як **високорівневий гнучкий чек-лист**, так і **формалізовані покрокові тест-кейси з передумовами та очікуваними результатами**, а також запропонувати **нестандартні ідеї для дослідницького тестування (Exploratory Testing Charters)**, про які людина навіть не подумала б.

У цьому поглибленому посібнику ми розглянемо:

* різницю між чек-листом (Checklist), тест-кейсом (Test Case) та чартером дослідження (Exploratory Charter);
* таксономію та структуру професійного тест-кейсу за міжнародним стандартом IEEE 829 / ISO 29119;
* техніки генерації тест-ідей за допомогою тестових евристик (SFDPO, CRUD, Goldilocks, RCRCRC);
* створення чартерів для Exploratory Testing за методологією Джеймса Баха (Session-Based Test Management);
* промптинг для масового експорту тест-кейсів у формати CSV/JSON для імпорту в TestRail, Zephyr та Jira;
* відсіювання низькоякісних та дублюючих тест-кейсів (Deduplication & Quality Filter).

## 2. Тестові евристики: як навчити AI генерувати нетривіальні ідеї

AI часто схильний генерувати банальні тести на кшталт «Введи логін і пароль». Щоб змусити модель мислити як елітний QA-хакер, використовуйте класичні **тестові евристики**:

```
+───────────────────────────────────────────────────────────────────────────+
|                       ТЕСТОВА ЕВРИСТИКА SFDPO (Sanity)                    |
+───────────────────────────────────────────────────────────────────────────+
| S - STRUCTURE:  З яких фізичних компонентів складається система (код, БД)?|
| F - FUNCTION:   Які функції та операції система повинна виконувати?       |
| D - DATA:       Які вхідні та вихідні типи даних циркулюють у системі?   |
| P - PLATFORM:   Які операційні системи, браузери, роздільності екранів?   |
| O - OPERATIONS: Як реальні користувачі по-різному використовують фічу?    |
+───────────────────────────────────────────────────────────────────────────+
```

```
+───────────────────────────────────────────────────────────────────────────+
|                    ЕВРИСТИКА CRUD (Create, Read, Update, Delete)          |
+───────────────────────────────────────────────────────────────────────────+
| Перевірте для кожного об'єкта:                                            |
| - Створення дубліката, створення з порожніми полями.                      |
| - Читання видаленого об'єкта, читання чужого об'єкта (IDOR).              |
| - Одночасне оновлення з двох вкладок (Race Condition).                    |
| - Видалення під час активного процесу редагування.                        |
+───────────────────────────────────────────────────────────────────────────+
```

## 3. Генерація чартерів для Exploratory Testing

Чартер дослідницького тестування задає вектор 45–90 хвилинної сесії без жорстких покрокових інструкцій:

```markdown
# ПРИКЛАД ЗГЕНЕРОВАНОГО AI ЧАРТЕРУ (EXPLORATORY CHARTER):
- ЦІЛЬ: Дослідити поведінку кошика покупок під час нестабільного інтернет-з'єднання.
- ЗОНА УВАГИ: Модуль Checkout, промокоди, списання бонусних балів.
- СЦЕНАРІЙ АТАКИ: 
  1. Додати товар -> Перевести мережу в Offline -> Спробувати оформити.
  2. Застосувати промокод двічі під час штучної затримки мережі (Slow 3G).
  3. Оформити замовлення, коли залишок товару на складі дорівнює 1 одиниці, одночасно з двох браузерів.
- РИЗИК: Подвійне нарахування знижки, зависання інтерфейсу, від'ємний баланс на складі.
```

## 4. Промпт для експорту тест-кейсів у TestRail (CSV-формат)

```markdown
Ти — QA Automation Lead.
На основі наданого опису API згенеруй таблицю тест-кейсів, готову для прямого імпорту в TestRail у форматі CSV.

ОБОВ'ЯЗКОВІ КОЛОНКИ:
"Section", "Title", "Preconditions", "Steps", "Expected Result", "Priority", "Type"

ПРАВИЛА:
1. Кроки пиши нумерованим списком всередині комірки: "1. Зробити POST... \n 2. Перевірити...".
2. Згенеруй мінімум 8 кейсів: 2 Smoke, 4 Negative, 2 Boundary.
3. Пріоритети: High, Medium, Low.
```

## Резюме уроку

1. AI скорочує час написання тестової документації **з днів до лічених хвилин**.
2. Використовуйте **чек-листи** для швидкої регресії, **тест-кейси** для формальної фіксації, а **чартери** для глибокого дослідження.
3. Підключайте **тестові евристики (SFDPO, CRUD, Goldilocks)** у промпти для пошуку прихованих та нестандартних дефектів.
4. Автоматизуйте експорт тестів у формати **CSV/JSON** для безшовного імпорту в TestRail та Jira.

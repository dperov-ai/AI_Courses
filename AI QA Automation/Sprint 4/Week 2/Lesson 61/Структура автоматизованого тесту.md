# Структура автоматизованого тесту: патерни AAA (Arrange-Act-Assert) та Given-When-Then, Page Object Model, фікстури та асерти

Написання коду автотестів підпорядковується ще суворішим правилам інженерної гігієни, ніж написання звичайного продуктового коду.

Якщо продуктовий код написаний погано — страждає одна конкретна функція. Якщо погано написані автотести — вся команда розробки втрачає довіру до тестів, починає ігнорувати їхні падіння, вимикає перевірки в CI/CD і випускає критичні дефекти на продакшн.

**Структурований, атомарний, незалежний та читабельний автотест** — це еталон надійності. Він повинен легко читатися як технічна документація, перевіряти рівно одну річ і чітко повідомляти причину збою.

У цьому поглибленому фінальному посібнику блоку автоматизації ми розглянемо:

* канонічну структуру автотесту: патерн **AAA (Arrange, Act, Assert)** та його BDD-аналог **Given-When-Then**;
* анатомію перевірок (Assertions): Soft Asserts vs Hard Asserts, читабельні матчери (Fluent Assertions);
* архітектурний патерн **Page Object Model (POM)** та Page Factory для UI-автоматизації;
* керування станом та ізоляцією: Тестові фікстури (Fixtures: Setup & Teardown), генерація унікальних даних;
* принципи надійного автотесту: Атомарність, Ізольованість (відсутність залежностей між тестами), Детермінізм;
* патерни очікування: чому `sleep(5)` — це зло, та як використовувати явні очікування (Explicit / Auto-waits у Playwright).

## 1. Канонічний патерн AAA (Arrange - Act - Assert)

Будь-який якісний автотест складається з трьох чітко розділених фаз:

```
+───────────────────────────────────────────────────────────────────────────+
|                        ПАТЕРН AAA (ARRANGE - ACT - ASSERT)                |
+───────────────────────────────────────────────────────────────────────────+
| 1. ARRANGE (Підготовка / Given):                                          |
|    - Створення тестових об'єктів, ініціалізація даних, налаштування моків,|
|      авторизація користувача, перехід на потрібну сторінку.               |
|                                                                           |
| 2. ACT (Дія / When):                                                      |
|    - Виконання цільової дії, яка тестується (виклик методу `calculate()`, |
|      клік на кнопку "Купити", відправка HTTP-запиту).                     |
|    - Фаза Act має бути максимально короткою (в ідеалі 1-2 рядки коду!).   |
|                                                                           |
| 3. ASSERT (Перевірка / Then):                                             |
|    - Звірка фактичного результату з очікуваним еталоном.                  |
|    - Перевірка статус-коду, перевірка тексту на екрані, перевірка запису в БД|
+───────────────────────────────────────────────────────────────────────────+
```

### Приклад чистого тесту на Python (PyTest):
```python
def test_apply_promo_code_calculates_correct_discount():
    # 1. ARRANGE (Підготовка)
    cart = ShoppingCart(user_id=42)
    cart.add_item(Product(name="Ноутбук", price=1000.0))
    promo = PromoCode(code="SALE20", discount_percent=20)

    # 2. ACT (Дія)
    final_price = cart.apply_discount(promo)

    # 3. ASSERT (Перевірка)
    assert final_price == 800.0, f"Очікували ціну 800.0, але отримали {final_price}"
    assert cart.discount_applied == True
```

## 2. Архітектурний патерн Page Object Model (POM)

Головний ворог UI-автотестів — зміна селекторів розробниками. Якщо селектор кнопки `login-btn` прописаний у 50 різних тестах, зміна кнопки змусить вас переписувати 50 файлів.

**Page Object Model** виносить локатори та методи взаємодії зі сторінкою в окремі класи:

```
  [ Тест test_login_success ] ──► [ Page Object: LoginPage ] ──► [ Браузер (DOM) ]
  (Містить тільки бізнес-кроки)   (Містить селектори #btn,       (Виконує фізичні кліки)
                                  та методи login(u, p))
```

### Приклад POM на Playwright / TypeScript:
```typescript
// pages/LoginPage.ts
export class LoginPage {
  constructor(private page: Page) {}

  private usernameInput = this.page.locator('#username');
  private passwordInput = this.page.locator('#password');
  private submitButton  = this.page.locator('button[type="submit"]');

  async login(user: string, pass: string) {
    await this.usernameInput.fill(user);
    await this.passwordInput.fill(pass);
    await this.submitButton.click();
  }
}

// tests/login.spec.ts
test('Успішний вхід користувача', async ({ page }) => {
  const loginPage = new LoginPage(page);
  await page.goto('/login');
  
  await loginPage.login('alex', 'secret123'); // Читається як людська мова!
  
  await expect(page).toHaveURL('/dashboard');
});
```

## 3. Золоті правила надійності автотестів

```
+───────────────────────────────────────────────────────────────────────────+
|                     4 ЗАКОНИ НАДІЙНОСТІ АВТОТЕСТІВ                        |
+───────────────────────────────────────────────────────────────────────────+
| 1. АТОМАРНІСТЬ: Один тест перевіряє рівно одну бізнес-фічу.               |
|                                                                           |
| 2. ІЗОЛЬОВАНІСТЬ (Independent): Тести повинні запускатися у будь-якому    |
|    порядку та паралельно. Тест B не повинен залежати від результату Тесту A.|
|                                                                           |
| 3. ДЕТЕРМІНІЗМ: За однакових умов тест повинен давати 100% однаковий      |
|    результат (Green або Red), виключаючи Flakiness.                       |
|                                                                           |
| 4. ЖОДНИХ `sleep()`: Використовуйте динамічні Web-First Assertions       |
|    (`expect(locator).toBeVisible()`), які чекають появи елемента автоматично.|
+───────────────────────────────────────────────────────────────────────────+
```

## Резюме уроку

1. Структура автотесту базується на канонічному патерні **Arrange-Act-Assert (AAA)**.
2. Для UI-автоматизації обов'язковим стандартом є патерн **Page Object Model (POM)**.
3. Кожен тест повинен бути **атомарним, незалежним, детермінованим та ізольованим**.
4. Заборонено використовувати статичні паузи `sleep()`; застосовуйте **Auto-waiting та явні очікування Playwright/Selenium**.

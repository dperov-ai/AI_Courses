# Визначення сценаріїв, доцільних для автоматизації: скорингові моделі, матриця пріоритизації та відбір кандидатів за допомогою AI

Головна помилка початківця-автоматизатора — хапатися за написання коду для першого-ліпшого тест-кейсу, який потрапив на очі.

У результаті часто автоматизують фічу, яка зміниться наступного тижня (наприклад, тимчасовий дизайн новорічної акції) або рідкісний крайовий випадок, який трапляється раз на рік у 0.01% користувачів. На це витрачаються тижні роботи, а критичні шляхи користувача (авторизація, додавання в кошик, оплата) залишаються без автоматичного захисту і падають на продакшні.

**Пріоритизація та відбір кандидатів на автоматизацію** — це стратегічна інженерна навичка, яка гарантує, що кожна година роботи над автотестами приносить максимальний бізнес-ефект і запобігає реальним збиткам.

У цьому поглибленому посібнику ми розглянемо:

* критерії відбору сценаріїв для автоматизації: частота виконання, бізнес-критичність, стабільність фічі та складність реалізації;
* скорингову модель оцінки кандидатів (Automation Feasibility & ROI Scoring);
* матрицю пріоритетів: «Автоматизувати негайно» vs «Категорично заборонено автоматизувати»;
* аналіз стабільності вимог (Feature Volatility / Churn Rate);
* використання AI для аудиту набору ручних тест-кейсів та автоматичного формування черги на автоматизацію;
* складання офіційного Automation Backlog.

## 1. Чотири золоті критерії відбору для автоматизації

```

|    - Сценарій запускається щодня або при кожному коміті в CI/CD           |

|      тестування 20 комбінацій знижок і промокодів (Data-Driven Testing).  |

## 2. Скорингова модель оцінки доцільності (Score Formula)

Для кожного ручного тесту розраховується бал автоматизації (**Automation Index / AIX**):

$$\text{AIX} = (\text{Критичність [1-5]} \times 3) + (\text{Частота [1-5]} \times 2) + (\text{Стабільність [1-5]} \times 2) - (\text{Складність [1-5]})$$

```
  ┌─────────────────────────────────────────────────────────────┐
  │ ОЦІНКА РЕЗУЛЬТАТУ СКОРИНГУ:                                 │
  │ • Більше 25 балів ──► ПРІОРИТЕТ 1: Автоматизувати в першу   │
  │                       чергу (Tier-1 Smoke/Core).            │
  │ • Від 15 до 25    ──► ПРІОРИТЕТ 2: Автоматизувати на рівні  │
  │                       API або інтеграційних тестів.         │
  │ • Менше 15 балів  ──► ЗАЛИШИТИ В РУЧНОМУ ТЕСТУВАННІ:        │
  │                       Автоматизація економічно невигідна!   │
  └─────────────────────────────────────────────────────────────┘
```

| - Smoke-тести критичного шляху.    | - Одноразові маркетингові промо-акції|
| - Регресійний набір платіжного шлюзу| - Фічі на етапі A/B тестування або   |

|   ками полів (Data-Driven Testing).|   перевищує рік ручних прогонів.     |
| - Багатомовні перевірки локалізації| - Специфічні UX-тести оцінки зручності|

```

## 4. Промпт для AI-аудиту тестового беклогу

```markdown
Ти — Lead Test Automation Architect.
Проаналізуй наданий список із 10 ручних тест-кейсів для інтернет-магазину.

Для кожного тест-кейсу:
1. Оціни за шкалою 1-5: Бізнес-критичність, Частоту запуску, Стабільність інтерфейсу, Складність коду.
2. Розрахуй скоринговий бал Automation Index.
3. Сформуй фінальний пріоритизований беклог автоматизації:
   - Tier 1: Термінова автоматизація в поточному спринті (API + E2E).
   - Tier 2: Автоматизація другого пріоритету (API-рівень).
   - Tier 3: Залишити в ручному тестуванні (з обґрунтуванням, чому автотест не потрібен).

ВХІДНІ ТЕСТ-КЕЙСИ:
"""
[Вставте опис тест-кейсів]
"""
```

## Резюме уроку

1. Автоматизувати все — це найкоротший шлях до провалу проекту; **пріоритизація визначає успіх**.
2. В першу чергу автоматизуються **часто повторювані, бізнес-критичні та стабільні сценарії**.
3. Використовуйте **скорингові математичні моделі (Automation Index)** для усунення суб'єктивності при виборі кандидатів.
4. AI допомагає швидко провести аудит сотень ручних тест-кейсів та згенерувати раціональний **Automation Backlog**.
